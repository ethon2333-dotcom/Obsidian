# 企业知识库连接器生态 学习笔记

> [!abstract] 心智模型（引文）
> 「连接器是 RAG 的『第一公里』——数据进不来、进错权限、进丢格式，后面的检索与生成再强，也是沙上之塔。」本笔记刻意区别于 [[知识库问答与 Enterprise Search 学习笔记]]：那篇讲「数据进来后怎么检索（权限感知检索层）」，**本篇只讲「数据怎么进来」（接入层 / connectors）**。一句话分工：**接入交给连接器，检索交给企业搜索。**

## 0. 为什么需要"连接器"这一层

RAG / Agent 的原材料散落在几十个相互隔离的系统里。连接器要解决的四个核心问题：

| 难题 | 含义 | 不解决会怎样 |
|---|---|---|
| **权限映射** | 把源系统 ACL 翻译成检索/生成层的过滤谓词 | 越权泄露（Copilot 误读 SharePoint 误配权限即典型事故面） |
| **增量同步** | 只抓变化部分，定时/实时刷新索引 | 索引陈旧、或全量重爬成本爆炸 |
| **格式解析** | PDF/Office/HTML/图片/表格 → 结构化、保留版式 | 表格/版式丢失，RAG 召回质量崩塌 |
| **元数据保留** | 来源/作者/时间/层级路径随内容一起入库 | 检索不可溯源、无法按时间/来源过滤 |

## 2. 连接器生态格局（点到为止）

- **两条路线并存**：①「索引式」（Copilot Graph Connectors、Glean、Coveo、Airbyte）——把数据拉进统一索引，适合"广域企业搜索"；②「实时式」（MCP server）——按需实时取数，适合"状态每分钟变"的工单/CRM。两者互补而非替代（微软路线图同时投资两者）。
- **MCP 是 2025-2026 最大变量**：从 Anthropic 内部项目 → 18 个月内成行业标准的"通信骨干"，让 agent 用同一协议连系统（MCP）与连 agent（A2A）。预建 server 已覆盖 GitHub/Slack/Drive/Notion/Jira/Confluence/Salesforce/PostgreSQL。
- **连接器供应商分化**：开源社区驱动（Airbyte 25k+ 社区、LlamaHub）vs 厂商托管（Glean/Coveo/Copilot 闭源连接器目录）；iPaaS（Workato/Boomi/MuleSoft/CData）也把既有连接器"暴露为 MCP 工具"，填补遗留 ERP 长尾。
- **权限映射是分水岭**：Glean/Coveo 用"索引时 early-binding 把 ACL 随文档入库"，Copilot 继承源系统权限并在 Graph 内强制过滤；这层决定了连接器能否用于 regulated 行业。

- [ ] **索引式 vs 实时式（MCP）如何选型？** 什么数据该全量索引、什么该按需实时拉取？临界规模（如 Confluence 1M+ 页用 federated search 而非全量索引）的工程判据是什么？
- [ ] **权限映射的三种落地（early-binding / late-binding / 实时 MCP 取数）各自的失效一致性成本？** ACL 变更后索引多久才同步？微软路线图提到 ServiceNow/Jira 层级 ACL（2026-04）与增量权限同步（2026-06），具体机制未细查。
- [ ] **连接器增量同步的"变化检测"怎么做？** 轮询 vs webhook vs CDC（Airbyte 支持 CDC）——不同源的增量能力差异与成本？
- [ ] **格式解析的质量如何评测？** 复杂表格/扫描件/手写，unstructured、LlamaParse、Reducto、Docling 之间有无独立 benchmark？CSDN 引 ParseBench 84.9% 为二手，待一手。
- [ ] **元数据保留的标准 schema 是什么？** LlamaIndex 的 `relationships`、unstructured 的 typed elements + `text_as_html`、各厂商不一，跨连接器流转时元数据如何对齐？
- [ ] **MCP 治理缺口**：公开 MCP server 多无 OAuth、带漏洞（Superkind 指出），企业上生产前的 scoped access / 写操作人工审批 / 全量审计如何落地？
- [ ] **连接器与 [[向量数据库 学习笔记]] 的边界**：连接器负责"拉+解析+带上元数据"，向量库负责"存+近邻检索"——两者如何分工、元数据如何无损传递到向量索引层（呼应 [[RAG 详细学习笔记]] 9.5 安全节）？
