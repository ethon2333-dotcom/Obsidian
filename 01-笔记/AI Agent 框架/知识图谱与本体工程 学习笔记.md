**知识图谱 = 把"世界由哪些实体、它们如何关联"显式建模成可查询、可推理、可解释的结构；本体（Ontology）是这张图的"建模契约"——定义允许哪些类、属性与关系，而大模型正把"造图"从手工工程变成半自动流水线。**

> 🌱 广度种子笔记：聚焦**知识图谱的构建侧**（本体建模 → 抽取 → 融合 → 存储/查询），即"如何造出 KG"，区别于 [[GraphRAG 与知识图谱增强 Agent 学习笔记]]（应用侧：用 KG 增强 RAG）、[[向量数据库 学习笔记]]（向量检索而非结构化图谱）。与 [[Graph Engineering 图谱工程]] 方法论互补、与 [[Agent 记忆系统 学习笔记]]（KG 可作持久结构化记忆）咬合。

## 1. 核心概念辨析（定义）

| 概念 | 一句话 | 形式 / 标准 | 关注点 |
|---|---|---|---|
| **知识图谱 KG** | 实体—关系—实体组成的语义网络 | 三元组 `(s, p, o)` 集合；可叠加本体与推理 | 表示"已知事实"并支持多跳查询与推理 |
| **本体 Ontology** | 对领域概念、属性及其约束的**形式化规范** | OWL / RDFS / SKOS；常用 Protégé 编辑 | 规定"允许什么样的知识"，保证一致性与互操作 |
| **RDF** | 资源描述框架，KG 的**底层数据模型** | W3C 标准，三元组 + URI | 数据交换与链接（Linked Data）的通用语法 |
| **OWL** | 网络本体语言，在 RDF 之上加**推理语义** | W3C 标准，描述逻辑 DL | 可推导新事实、做一致性检查（需推理机） |
| **属性图 Property Graph** | 节点/边可带任意属性的图模型 | 非 W3C 标准；Neo4j 等采用 | 工程友好、遍历性能高，原生不强制推理 |

> 简记：RDF 是"数据的语法"，OWL 是"带推理的语义"，本体是"用 OWL/RDFS 写出的建模规范"，KG 是"装满了三元组、并可能套着本体的图"。属性图与 RDF/OWL 是两条技术路线（后者重语义标准，前者重工程性能）。

## 2. 构建流程（怎么造出一张 KG）

| 阶段 | 做什么 | 关键产物 / 工具 |
|---|---|---|
| ① 本体设计 | 界定范围（Competency Questions）、定义类层级、属性、约束 | Protégé、NeOn 方法论、ODP（本体设计模式） |
| ② 实体/关系抽取 | 从文本/表格抽出实体、类型、三元组 | LLM prompt、NER+RE、ChatIE/KGGEN（生成式抽取） |
| ③ 对齐/融合 | 实体消歧、同义关系归一、跨源合并 | 向量相似度 + LLM 消歧；owl:sameAs |
| ④ 存储/查询 | 落库并提供查询与推理 | SPARQL（RDF 系）/ Cypher（属性图系） |

LLM 时代的两种范式（Bian et al. 2025 综述）：
- **Schema-based**：先定本体，让 LLM 往里填。一致性高，医疗/金融等受监管域必需。
- **Schema-free / 数据驱动**：LLM 自主发现实体与关系、事后归纳 schema（如 EDC 框架：Extract–Define–Canonicalize）。灵活但需归一化治理。
- 实践常用**混合**：先定 4–8 个顶层实体类型，子类型与关系由 LLM 自由发现。

## 3. 主流方案与工具

| 工具 | 类型 | 查询语言 | 是否支持推理 | 典型场景 |
|---|---|---|---|---|
| **Neo4j** | 属性图数据库 | Cypher（兼容 GQL） | 原生不支持，靠插件/图算法 | 高吞吐遍历、推荐、社交网络、GraphRAG 底座 |
| **Apache Jena** | RDF 框架 / TDB 三元组库 | SPARQL（Fuseki 服务） | 支持（规则引擎，查询时推理） | 深度定制语义应用、学术研究 |
| **Protégé** | 本体编辑器（离线设计） | 经推理机导出/校验 | 是（HermiT/Pellet 插件） | 领域本体建模、一致性检查 |
| **RDFox** | 内存式 RDF 存储 | SPARQL + Datalog 规则 | 是（并行 Datalog 物化推理） | 低延迟、规则密集型推理 |
| **Stardog** | 企业级语义图平台 | SPARQL | 是（OWL 推理、查询时求值） | 企业知识集成、数据虚拟化、合规 |
| **GraphDB** | 语义图数据库 | SPARQL | 是（TRREE 前向物化推理） | 出版/开放数据、SHACL 校验 |
| **Amazon Neptune** | 全托管双模型图库 | Gremlin / SPARQL | 视模型 | 云上高可用、AWS 生态集成 |

> **图库 vs 向量库（要点到为止）**：向量库擅长"语义相似、开放召回"，图库擅长"多跳、精确、可解释、可溯源"。现代 RAG 多走**混合**——向量初召回 + 图约束/遍历精排（如 HybridRAG 在金融 QA 上优于单用其一）。Neo4j/TigerGraph 已原生内嵌向量索引，支持"向量相似 → 图遍历"统一查询。详见 [[向量数据库 学习笔记]]。

## 4. 2025-2026 进展

- **LLM 辅助本体自动构建**：从 CQ（Competency Questions）直接生成 OWL（CQbyCQ、Ontogenia 元认知提示、NeOn-GPT）已接近"初级人类建模者"质量；半自动化流水线让专家只在关键 checkpoint 介入。
- **自动实体/关系抽取**：NER→RE 模块化管线被统一生成式框架取代（ChatIE 多轮对话、KGGEN 两调用渐进抽取）；few-shot（5–7 例）稳定优于 zero-shot。
- **KG 作为 GraphRAG 上游知识源**：微软 GraphRAG、LightRAG 等均依赖"先建图再检索"；本文上游即其"造图"环节（应用侧见 [[GraphRAG 与知识图谱增强 Agent 学习笔记]]）。
- **企业知识图谱**：Neo4j 2026 将"本体作为一等公民"（Ontologies as 1st-class citizen，带 schema 强制与样本库）；Aura Agent（2026-02 GA）可从图 schema 自动生成 grounded agent 并一键部署 MCP Server。⚠️ 厂商口径，待核实。
- **动态/自演化 KG**：AutoSchemaKG、EvoKG（MIT，arXiv 2509.15464）支持从文档增量更新、按时间戳/可信度解决冲突；"构建"与"使用"边界在消失。
- **可验证推理**：GCR（ICML 2025）把 KG 结构作为解码约束（KG-Trie），在 WebQSP/CWQ 实现 100% 忠实推理路径——前提是 KG 完备。

## 6. 深度盲区（待解问题）
