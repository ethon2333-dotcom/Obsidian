# 推理引擎的量化与稀疏化集成 学习笔记

> 一句话心智模型：推理引擎的量化与稀疏化 = 在云端 serving 侧把权重 / KV cache 压成低精度、把矩阵变稀疏（跳过零值计算），用"一点精度 / 少量信息"换"吞吐与显存 / 成本"，且必须与 continuous batching / 投机解码 / PagedAttention 等系统优化协同才见效。

## 广度覆盖（BREADTH > DEPTH，点到为止）

### 定义与范畴

服务端 / 云端推理引擎的量化与稀疏化，指 vLLM、SGLang、TensorRT-LLM、TGI、LMDeploy 等引擎在**数据中心 GPU** 上，把模型权重、激活、KV cache 转成低比特精度（FP8 / INT8 / INT4 / NVFP4），以及把权重矩阵做成结构化稀疏（2:4），从而在**不重训**前提下压显存、提吞吐、降单位 token 成本。它与 [[端侧模型量化 学习笔记]] 的关键区别在于约束不同：端侧量化是"4GB 内存 / 3W 功耗预算下能不能跑动"的**前提项**（离线优先、敢压到 INT4/1.58-bit）；serving 侧量化是"同一张卡塞更大模型、喂更多并发"的**优化项**，受显存容量 / 带宽与单卡峰值吞吐约束，且可随时换更大机器——所以更敢用 FP8 这种"几乎无损又省一半"的方案，也更能接受 KV cache 量化这种近无损工程收益。

### 分类 / 主流方案（表格）

| 技术 | 说明 | 代表引擎支持 | 备注 |
| --- | --- | --- | --- |
| **W4A16 / W8A16**（权重-only 量化） | 只压权重到 INT4/INT8，激活保 FP16 | vLLM(AWQ/GPTQ+Marlin)、SGLang、TensorRT-LLM、TGI、LMDeploy 均支持 | "内存换模型规模"主力；AWQ/GPTQ 是生产 INT4 默认算法 |
| **FP8 W8A8**（权+激 FP8 E4M3） | 权重与激活都转 FP8，Hopper/Ada 原生 Tensor Core 加速 | vLLM(`--quantization fp8`)、SGLang、TensorRT-LLM(fp8/block-scaling)、LMDeploy | **2025 生产默认**；无需校准数据、低摩擦 |
| **W8A8 INT8（SmoothQuant）** | 把激活离群值迁移到权重后再 INT8 量化 | vLLM(`int8_w8a8`)、TensorRT-LLM(SmoothQuant)、LMDeploy | "精度几乎无损"安全区，云端主流 |
| **NVFP4 / MXFP4（W4A4 浮点块量化）** | Blackwell(B200) 专属 FP4 Tensor Core，2× 于 FP8 压缩 | TensorRT-LLM(`nvfp4`)、SGLang(`modelopt_fp4`) | 仅 Blackwell 硬件；需块级 scale |
| **KV Cache 量化（INT8/FP8/FP4/3-bit）** | 把缓存的 K/V 压低精度，运行时动态量化 | vLLM(`kv_cache_dtype=fp8`)、SGLang(`--kv-cache-dtype fp8_e4m3`，2026 加 FP4)、TensorRT-LLM(`int8/fp8_kv_cache`)、LMDeploy(per-head per-token 非对称) | 长上下文 / 高并发的显存天花板解法 |
| **2:4 结构化稀疏（N:M 半结构化）** | 每 4 个权重建 2 个零，Ampere+ Sparse Tensor Core 原生加速 | vLLM(CUTLASS sparse GEMM，llm-compressor 产出)、SGLang 导入同内核 | 理论 2× MatMul 加速，实测端到端 ~1.2–1.3×（待核实） |
| **稀疏注意力（context sparsity）** | prefill 阶段对注意力矩阵稀疏化，降 O(n²) | 多为模型架构层（sliding-window / 局部注意力），引擎集成度低 | 与"权重稀疏"正交，常和长上下文策略一起出现 |

### 2025-2026 进展

- **FP8 成为 serving 生产默认精度**：vLLM / SGLang / TensorRT-LLM / LMDeploy 均原生支持 FP8 权重 + FP8 KV cache（Hopper/Ada 硬件加速），无需校准、低摩擦（softcorefuture 2025 综述）。
- **Blackwell 世代 NVFP4（W4A4 浮点块量化）落地**：TensorRT-LLM `nvfp4`、SGLang `modelopt_fp4`，较 FP8 再压缩 2×、精度近无损；但仅 B200 等 Blackwell 卡。NVIDIA Model Optimizer 称 NVFP4 在 Qwen-23B / DeepSeek-R1-0528 / Llama Nemotron 上达 2–3× 生成吞吐——**厂商口径，待核实**。
- **KV Cache 量化从"可选"变"一等优化"**：FP8 KV cache 主流；SGLang 2025–2026 加入 FP4(E2M1) KV cache（issue #10083，2026-02 合并）；研究侧 TurboQuant（Google, ICLR 2026）3-bit 达 6× 显存压缩、8× attention 提速——**论文/媒体口径，待核实**。
- **引擎原生量化格式收敛**：`compressed-tensors`（llm-compressor，Red Hat 与 vLLM 联合）成为"自动识别、免 flag"的推荐路径，W4A16/W8A8/FP8 一个工具搞定；NVIDIA Model Optimizer 统一 PTQ 出口，量化结果可直喂 vLLM/SGLang/TensorRT-LLM/Dynamo。
- **MoE 量化成焦点**：DeepSeek-V3/R1 等 MoE 用 **FP8 block-wise** 量化专家权重（cc≥8.9），避开 per-tensor 维度不匹配 bug；NVFP4 同时量化专家 GEMM 与 token 分发、通信量减半（lmsys 2025-09 GB200 实测 FP8 attention + NVFP4 MoE 较 H100 3.8×/4.8× prefill/decode——**厂商博客口径，待核实**）。
- **量化与系统优化协同成标配**：量化不再是孤立模块，与 continuous batching、PagedAttention、前缀缓存、投机解码一起"乘法叠加"才出效果。

### 代表引擎量化支持对比（表格）

| 引擎 | 支持的量化 | KV cache 量化 | 稀疏化 | 备注 |
| --- | --- | --- | --- | --- |
| **vLLM** | AWQ/GPTQ(W4A16)、FP8 W8A8、INT8 W8A8、bitsandbytes、GGUF、compressed-tensors、TorchAO、NVFP4(经 Model Optimizer) | FP8 KV cache(`kv_cache_dtype=fp8`) | 2:4 结构化稀疏(CUTLASS sparse GEMM) | 生产事实标准；Marlin kernel 跑 W4A16 较原生 AWQ 大幅提速（待核实倍数） |
| **SGLang** | AWQ/GPTQ、FP8 W8A8、modelopt_fp4(NVFP4 MoE)、TorchAO INT4 | FP8(e4m3/e5m2)；2026 加 FP4 KV | 2:4 稀疏(导入 CUTLASS) | 结构化/Agent/RAG 强；Blackwell 上 FP8 attention + NVFP4 |
| **TensorRT-LLM** | FP8(per-tensor/block/rowwise)、NVFP4、W4A8/W4A16 AWQ/GPTQ、SmoothQuant W8A8、INT4/INT8 wonly | INT8 / FP8 KV cache | 依赖权重稀疏 + CUTLASS（稀疏非主打） | NVIDIA 原生；AOT 编译；DeepSeek block-scaling FP8 GEMM |
| **TGI** | 主流 PTQ(AWQ/GPTQ/FP8/bitsandbytes) | 支持（文档口径） | 有限 | 2025-12 进入 maintenance mode，新项目转 vLLM/SGLang |
| **LMDeploy** | AWQ/INT4、W8A8、KV 量化(per-head per-token 非对称) | INT4/INT8 KV(`quant_policy`) | — | TurboMind C++；中文社区强，低延迟量化 |
| **llama.cpp / Ollama** | GGUF Q2–Q8、INT4 | 有限(GGUF 侧) | 有限 | 端/边取向，非高并发 serving（见 [[端侧大模型推理 学习笔记]]） |
