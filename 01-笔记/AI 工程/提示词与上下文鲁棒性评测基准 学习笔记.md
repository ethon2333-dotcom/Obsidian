# 提示词与上下文鲁棒性评测基准 学习笔记

> 心智模型：在「提示词工程 → 上下文工程」成为范式之后，我们需要一套基准，来回答——**换种说法 / 加干扰 / 换上下文，模型表现到底崩不崩**。

本篇聚焦「鲁棒性评测基准与工具」本身，与 [[提示词工程到上下文工程演进与 Prompt Ops 学习笔记]]（演进史+提示词管理工具链）和 [[Context Engineering 学习笔记]]（概念层）互补：那两篇讲"怎么写提示词/上下文"，本篇讲"怎么系统性测提示词/上下文变体下模型还稳不稳"。区别于 [[ANN 索引算法专题 学习笔记]]（检索结构，非评测）。

## 一、问题分类（扰动 taxonomy）

| 扰动类型 | 含义 | 代表攻击/方法 |
| --- | --- | --- |
| 字符级扰动 | 错字/同形替换/大小写/标点 | DeepWordBug、TextBugger |
| 语义改写 | 同义复述、句式重组、换措辞 | 人工复述、LLM 复述、BERT-ATTACK |
| 对抗后缀 | 追加人类无意义但可越狱/降质的 token 串 | GCG/Zou2023、自动后缀搜索 |
| 上下文扰动 | 插入无关上下文、改 few-shot 顺序、注入干扰段 | distractor / 上下文注入、needle-in-haystack |
| 多语言/方言 | 非英文、方言、翻译改写 | 跨语言扰动、C/Eval 风格 |
| 格式攻击 | 改空白/Markdown/JSON 结构、破坏 schema | 格式腐蚀、schema drift |

## 二、主流基准（各自测什么）

| 基准 | 出处 | 测什么 / 注意点 |
| --- | --- | --- |
| **PromptBench** | Microsoft, 2023 (arXiv:2306.04528) | 字符/词/句/语义 4 级对抗提示；4032 条对抗提示、8 任务、13 数据集；开源 github.com/microsoft/promptbench |
| **PromptAttack** | 同上（PromptBench 家族） | 4 类攻击封装：DeepWordBug(字符)/TextFooler(词)/CheckList(句)/BERT-ATTACK(语义) |
| **AdvGLUE** | Wang et al. 2021 | 在 GLUE 上加文本对抗样本，测 NLU 鲁棒性 |
| **AdvGLUE++** | Wang et al. 2023 | 扩展到 ChatGPT/GPT-4 时代，含自动生成方法与更多样本 |
| **FLAMES** | 上海AI Lab+复旦, NAACL2024 | ⚠️ 常被误记成"事实性"；实为**中文价值观对齐/无害性**对抗基准（公平/安全/道德/合法/数据保护 5 维） |
| **RobustBench** | NeurIPS2021 | ⚠️ 主要是**图像分类器** L∞/L2/常见腐蚀 的对抗鲁棒榜单；作 LLM 鲁棒性"类比参照"而非文本基准 |
| **CheckList** | Microsoft, ACL2020 | 行为测试方法论（不变性/方向期望/最小功能测试），非固定数据集；可派生扰动用例 |
| **CleanLab** | data-centric AI | ⚠️ 偏"标签错误/数据质量"检测库，与提示鲁棒性**相切但不核心**，本篇仅作旁支提及 |
| **PromptRobust** | 2025 综述时间线 | 提示扰动鲁棒性基准（细节待核实） |
| **ReliabilityBench** | 2026-01 (arXiv:2601.06112) | Agent 生产级可靠性：pass@k 一致性 + 语义等价扰动(ε) + 故障注入(λ) 混沌测试 |

## 三、代表工具 / 框架

| 工具 | 归属 | 用途 / 状态 |
| --- | --- | --- |
| **OpenCompass(司南)** | 上海AI Lab | 综合评测平台；2.0(2025-02)加数学/代码/Agent 维度、长文本评估、数据污染检测；路线图含鲁棒性&红队子集 |
| **lm-eval-harness** | EleutherAI | 行业事实标准，500+ 任务；含部分鲁棒/扰动相关任务，但本体是通用评测 harness |
| **Microsoft Counterfit** | Microsoft | 对抗 ML 红队工具包；⚠️ 维护状态/是否归档待核实 |
| **IBM ART** | LF AI & Data | Adversarial Robustness Toolbox；支持规避/提取/投毒/推理攻击+防御，含部分 LLM 支持 |
| **Garak** | NVIDIA | LLM 漏洞扫描器，50+ probes（注入/越狱/幻觉/数据泄露），模块化可扩 |
| **PyRIT** | Microsoft | 生成式 AI 红队编排，支持多轮攻击与自动打分 |

## 四、2025–2026 进展（与上下文工程结合）

- **长上下文鲁棒性**成为独立关注点：needle-in-a-haystack（多位置/多长度热力图）、有序检索、end-of-context 摘要、distractor 抗性——直接对应 Context Engineering 的"长上下文真用不用得上"。
- **Agent 可靠性基准化**：ReliabilityBench(2026) 用"动作蜕变关系+故障注入"把鲁棒性从单轮扩展到多轮生产环境，呼应 chaos engineering。
- **动态/抗污染评测**：283 基准综述(arXiv:2508.15361v1，待核实)与 MMLU-Pro/LiveBench 等推动"静态题库失效→动态对抗"范式。
- OpenCompass 等长上下文榜单把鲁棒性纳入常态化 CI/CD 评测。

## 五、对 Agent / 上下文工程的工程意义

1. **提示词不是一锤定音**：同一意图换措辞性能可大幅波动，提示词模板需做扰动回归测试。
2. **上下文注入/干扰**是 Agent 的真实失效面（见 [[AI Agent 框架 MOC]] 的 Data Injection 笔记），需用上下文扰动基准压测。
3. **长上下文≠可用上下文**：用 stress test 找"lost in the middle"与长尾失效，再决定 RAG/上下文窗口策略。
4. **把鲁棒性当 CI**：Garak/PyRIT/OpenCompass 跑进发布流水线，版本间对比 ASR、降质幅度。
