# AI 模型类型与架构

> 人工智能从「单模态文本处理」向「全感知通用智能」演进的四个阶段与视角：**LLM → VLM → MLLM → LMM**。
> 以及支撑它们的两条技术路线：**外挂适配式（Adapter-based）** 与 **原生多模态（Native / End-to-End）**。

## 一句话脉络
- **LLM** 是内核：绝大多数 MLLM / LMM 的推理能力源自 LLM 范式。
- **VLM** 是分支：专注「视觉 + 文本」；当它的语言部分换成深度 LLM，就升级为 **MLLM**。
- **LMM** 是趋势：从「给 LLM 拼装眼睛（外挂 MLLM）」走向「出生就有视觉听觉（原生 LMM）」。
- 架构差异直接决定**响应速度、信息无损度、交互自然度**。

## 深化补充

### 一句话心智模型（PM 版）

> **这四个词不是四种产品，是同一条演进曲线上的四个采样点。作为 PM 我不需要记住定义，我需要知道的是：在我的场景里，"信息在哪一步被压成文本"决定了我能不能做出那个体验。**

技术分类学对 PM 的价值，只在于它能不能**换算成需求约束**。我给自己定的换算规则：

| 我想要的体验 | 最低要求的模型形态 | 为什么 |
|---|---|---|
| 读屏幕、理解截图 | VLM / MLLM 够用 | 视觉→文本的损耗可接受 |
| 听懂用户"语气不耐烦"并调整 | **必须原生 LMM** | 情绪在波形里，转文本就没了 |
| 打断式自然对话 | **必须原生 LMM** | 全双工是架构属性，管线拼不出来 |
| 端侧本地跑 | 现阶段基本只能 MLLM/小 VLM | 原生 LMM 端侧化尚不成熟（待核实具体端侧原生 LMM 落地情况） |

**最后一行是我最该记住的一行。** 它意味着：现在写端侧 Agent 的 PRD，如果需求里写了"能感知用户情绪语气"，那大概率是在画饼——除非走云端。

### 一个我需要修正的直觉

原文的包含关系图（LMM ⊃ MLLM ⊃ {LLM, VLM}）是**概念上的包含**，容易让人误以为是**能力上的包含**——好像 LMM 天然比 MLLM 强。实际不是：

- **MLLM 的推理能力可能更强**，因为它站在一个已经训熟的强 LLM 底座上；
- **原生 LMM 的感知更自然**，但语言推理不一定超过同期最强纯文本模型。

所以这不是"升级"关系，是**能力换取**：原生多模态用一部分语言推理的确定性，换来了感知的无损和延迟的骤降。理解成"取舍"而非"进化"，我在做技术选型讨论时才不会被"原生的一定更好"这种话带偏。
