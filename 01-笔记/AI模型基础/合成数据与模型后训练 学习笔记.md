**学习定位**：本文是从 [[AI模型基础 MOC]] 锚点向外辐射的「训练/数据侧」种子笔记，专门覆盖「怎么把端侧小模型训好/对齐」，刻意不与 [[端侧模型量化 学习笔记]]、[[移动端 NPU 与推理编译栈 学习笔记]] 的「推理/部署侧」混淆。

**心智模型**：**端侧 SLM 的能力天花板，越来越不取决于预训练规模，而取决于「合成数据质量 × 后训练配方」——这是小模型低成本逼近大模型的关键杠杆。**

## 1. 合成数据生成范式表

> 核心动机：人工标注慢（$1–10/样本、数周）、难扩展；合成数据边际成本近零，可定制、可绕开部分数据授权问题。但「重剂量递归合成」有塌缩风险。

| 方法 | 原理 | 代表实践 | 质量风险 |
|---|---|---|---|
| Self-Instruct | 用 ~175 条种子指令自举生成 (instruction, input, output) 三元组 | Alpaca(52K, GPT-3.5)、Evol-Instruct(WizardLM 迭代加难) | 分布受种子与生成器偏见约束；多样性上限有限 |
| 知识蒸馏（hard/soft/speculative） | 教师大模型生成样本/软标签，学生小模型模仿 | Phi 系列、Orca、DeepSeek-R1-Distill 系列 | 学生继承教师幻觉；soft 蒸馏需白盒访问 |
| 拒绝采样 + 验证过滤 | 多次生成 + 验证器筛优后训练 | Phi-4 后训练的 Pivotal Token Search | 验证器本身可能漏判，错误被放大 |
| 仿真 / 合成环境 | 在模拟器或世界模型里生成轨迹数据 | NVIDIA 11 小时生成 78 万机器人轨迹；Waymo World Model (Genie 3) 多传感器驾驶数据 | 仿真-现实 gap；分布偏移 |
| World model / 定理合成 | 合成数学证明、逻辑轨迹 | AlphaProof / AlphaGeometry 2（IMO 2024 银牌级） | 仅限可验证领域，泛化有限 |
| 智能体自演进 / 自我博弈 | 模型自生成偏好数据、Self-Play 迭代 | SPIN、Meta Self-Reward（迭代 3 次胜率 50%→78%） | 自我反射闭环，塌缩隐患 |
| 对抗生成 / Hard Negative | 生成「接近正确但含瑕疵」样本做难例 | Hard Negative DPO（arXiv:2512.19728，1.5B Qwen2.5） | 需可靠 verifier 定义「错误」 |

## 2. 后训练方法对比表

| 方法 | 原理 | 数据需求 | 对小模型友好度 |
|---|---|---|---|
| SFT（监督微调） | 模仿高质量 (指令, 回答) 对，标准交叉熵 | 高质量指令/对话数据（~100K–1M） | 高（基础必需，成本可控） |
| SFT-from-distill | 用教师模型合成数据做 SFT | 依赖教师模型生成能力 | 高（端侧主流，见 [[端侧小语言模型 SLM 生态 学习笔记]]） |
| DPO（直接偏好优化） | 数学变换把 RLHF 转成单阶段监督式，最大化 chosen/rejected 对数概率差 | 偏好对 (chosen, rejected) + 参考模型 | 高（2 模型、稳定、省算力，2025 已成默认） |
| RLHF（PPO） | 训奖励模型 + PPO 策略优化，KL 约束参考模型 | 人类偏好标注 + 4 模型并行 | 低（资源重、超参敏感、易崩溃） |
| RLAIF（AI 反馈） | 用 LLM/宪法原则替代人类做偏好标注 | AI 生成偏好 或 显式奖励模型 | 中（省标注，但受评判模型偏见放大影响） |

> 补充变体（点到为止）：SimPO（去掉参考模型）、Online/Iterative DPO、GRPO（组内相对优势，无需 Critic）、RLVR（可验证奖励，数学/代码）、PRM（逐步奖励）。趋势：**RLHF 重工程 → DPO 轻量 → GRPO/RLVR 自动化验证**。

## 3. 2025–2026 关键进展表

| 进展 | 要点 | 意义 |
|---|---|---|
| Phi 哲学：教科书级合成数据 | Phi-4（14B）约 40% 合成数据，数学超 GPT-4o（arXiv:2412.08905） | 「数据质量 ≥ 规模」在小模型上被验证 |
| Phi-4-Mini-Reasoning 配方 | 3.8B 四步：蒸馏长 CoT 中训练 → 高质量长 CoT SFT → Rollout DPO → 可验证奖励 RL（arXiv:2504.21233） | 系统化 SLM 训练 recipe 成型，Math-500 超更大蒸馏模型 |
| 蒸馏 scaling / 数据高效后训练 | DeepSeek-R1 用 RL 做数据高效后训练；综述 ACL 2025（arXiv:2510.10991） | 数据价值飞轮成为统一框架 |
| DPO 普及替代 RLHF | 端侧模型（Qwen2.5 / Llama-3.2 / MiniCPM）后训练均走 SFT+DPO(+GRPO) | 小模型对齐工程门槛大幅下降 |
| 合成数据塌缩风险被正视 | Model Collapse（Nature 2024, Shumailov）；ICLR 2025 称极低比例（约 1/1000）即可触发；"Hall of Illusions" 公开信（Lei 2025） | 合成占比需披露 + 崩溃测试 |
| 行业预测 | Gartner：2028 年 80% 训练数据为合成（**预测值，非实测，待核实**） | 方向性信号，非硬事实 |
| 端侧后训练低成本化 | MiniMind 级别：~2 小时 / 单卡 3090 完成小模型全流程 | 利于端侧模型 OTA 快速迭代 |

## 4. 端侧小模型后训练流程示意表

| 阶段 | 目标 | 典型做法 | 备注 |
|---|---|---|---|
| 0. 预训练 / 继续预训练 | 基础语言能力、领域适配 | 领域语料续训（MiniCPM 用多尺度 token 衰减） | 可继承通用基座 |
| 1. SFT（含 from-distill） | 指令跟随、对话质感 | 教师合成 + 精选真实数据（~100K–1M） | MiniCPM / Qwen 均用 |
| 2. 偏好对齐 DPO | 风格、安全、有用性 | 偏好对 + 单阶段优化 | 端侧主流，成本低 |
| 3. 推理增强（可选） | 数学 / 代码 / 长链推理 | 长 CoT 蒸馏 + GRPO/RLVR | Phi-4-Mini-Reasoning 范式 |
| 4. 量化部署 | 上设备 | 见 [[端侧模型量化 学习笔记]] | **本篇不展开推理/量化** |

## 5. 对 OS PM 的意义

- **快速迭代闭环**：端侧小模型靠「合成数据 + 后训练」可自主生产训练样本、低成本对齐，避免每次都依赖真实数据采集与人工标注，缩短版本演进周期（MiniMind 级成本 ≈ 单卡数小时）。
- **隐私 / 合规友好**：合成数据可在自有云或设备端生成，减少跨域真实用户数据流转；但注意「合成」≠「自动合规免责」，监管口径待确认。
- **OTA 模型更新**：小模型后训练轻，适合随系统版本做模型能力增量更新，与 [[移动端 NPU 与推理编译栈 学习笔记]] 的部署链路配合。
- **风险需纳入评估**：合成塌缩、偏见放大、自我博弈失控——产品侧要监控真实世界 held-out 指标是否随合成占比升高而漂移。
- **选型启示**：优先采用已验证的「SFT-from-distill + DPO」配方，推理增强按需加 GRPO/RLVR，避免一上来就上 RLHF 重工程。

## 6. 待解问题（深度留白）

- [ ] 合成数据占比多少会过拟合/塌缩？极端研究称 ~1/1000 即可触发，但端侧实际安全阈值待核实。
- [ ] DPO 在 1B 以下模型是否仍有效？偏好信号是否足够？
- [ ] 蒸馏 scaling law：教师能力与学生规模是否存在饱和点？
- [ ] 端侧小模型能否「自举」（self-reward）而不依赖云端大模型教师？
- [ ] RLAIF 的「评判模型偏见」在端侧场景如何检测与缓解？
- [ ] 长 CoT 蒸馏对小模型是真推理提升，还是过拟合训练分布？
- [ ] 合成数据能否满足 GDPR / 国内数据合规？「绕开真实数据合规」是否误判？
- [ ] GRPO / RLVR 在 <3B 模型上的奖励信号噪声问题如何解决？
- [ ] 后训练各阶段（SFT vs DPO vs RL）数据配比的最优组合是什么？
- [ ] 与 [[端侧模型量化 学习笔记]] 的顺序：先对齐后量化，还是量化感知后训练（QAT）？

- Gartner「2028 年 80% 训练数据为合成」为**预测值**，非实测，来源可靠性需交叉验证。

- RLAIF 偏见放大的量化程度、端侧可检测性尚未有统一结论。
