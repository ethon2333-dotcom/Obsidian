# 大模型四类型：LLM / VLM / MLLM / LMM

> 这四个概念代表 AI 从「单模态文本」向「全感知通用智能」演进的不同阶段与视角。

## 1. LLM（Large Language Model，大语言模型）
- **核心焦点**：纯文本（文本输入 $\rightarrow$ 文本输出 / 代码）。
- **技术本质**：基于 Transformer 架构（主要是 Decoder-only），海量文本预训练，预测下一个 Token 概率分布。
- **核心能力**：逻辑推理、文本创作、代码生成、翻译、上下文理解。
- **典型代表**：GPT-3.5/4（纯文本版）、Llama 3、DeepSeek-R1、Claude 3.5 Text。

## 2. VLM（Vision-Language Model，视觉语言模型）
- **核心焦点**：专精「图像 / 视频 + 文本」跨模态交互。
- **技术演进**：
  - **早期（判别式）**：如 OpenAI **CLIP**，做图文特征对齐和图文检索，不能长篇图文对话。
  - **现代（生成式）**：视觉编码器 + 文本生成能力，能理解图片并答复杂问题（如「图中数学题怎么解」）。
- **典型代表**：CLIP、BLIP、ALBEF，以及现代视觉对话能力的 Qwen2-VL、LLaVA。

## 3. MLLM（Multimodal Large Language Model，多模态大语言模型）
- **核心焦点**：**以 LLM 为「思考大脑」**，挂载其他模态「感官接收器」。
- **架构特征**：「外挂模式」—— 预训练视觉编码器（如 ViT）或音频编码器，经连接器（Projector / Adapter，如 MLP 或 Q-Former）映射到 LLM 的 Token 空间，让 LLM 像处理文本一样处理图 / 音。
- **核心优势**：继承 LLM 极强的常识推理与复杂指令遵循能力，只需训练极少连接层即可快速赋予看图 / 听音能力。
- **典型代表**：LLaVA、BLIP-2、Qwen2-VL。

## 4. LMM（Large Multimodal Model，大多模态模型）
- **核心焦点**：涵盖面最广的统称，代表**全模态（Any-to-Any）通用大模型**终极形态。
- **与 MLLM 的细微区别**：
  - **MLLM** 强调「以文本 LLM 为主体去拼接其他模态」；
  - **LMM** 是更广泛称呼，**更强调原生（Native）多模态**——模型从一开始就统一架构下同时接受文本、图像、声音、视频乃至 3D 联合预训练（如 GPT-4o 能原生直接输出语音，无需经 TTS 转换）。
- **典型代表**：GPT-4o、Gemini 1.5 Pro、Claude 3.5 Sonnet。

## 对比与包含关系

| 概念 | 核心模态 | 核心架构特征 | 优势与局限 | 典型代表 |
|------|------|------|------|------|
| **LLM** | 纯文本 / 代码 | Transformer Decoder 自回归 | 推理最强，但对视觉 / 听觉无感知 | Llama 3, DeepSeek-R1 |
| **VLM** | 视觉 (图/视) + 文本 | 视觉 Encoder + 语言处理头 | 专注图文对齐；早期缺乏复杂推理 | CLIP, BLIP-2, Qwen2-VL |
| **MLLM** | 文本 + 视觉/音频等 | **LLM 底座** + 模态适配器 (Adapter) | 开发成本低、推理强；非文本模态转换有损耗 | LLaVA, InternVL |
| **LMM** | 全模态 (图/音/文/视) | 原生端到端多模态 Token 化 | 延迟极低（实时语音交互）、感知自然；训练极难 | GPT-4o, Gemini 1.5 |

### 三者关系
1. **LLM 是内核**：绝大多数 MLLM / LMM 的底层认知与推理能力源自 LLM 训练范式。
2. **VLM 是分支**：VLM 专注「视觉 + 文本」；当 VLM 的语言处理部分换成深度理解的 LLM，就升级为 **MLLM**。
3. **LMM 是趋势**：行业正从「给 LLM 拼装眼睛（MLLM）」向「出生就具备视觉和听觉（原生 LMM）」演进。

> 外挂适配式多模态是「给纯文本大脑接上摄像枪、麦克风和翻译官」；原生多模态则是「大脑天生同时发育出视觉、听觉和语言神经」。

## 深化补充

> 本篇概念已比较完整，这里只补**我自己容易记混的辨析**和**PM 视角的落点**，不重复定义。

### 帮我记住区别的一句话

> **VLM 是"专才"，MLLM 是"通才配了副眼镜"，LMM 是"生下来就五感俱全"。而 LLM 是前三者共同的那颗脑子。**

我之前老把 VLM 和 MLLM 搞混，后来抓住一个判据就不混了：**看语言侧有多深**。
- 语言侧只是个"对齐/检索头"（CLIP 那种）→ **VLM**，它能告诉你"这是猫"，但不能跟你论证猫为什么这么坐；
- 语言侧是个完整的强 LLM，视觉只是外挂进来的 → **MLLM**；
- 压根没有"外挂"这个动作，所有模态从第一层就在一个空间里 → **LMM**。

再补一个记忆锚：**LLaVA、Qwen2-VL 在表格里同时出现在 VLM 和 MLLM 两行**——这不是笔误，是因为现代 VLM 基本都是 MLLM 架构实现的。"VLM"现在更多是**按模态范围**命名（只管视觉+文本），"MLLM"是**按架构方式**命名（LLM 底座 + 适配器）。**一个是范围词，一个是架构词，不在一个坐标轴上，所以会重叠。** 这个点想通之后我就不纠结了。

### 具体例子：同一个任务，四种模型分别怎么处理

任务：用户拍了张手机设置界面的照片，问"帮我把这个开关关掉"。

| | 能做到哪一步 | 卡在哪 |
|---|---|---|
| **LLM** | 看不见图，只能问"你说的是哪个开关" | 无视觉输入 |
| **早期 VLM（CLIP 类）** | 能判断"这是一张设置页截图" | 不能定位具体控件、不能规划动作 |
| **MLLM（LLaVA/Qwen2-VL）** | 能读懂界面文字、定位开关、输出"点击坐标 (x,y)" | **视觉 token 有压缩损耗**，小字/密集列表易错；纯文本输出，动作要外部执行器落地 |
| **原生 LMM** | 同上，且能边看边听用户补充"不是那个，下面那个" | 端侧跑不动；成本高 |

**结论对我的意义**：做手机 GUI Agent，**MLLM 就是当前的工程最优解**，不用等原生 LMM。真正的瓶颈不在模型类型，而在 ① 视觉 token 的分辨率损耗 ② 动作执行通道（见 [[端侧执行通道 GUI 与 MCP 路线之争]]）。这也解释了为什么工业方案要**VLM + 无障碍树双通道**——用结构化文本补视觉的损耗。
