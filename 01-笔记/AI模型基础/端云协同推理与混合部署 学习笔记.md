# 端云协同推理与混合部署 学习笔记

## 学习定位
端云协同推理（hybrid inference）回答的是一个很朴素但很关键的产品问题：**一次 AI 请求到底跑在端侧还是云端，由谁、依据什么来决定？** 它与 [[端侧大模型推理 学习笔记]] 的区别在于，后者只讲"纯端侧怎么跑"，本篇讲的是"端 + 云怎么分工、怎么切、怎么兜底"。它与 [[隐私计算与端云协同 学习笔记]] 的区别在于，后者聚焦"信任技术（TEE/PCC 如何保证云侧不偷看）"，本篇聚焦"路由决策与混合部署形态"——两者是同一枚硬币的两面，PCC 是端云协同里"隐私云"这一端的代表实现。预算侧可引用 [[端侧 AI 基建与算力预算]]。

> **心智模型：端云协同像把难活交给云端大力士、把日常交给身边小助手，关键是谁来当调度员——路由策略就是那个调度员。**

## 一、概念定义
| 术语 | 定义（核实口径） | 代表 / 备注 |
| --- | --- | --- |
| Hybrid inference（混合推理） | 同一个 AI 请求，按策略在端侧与云端之间分配计算，端侧跑轻量部分、云端跑重负载部分 | 区别于纯端侧（见 [[端侧大模型推理 学习笔记]]）与纯云端 |
| 端云分流 / 端云协同 | 由设备先做能力判断：能本地做的本地做，超出端侧能力或隐私/延迟约束的才上云 | Apple Intelligence 的本地优先 + PCC 兜底即此范式 |
| 模型路由（model routing） | 在请求发出前/中，用轻量分类器或级联策略把请求派给"最便宜且够用"的模型/节点 | RouteLLM、FrugalGPT、Bedrock Intelligent Prompt Routing、Azure Model Router |
| 端侧 SLM / 小模型 | 跑在 NPU/端侧的轻量模型，承担低延迟、隐私敏感任务 | 见 [[端侧小语言模型 SLM 生态 学习笔记]]；Phi、Gemini Nano、端侧意图框架 |
| 隐私云（privacy cloud） | 云端算力但带隐私保证（无状态、可审计、TEE）的后端 | Apple PCC、PCC on Google Cloud（NVIDIA 机密计算 + Intel TDX） |

## 二、为什么需要端云协同（四维权衡）
| 维度 | 端侧 | 云端 | 备注 |
| --- | --- | --- | --- |
| 能力 | 受 NPU/内存/电量限制，适合轻任务 | 可跑前沿大模型，深度推理强 | 端侧 SLM 见 [[端侧小语言模型 SLM 生态 学习笔记]] |
| 隐私 | 数据不出设备，天然强 | 需 TEE/PCC 等信任技术兜底（见 [[隐私计算与端云协同 学习笔记]]） | 敏感数据尽量端侧 |
| 延迟 | 本地毫秒级，离线可用 | 受网络往返与排队影响 | 实时/可穿戴场景偏端侧 |
| 成本 | 一次性硬件，无 token 计费 | 按 token/API 计费，易随用量放大 | 路由核心动机见 [[端侧 AI 基建与算力预算]] |

## 三、路由策略（端云怎么分）
| 策略 | 做法 | 优点 | 代价 / 局限 |
| --- | --- | --- | --- |
| 按任务复杂度路由 | 轻量分类器预估难度，简单走端侧/小模型，复杂走云端/大模型 | 省成本、保质量；RouteLLM 在 MT-Bench 省 85% 成本仍保 95% GPT-4 质量 | 难度预估有误会错派；需带评估闭环防止静默劣化 |
| 按能力边界路由 | 端侧 SLM 默认处理，能力/置信不足再升级到云端 LLM | 默认隐私强、延迟低 | 升级判据难定；跨端云一致性体验要设计 |
| 投机卸载（speculative offload） | 先在端侧跑、置信度不够再"投机性"地把请求或后半程卸载到云（cascade 式） | 多数易请求零云成本 | 失败请求叠加两端延迟；不适合实时交互（更适合批处理） |
| 层切分（layer-wise split） | 把 transformer 层拆开：前 N 层在端提特征，高阶在云；或 attention head / FFN 子块级切分 | 端云协同算、隐藏通信延迟（Splitwise 用三阶段异步流水线） | 切分点/特征压缩需调优；网络差时回退端侧 |
| early-exit | 模型中间插出口，简单样本浅层退出，复杂继续深层；可与 split 组合（SplitEE） | 简单样本省大量算力 | 需改模型结构；出口阈值难调，可能掉精度 |

## 五、2025–2026 进展（广度速览）
| 方向 | 关键事实（核实） | 含义 |
| --- | --- | --- |
| 端云协同框架精细化 | HybridFlow（ICML 2026）：把查询拆成 DAG，子任务级在线预算感知路由（端 Llama3.2-3B + 云 GPT-4.1） | 从"整请求级"路由走向"子任务级 + 依赖并行" |
| 层切分/卸载系统化 | Splitwise：Lyapunov 辅助 DRL 把 LLM 层拆到端云，1.4×–2.8× 加速、最高 41% 省电 | 切分点动态化、通信延迟被流水线隐藏 |
| 端侧 early-exit 加速 | SpecEE（无问芯穹，ISCA 2025）：基于推测的 early-exit 端侧推理引擎 | 端侧异构 NPU/CPU/GPU 协同提速 |
| 模型路由器智能化 | Router-R1(2026) 用 RL 把路由当序贯决策；R2-Router 做子任务级编排 | 路由器能从"阈值"走向"自学习、可泛化到未见模型" |
| Agent 路由 / 混合编排 | 云边协同推理智能体（如医疗辅助诊断框架，2025–2026）集成"智能路由 + 动态脱敏" | OS 级 agent 把路由当一等公民，与隐私脱敏绑定 |
| 隐私云外延 | Apple PCC 扩展至第三方云（Google Cloud + NVIDIA 机密计算） | 隐私云不再绑定自有数据中心，混合部署信任边界上移 |

## 六、对 OS PM 的意义
对 Android OS PM 来说，端云协同不是一个技术实现细节，而是**系统级默认体验的调度策略**。PM 要决定的第一件事是"默认端侧、按需上云"还是"默认云端、端侧兜底"——前者隐私/延迟好但能力天花板低，后者能力强但成本与信任风险高。路由的判据（复杂度、能力边界、隐私分级）应当作为可配置策略沉淀在系统里，而不是写死在某个 App。可参考 [[端侧意图框架 学习笔记]] 把"意图→路由"做成可插拔策略，并与 [[手机AI智能体知识库]] 的本地知识结合，决定哪些请求根本不必出端。

兜底设计是 PM 最容易翻车的地方：端侧模型能力不够时如何平滑升级到云、网络抖动时如何降级、云端隐私云（如 PCC 类方案）不可用时如何回退到纯端侧并诚实告知用户。这些 fallback 路径要像主路径一样被设计和测试，否则"智能"会变成"偶发智障"。系统级挑战详见 [[OS-PM-端侧大模型系统级挑战]]。

信任边界要写进产品话术与设置项：哪些数据走了隐私云、是否可审计、用户能否关闭云端桥接（类似 Apple 用 MDM 开关关 ChatGPT 桥）。这部分的技术底座在 [[隐私计算与端云协同 学习笔记]]，PM 的任务是把它转译成用户可理解、可控制的开关与提示，而不是默认全量上云。
