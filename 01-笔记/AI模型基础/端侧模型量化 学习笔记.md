# 端侧模型量化 学习笔记

> 学习定位：这是一篇**广度种子笔记**（BREADTH > DEPTH）。目标是在一张地图里把量化这条线从「是什么」铺到「端侧为什么离不开它」、再到「2025-2026 走到哪了」。深度细节（具体算法推导、各家 kernel 实现、校准集怎么选）我留了 `- [ ]` 待补，等后续按项目需要再往下凿。
> 本文是 own-words 综合，不是论文复读；涉及具体数字的，凡来自媒体/二手口径的均标「待核实」，不编造。

---

## 一、一句话心智模型

**量化 = 给模型「降低数字的精度」来减肥。**

模型权重原本存成 FP16/BF16（每个数 2 字节、能表示很细的小数）；量化把它压成 INT8（1 字节）、INT4（半字节）、甚至 1.58-bit（约 0.2 字节）这样的「粗数字」。位数越少 → 文件越小、占内存越少、算得越快、越省电——但信息丢得越多，模型可能变笨。

> **端侧视角补一句**：云端可以堆显存硬扛 FP16，手机只有几 GB 可用内存 + 散热极差的 NPU/CPU。**端侧 AI 的命脉不是「能不能跑」，而是「能不能在 4GB 内存和 3W 功耗预算里跑得动」——量化是这道算术题唯一的答案。**

---

## 二、为什么是端侧 AI 的命脉

端侧和云端面对的是两套完全不同的约束，量化在端侧不是「优化项」而是「前提项」：

| 端侧约束 | 量化怎么解 |
|---|---|
| **内存/RAM 硬上限**（多数手机可用 4–8GB，还要分给系统和其他 App） | FP16→INT4 把权重体积极大约压到 1/4，让 7B 模型从 ~14GB 落到 ~4GB（待核实具体值，见来源清单） |
| **功耗/续航/散热** | 低位宽让 NPU/CPU 的 MAC 运算更少数据搬运、更少内存访问，能耗显著下降 |
| **离线可用** | 模型能塞进设备本地存储，才能断网跑；不量化就塞不进 |
| **首 token 延迟 / 隐私** | 本地推理免去网络往返；量化让本地推理达到「能交互」的速度 |

几个**可记住的数量级**（均为 FP16/BF16 = 2 字节基准）：

- INT8 = 1 字节 → 体积 **约 1/2**（相对 FP32 则是「约 75% 缩减」，一手源 TianPan 2026 表述）
- INT4 = 0.5 字节 → 体积 **约 1/4**
- INT2 = 0.25 字节 → 体积 **约 1/8**
- 1.58-bit（BitNet 三值）≈ 0.2 字节 → 体积 **约 1/10**

> **关键认知**：省的不是「算力」本身，主要是**内存带宽和存储**。LLM 推理是 memory-bound（权重一遍遍从内存搬到计算单元），位数减半 ≈ 搬运量减半 ≈ 又快又省电。这条是理解量化收益的第一性原理。

## 三、主流量化方法

### 3.1 第一个切分维度：训练后量化 PTQ vs 量化感知训练 QAT

| | PTQ（Post-Training Quantization） | QAT（Quantization-Aware Training） |
|---|---|---|
| 时机 | 模型训完后再压 | 训练/微调时就模拟量化误差 |
| 成本 | 低，几小时~几分钟校准集跑一遍 | 高，要重新训练/微调 |
| 精度保留 | 中低位宽（INT4 以下）掉点明显 | 同压缩率下明显更稳 |
| 代表 | **GPTQ、AWQ、GGUF K-quants** | BitNet 系（从零就 1.58-bit）、QLoRA |
| 端侧常用度 | ⭐⭐⭐ 绝对主力 | ⭐ 多用于"原生低位宽"模型 |

> 一句话：**PTQ 是工程默认（拿来就用），QAT 是「为低位宽而生的模型」才走**（如 BitNet 是训练时就按 1.58-bit 设计的，不是训完再压）。

### 3.2 第二个切分维度：量化谁——权重-only vs 权重+激活

激活（每层算出来的中间结果）也有分布问题，尤其「离群值（outlier）」会毁掉低位宽。

| 方案 | 含义 | 取舍 |
|---|---|---|
| **W4A16 / W8A16**（权重 INT4/8，激活 FP16） | 只压权重，激活保持高精度 | 简单、最常用（AWQ 默认 W4A16）；激活占内存但不量化 |
| **W8A8** | 权重+激活都 INT8 | 精度几乎无损，云端服务端主流 |
| **W4A8 / W4A4** | 都压到 4-bit | 更狠；Atom（MLSys 2024）做到 W4A4 仍近乎无损（待核实一手数据） |
| **KV Cache 量化** | 推理时缓存的键值也压 | 长上下文端侧的关键——见 [[端侧意图框架 学习笔记]] 里长上下文落地的关联 |

### 3.3 第三个切分维度：精度档位与代表算法

| 精度 | 含义 | 代表算法 / 格式 | 端侧角色 |
|---|---|---|---|
| **FP16/BF16** | 基准（不量化） | 原始 | 云端默认；端侧仅极小模型 |
| **INT8** | 8-bit | 通用 PTQ、ONNX Runtime INT4/INT8 | 「生产安全默认」，掉点 <1%（待核实） |
| **INT4** | 4-bit | **AWQ、GPTQ、GGUF Q4_K_M、QuIP#** | 端侧主力甜点区 |
| **INT2** | 2-bit | 激进研究、混合精度里的「不重要层」 | 长尾探索 |
| **1.58-bit** | 三值 {-1,0,+1} | **BitNet b1.58** | 1-bit 前沿 |

### 3.4 重点算法速查（own-words 版）

- **GPTQ**（2022，IST Austria）：PTQ。用校准集算 Hessian，逐列量化、并反向补偿未量化列以最小化重建误差。代价是量化慢（要算 Hessian）。开「INT4 端侧可行」的先河。
- **AWQ**（2024，MIT Media Lab）：PTQ，「激活感知」。发现少数「显著权重通道」配对大激活，量化它们损失最大——于是给这些通道做 per-channel 缩放保护起来。比 GPTQ 快 5–10×、精度常更好，**2024–2026 的 INT4 权重-only 生产默认**。llama.cpp / vLLM / TensorRT-LLM 都一等支持。
- **GGUF K-quants**（llama.cpp 生态）：一套从 Q2_K 到 Q8_0 的量化家族，按「超级块 + 子块」精细配 scale。**Q4_K_M（约 4.5 bpw，掉点 ~1–2%）是本地 LLM 事实默认**，专为 CPU/Apple Silicon 设计（区别于 AWQ 的 GPU 取向）。
- **混合精度**：不同层/不同张量用不同 bit。代表：**Apple 端侧基础模型用混合 2/4-bit、平均 ~3.7 bpw**；**Gemini Nano 4-bit**。
- **稀疏化（Sparsity）**：和量化「正交互补」的另一条减肥路——把不重要的权重置零跳过计算。MSR 的 **Q-Sparse** 做激活稀疏，与 BitNet 互补（待核实细节）。
- **QLoRA**（ICLR/ICML 2023）：4-bit 权重上做 LoRA 微调，把「量化 + 训练」合流，是 QAT 思路在端侧小模型上的实用化。

## 四、精度-速度-体积三角权衡

三者不可能同时最优，是个**互相挤占的三角**：

```
        体积最小 (INT2 / 1.58-bit)
              /\
             /  \
            /    \
  速度最快  ------  精度最高 (FP16)
```

- **压得越狠（位宽越低）** → 体积越小、越快、越省电 ✅，但精度掉得越多 ❌。
- **甜点区共识**：INT4（尤其 AWQ / Q4_K_M）是「体积-精度」的最佳折中；INT8 是「精度优先」的安全区；≤INT2 或 1-bit 是「极限体积」的前沿、精度风险高。
- **激活比权重更娇贵**：压权重到 INT4 较安全，压激活到 INT4 容易崩——所以 W4A16 比 W4A4 稳。这是为什么「权重-only」是端侧最稳的起步姿势。
- **校准集决定下限**：PTQ 精度高度依赖校准集是否匹配真实场景（有实测案例：换中文校准集后精度翻倍）。这条是端侧落地最容易踩的坑。

> **PM 一句话**：选量化档位不是「越狠越好」，是「在你的内存预算内选精度掉得最少的那一档」。先定设备内存上限，再倒推能用几-bit。

## 五、2025-2026 进展（1-bit / BitNet 等）

### 5.1 BitNet：把「低位宽」从压缩技术变成「训练目标」

- **BitNet b1.58**（微软，核心论文 2024-02）：权重压到**三值 {-1, 0, +1}**，激活 8-bit（**W1.58A8**）。关键：**从零训练就按这个格式设计，不是训完再压**。
- **bitnet.cpp**（2024-10 发布 1.0）：1-bit LLM 的官方 C++ 推理框架，带专用三元内核。
  - ARM CPU 提速 **1.37×–5.07×**，能耗降 **55–70%**；
  - x86 CPU 提速 **2.37×–6.17×**，能耗降 **71–82%**；
  - 宣称单 CPU 可跑 100B 的 BitNet b1.58，速度接近人读（5–7 tok/s）。
- **BitNet b1.58 2B4T**（官方 2B 模型，HuggingFace 2025-04）：4 万亿 token 训练、约 **0.4GB**、性能对标同规模全精度开源模型。
- **BitNet a4.8**（2024-11）：进一步把激活压到 4-bit。

> 意义：BitNet 证明「1-bit 级模型不是玩具」——在极小体积下能保持可用能力，且专用内核带来数量级的能耗优势。**这是端侧（尤其 IoT、手机 NPU 未来）最值得盯的路线。**

### 5.2 端侧小模型量化已成「出厂标配」

2025–2026 主流端侧模型出厂即量化，量化方案本身成了产品规格：

| 模型 | 参数量 | 量化方案 | 端侧形态 |
|---|---|---|---|
| **Gemini Nano** | ~1.8B / ~3.25B | **4-bit** | Android AICore 系统级预装 |
| **Apple 基础模型** | ~3B | **混合 2/4-bit（avg ~3.7 bpw）** | Apple Intelligence，iOS 18+ |
| **Phi-3 Mini** | 3.8B | 4-bit（社区/QLoRA） | 开放权重 |
| **Llama 3.2** | 1B / 3B | 4-bit（社区） | 开放权重，llama.cpp |
| **Qwen2** | 0.5B / 1.5B | 4-bit（社区） | 开放权重 |
