# 系统级 Agent「场景化意图快捷指令」PRD 范例（Demo）

> 这是一份**可直接套用的范例**，演示如何用 [[PRD_Template]] / [[PRD写作SOP]] 的结构写一份「系统级产品」的 PRD。
> 产品假设：某 OS 厂商为系统级 Agent 提供「场景化意图快捷指令」能力，让用户在锁屏/语音/跨 App 场景下用一句话触发多步操作。
> 关联知识：[[APP INTENTS]] · [[Apple AppIntents Schema Protocol 2026]] · [[Agent 身份与硬件级审批]] · [[Function Calling 端侧工具调用]] · [[System Orchestrator 系统编排]]

## 1. 背景与问题（Why）
- **现状**：用户每天在多个 App 间重复执行「组合操作」（如"回家路上给我妈发消息说我晚点到 + 播放播客"）。现有快捷指令需手动编排，门槛高、跨 App 调用受限。
- **问题**：系统级 Agent 已具备自然语言理解，但**缺少标准化的能力暴露面**——App 不知道该如何安全地把自己的能力开放给系统 Agent；系统也不知道该在何时、以何种权限替用户执行。
- **机会**：参照 [[Apple AppIntents Schema Protocol 2026]] 的意图声明范式，建立 OS 原生「意图快捷指令」能力，让开发者低门槛接入，用户一句话即用。

---

## 2. 目标与成功指标（What & Metrics）
**目标**：让系统级 Agent 能安全、稳定地执行跨 App 的「场景化意图」，且开发者接入成本 ≤ 1 人日。

| 指标 | 基线 | 目标（3 个月） |
|---|---|---|
| 周活跃触发用户数 | 0 | ≥ 500 万 |
| 意图执行一次成功率 | — | ≥ 92% |
| 平均端到端延迟（含确认） | — | ≤ 1.8s（端侧优先，链 [[Function Calling 端侧工具调用]]） |
| 开发者接入时长 | — | 中位 ≤ 1 人日 |
| 误触发/越权投诉率 | — | ≤ 0.3% |

**非目标（Out of Scope）**：第三方网页自动化（本版本不开放浏览器域）；企业 MDM 托管策略（下版本）。

---

## 3. 用户场景与故事（User Stories）
- **场景 A（通勤）**：用户语音"回家路上给妈妈发我晚到，并放播客" → Agent 解析为两个意图：`sendMessage` + `playMedia`，在锁屏以 [[Agent 身份与硬件级审批]] 要求的确认 UI 一次授权后顺序执行。
- **场景 B（跨设备）**：手机端说"把这张图发到平板备忘录" → 经 [[System Orchestrator 系统编排]] 路由，识别目标设备在线后执行。
- **场景 C（失败兜底）**：某意图所需 App 未安装 → Agent 不崩溃，改为返回「可替代方案」或降级提示（见 §7）。

---

## 4. 需求范围
### 4.1 功能需求
- FR1 意图声明：开发者通过 schema 声明意图（入参、出参、所需权限），平台生成标准调用面。
- FR2 自然语言解析：系统 Agent 将用户语句映射到意图+参数（含消歧）。
- FR3 编排执行：多意图按依赖图顺序/并行执行，支持中断与回滚。
- FR4 确认与审批：高风险意图（支付、删除、分享）必须走确认 UI（链 [[Confirmation UI 安全机制]]）。

### 4.2 非功能需求
- NFR1 隐私：跨 App 数据不出设备优先；云端仅用于解析兜底，且脱敏。
- NFR2 性能：解析+编排 P95 ≤ 800ms（端侧）。
- NFR3 安全：防 [[XPIA 跨提示注入]]，意图参数不可被外部页面篡改。
- NFR4 兼容：向后兼容旧版 intent 声明（弃用周期 ≥ 2 个系统版本）。

---

## 5. 能力暴露 / 意图 Schema（核心章节）
> 系统级 PRD 与 App PRD 最大差异：**必须定义「接口面」**。

```yaml
# 意图声明示例（参考 AppIntents 范式）
Intent:
  name: SendMessage
  parameters:
    - recipient: Contact   # 类型约束
    - content: String
  requiredPermission: [contacts:read, message:send]
  riskLevel: medium        # 决定是否需要确认 UI
  onDeviceOnly: true       # 端侧执行优先
```

- 平台提供 Registry，开发者自助注册；系统侧做静态校验 + 运行时权限裁定。
- 详细字段规范见 [[Apple AppIntents Schema Protocol 2026]]。

---

## 6. 权限与审批流
- 权限分级：low（无需确认）/ medium（隐式授权，可撤销）/ high（每次显式确认，硬件级背书见 [[Agent 身份与硬件级审批]]）。
- 审批 UI 不可被意图内容伪造（防提示注入）。
- 用户可在系统设置中按 App / 按意图粒度回收授权。

---

## 7. 系统编排与 Fallback
- 编排由 [[System Orchestrator 系统编排]] 统一负责，App 之间不直接互驱（隐私隔离）。
- Fallback 策略：
  1. 意图不可用 → 返回替代意图或降级提示，不抛错中断整条链；
  2. 网络/设备离线 → 排队，恢复后重试（幂等设计）；
  3. 用户中途取消 → 已执行步骤提供「撤销」入口（若可逆）。

---

## 8. 端侧与隐私
- 解析与编排默认端侧（链 [[Function Calling 端侧工具调用]]、[[Local Agent Bench 端侧智能体基准]]）。
- 仅当端侧置信度低于阈值才升云，且用户可见「本次使用了云端」标识。

---

## 9. 验收标准（Definition of Done）
- [ ] 一条跨 2 个 App 的场景化意图端到端跑通，成功率 ≥ 92%
- [ ] high 风险意图在测试中被强制走确认 UI（含注入攻击用例 10 条，0 绕过）
- [ ] 开发者接入 demo 在 1 人日内完成（外部招募 5 名开发者实测）
- [ ] 离线场景 Fallback 不崩溃、可恢复
- [ ] 隐私审计：跨 App 明文数据 0 出端

---

## 10. 里程碑与风险
| 阶段 | 时间 | 交付 |
|---|---|---|
| M1 意图 Schema 与 Registry | W1-2 | 开发者可注册 |
| M2 端侧解析+编排 | W3-5 | 通勤场景跑通 |
| M3 确认 UI 与安全 | W4-6 | 通过注入测试 |
| M4 灰度 | W7-8 | 5% 用户 |

**风险**：开发者接入意愿低 → 配套模板与示例库（复用 [[PRD学习笔记]] 思路做开发者 onboarding）。

---

## 附：本范例用到的 PRD 写法要点
- 写 What & Why，不写 How（实现细节留给研发）
- 系统级产品必须单独写「能力暴露/接口面」「权限审批」「编排与 Fallback」「端侧隐私」
- 验收标准可勾选，对齐 [[PRD写作SOP]] 的 12 项检查清单
