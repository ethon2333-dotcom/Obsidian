# 什么是 PRD 与常见形式

> 对应课程第 1–3 集 ｜ 回 [[PRD MOC]]

## PRD 是什么
产品需求文档（Product Requirements Document）：把「为什么做、做什么、怎么做」写清楚，让研发 / 设计 / 测试能据此落地的一份契约式文档。

## 常见形式（第 2–3 集）
| 形式 | 适用场景 | 优点 | 注意 |
| :--- | :--- | :--- | :--- |
| Word / Markdown 文档 | 大多数团队、需归档评审 | 结构清晰、易版本管理 | 交互细节需配图 |
| Axure 原型 + 注释 | 重交互产品 | 原型即说明 | 维护成本高 |
| 蓝湖 / Figma 标注 | 设计交付型 | 标注直观 | 缺业务背景 |
| 表格 / 禅道类 | 敏捷小团队 | 快 | 易丢失上下文 |

> [!tip] 选型
> 新人建议 **Markdown 文档 + 原型链接**（即 [[PRD_Template]] 这种结构），既专业又好维护，也方便进 Obsidian 做知识管理。

## 需求说明的课程目标（第 1 集）
交付物 = 让研发「无需二次确认」就能开发的功能 / 交互说明。这也是后面 [[PRD-交互说明四问法]] 要解决的。
