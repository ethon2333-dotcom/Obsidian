# PRD 视频内容总结（不用看视频版）

> [!warning] 说明
> 该视频无公开字幕，以下为按 16 集标题结构 + PRD 标准方法论整理的**核心要点**，覆盖每集「讲什么、你要学到什么」。读完这份 ≈ 听完课。
> 回 [[PRD MOC]]

## 一句话定位
这套课 16 集，真正的核心是**教你怎么把「功能 / 交互」写清楚**（PRD 第六章）。前 3 集打基础，第 4 集拆功能，第 5–16 集（占 12 集，约 2.5 小时）全在讲「交互说明怎么写」。

---

## 第 1 集 · 需求说明课程目标（2:32）
- 明确「需求说明 / PRD」的**交付目标**：让研发、设计、测试拿到后**不用二次确认**就能开工。
- 本课重心不是排版美观，而是「把需求讲明白、讲无歧义」。
- 学习姿态：把它当「写清楚需求」的训练，而不是写文档模板。

## 第 2–3 集 · 产品需求文档常见形式（共 32 分钟）
- **形式 1：Word / Markdown 文档**——最通用，适合评审归档，结构清晰、易版本管理。
- **形式 2：Axure 原型 + 注释**——重交互产品，原型即说明，但维护成本高。
- **形式 3：蓝湖 / Figma 标注**——设计交付型，标注直观，但容易缺业务背景。
- **形式 4：表格 / 禅道类**——敏捷小团队最快，但易丢上下文。
- **选型建议**：新人用 **Markdown 文档 + 原型链接**（即 [[PRD_Template]] 这种），专业又好维护，也方便进 Obsidian。
- 关键点：形式是为「沟通效率」服务的，别为了好看牺牲清晰。

## 第 4 集 · 功能需求说明（8:59）
- 用「**功能点**」拆解需求：模块 → 功能点 → 优先级(P0/P1/P2) → 适用终端。
- 这是写详细交互前的「目录」，先让所有人**对齐范围**，再展开细节。
- 模板对应第五章：账号体系（一键登录 P0 / 验证码登录 P0）、风控（图形验证码 P1）。

## 第 5 集 · 常见交互类型（9:14）
- 建立「交互词汇表」：点击、输入、页面跳转、弹窗、Toast、下拉/选择、滑动、加载、空状态、刷新……
- 先能**准确命名**交互类型，后面才能无歧义地描述。
- 这一步是地基，别跳。

## 第 6–7 集 · 常见交互形式（共 12 分钟）
- 具体「形式」的写法举例：
  - **按钮态**：默认 / 悬停 / 点击 / 禁用(Disabled) / 加载中——每个状态都要写。
  - **输入框**：占位符、聚焦态、错误态（红框+提示）、字数限制。
  - **列表**：加载中 / 空数据(Empty) / 加载失败 / 分页。
  - **弹窗**：确认型 / 警告型 / 底部 Action Sheet。
  - **页面跳转**：带参跳转 / 不带参、是否可返回。
- 核心心法：**每个元素都要写「正常态 + 异常态」**。

## 第 8–10 集 · 交互说明撰写（公式，共 32 分钟）★重点
- 给出**撰写公式（四问法）**：触发 → 动作 → 反馈 → 异常/边界。详见 [[PRD-交互说明四问法]]。
  1. **触发**：谁、在什么页面/状态、做了什么前置操作？
  2. **动作**：具体交互动作（点/输/滑/选）。
  3. **反馈**：系统正常时给什么结果（跳转/弹窗/Toast/加载）。
  4. **异常**：失败、超时、空、重复提交、极值怎么处理。
- 第 10 集专讲「**异常怎么写进说明**」：失败提示文案、网络超时、空数据兜底、重复提交防抖、文本/数字极值。

## 第 11 集 · 交互说明撰写案例（17:44）
- 一个**完整功能**的交互说明范例，把前面词汇 + 形式 + 公式串起来，给你一个「标准答案」长什么样。

## 第 12–15 集 · 交互说明撰写演示（共约 2 小时）★重点中的重点
- 从 0 到 1 完整演示：功能清单 → 画流程图（[[PRD_Template]] 第四章）→ 逐条写交互说明。
- **演示场景正是「手机验证码登录」**，覆盖：
  - 手机号格式校验（11 位、号段规则）→ 非法 Toast「请输入正确的手机号码」。
  - 获取验证码 → 60s 倒计时、单日上限、防重复发送。
  - 输入 6 位验证码 → 校验通过 → 跳转首页。
  - 边界：断网、接口超时(>5s)、单日超限、重复点击 Disabled 防抖。
- 这与你模板 6.1 的例子**完全对应**，建议边读边把 6.1 照抄填满。

## 第 16 集 · 交互说明撰写总结（3:00）
- 方法论复盘：**四问法 + 异常必写 + 流程图先行**。
- 一句收尾：把「功能」写清楚 = 好 PRD 的一半；另一半（背景/用户/非功能/上线）见 [[PRD-模板章节与课程对照]]。

---

## 你只需记住的 3 件事
1. 写交互 = **触发 + 动作 + 反馈 + 异常**，四要素缺一不可（尤其「异常」最常被漏）。
2. 先画**流程图**（第四章），再写**交互说明**（第六章），二者一一对应。
3. 课程只深讲第五/六章；二/三/七/八章要另补，否则 PRD 不完整。
