## 六、 详细功能需求说明

### 6.1 功能模块：[模块名称/功能名称]

#### 6.1.1 界面原型与元素说明
* **原型展示**：（在此粘贴原型截图或说明原型对应页面名称）
* **页面元素列表**：
  | 元素名称 | 元素类型 | 数据来源 | 默认状态/文案 | 是否必填 |
  | :--- | :--- | :--- | :--- | :--- |
  | 手机号输入框 | Input | 用户输入 | 占位符：“请输入 11 位手机号码” | 是 |
  | 获取验证码按钮 | Button | 客户端交互 | 文案：“获取验证码”；点击后进入 60s 倒计时 | - |
  | 服务协议勾选框 | Checkbox | 客户端保存 | 默认未选中；带《用户协议》《隐私政策》超链接 | 是 |

#### 6.1.2 输入校验与规则限制（Rules & Validation）
* **手机号格式校验**：
  * 仅限 11 位数字，且符合国家手机号号段规则（以 `13/14/15/16/17/18/19` 开头）。
  * 若输入不符合规则，失去焦点或点击按钮时弹出 Toast 提示：“请输入正确的手机号码”。
* **验证码规则**：
  * 6 位纯数字，有效期 5 分钟。
  * 同一手机号 60 秒内仅允许发送 1 次。
  * 同一 IP / 手机号单日发送上限 10 次。

#### 6.1.3 极值与边界情况处理（Edge Cases）
* **文本极值**：用户名长达 50 个字符时，在顶部导航栏等展示位置是否折叠为 `...`？
* **网络异常**：请求发起时若断网，弹出 Toast 提示：“网络连接不稳定，请检查网络”。
* **数据为空**：若列表无数据，展示 Empty 缺省页及“重新加载”引导按钮。
* **重复提交**：提交按钮在点击瞬间设为 `Disabled`，防止重复点击触发多次 API 请求（防抖/节流）。

## 七、 非功能需求（Non-Functional Requirements）

### 7.1 性能需求（Performance）
* **响应时间**：API 接口平均响应时间 ≤ 200ms，99% 请求 ≤ 500ms。
* **并发处理**：核心登录接口需支持峰值 QPS ≥ 1000。

### 7.2 安全与合规需求（Security & Compliance）
* **敏感数据加密**：用户手机号、身份证号数据库加密存储（AES-256），前端展示脱敏处理（如：`138****1234`）。
* **传输安全**：所有 API 请求必须基于 HTTPS 协议，敏感操作增加签名（Sign）防篡改。
* **合规要求**：首次登录必须显式勾选《隐私政策》与《服务协议》，符合工信部合规要求。

### 7.3 兼容性与硬件要求（Compatibility）
* **App 移动端**：iOS 13.0 及以上，Android 8.0 及以上。
* **Web 浏览器**：Chrome ≥ 90、Safari ≥ 14、Edge 等主流浏览器。

### 7.4 数据埋点需求（Analytics & Tracking）
| 事件名称（Event Code） | 触发时机 | 上报参数（Properties） | 埋点目的 |
| :--- | :--- | :--- | :--- |
| `login_page_view` | 进入登录页时 | `source` (来源入口) | 统计登录页曝光量 |
| `send_code_click` | 点击获取验证码时 | `phone_valid` (手机号合法性: true/false) | 统计验证码发送率 |
| `login_success` | 登录成功后 | `method` (一键登录/验证码), `duration` (耗时) | 统计登录成功率与耗时 |

## 八、 上线策略与运营/运维支持

### 8.1 灰度发布策略（Gray Scale Rollout）
* 按照 **1% → 5% → 20% → 50% → 100%** 的比例逐步放量。
* 重点观察指标：接口错误率、Crash 率、客诉反馈。

### 8.2 运营与客服准备
* 客服团队需提前录入“登录异常/验证码收不到” FAQ 标准解答话术。
* 运营后台新增“验证码发送失败明细查询”与日志追踪工具。
