## 0. 先看结论：这门课到底教什么

这套 16 集的重心不是「PRD 全流程」，而是 **「功能 / 交互说明怎么写」**——也就是你模板里 **第六章「详细功能需求说明」** 的写法。

- **01–03 集**：建立认知（PRD 是什么、有哪几种常见形式）
- **04 集**：功能需求怎么描述（对应模板第五章功能清单 + 第六章）
- **05–16 集（共 12 集）**：**交互说明撰写专项**——交互类型、交互形式、撰写公式、案例与演示

> [!warning] 课程范围提醒
> 模板里 **一、五、六** 三章，本套课讲得最透；**二、三、七、八** 四章（背景、用户、非功能、上线）本套课基本不覆盖，需要你用别的资料补。下面每一节都标了「课程覆盖 / 需自补」。

### 一、文档基本信息（1.1 修订日志 / 1.2 人员 / 1.3 文档链接）
- **课程对应**：02–03 集（PRD 形式）。这一章是“元数据”，不考验产品能力，但体现专业度。
- **填写要点**：V1.0.0 起手就建修订日志；相关文档链接（原型/UI/接口/DB）尽早补，研发会频繁点。

### 二、需求背景与业务目标（⚠️ 课程不覆盖，需自补）
- 这是“为什么做”。对应 2.1 痛点、2.2 价值、2.3 KPI。
- **补法**：用「现状痛点 → 触发契机 → 目标价值 → 可量化 KPI」四句话模板；或看同系列前几部（需求分析/竞品）。

### 三、用户画像与使用场景（⚠️ 课程不覆盖，需自补）
- 对应 3.1 目标用户、3.2 使用场景。给研发/设计“为谁做”。

### 四、业务流程与逻辑图（建议补，课程隐含涉及）
- 模板里有「主流程图 + 状态迁移表」，是写第六章前必须先画的“地图”。
- 课程 05–07 的交互类型，本质就是帮你把流程图里的每一步拆细。

- 用表格把功能点列全，标 P0/P1/P2 优先级、适用终端。这是 PRD 的“目录”。

### 六、详细功能需求说明（课程核心，对应 04–16 集）← 重点

### 七、非功能需求（⚠️ 课程不覆盖，需自补）

## 3. 核心方法：交互说明怎么写（课程 05–16 精华提炼）

你模板 6.1 已经给了很好的骨架（元素列表 / 校验规则 / 边界情况）。课程教的是把每一条交互写成「研发拿到就能开发」的说明。套用下面公式：

> **交互说明 = 触发条件（谁、在什么状态） + 交互动作（点了/输了/滑了） + 系统反馈（跳转/弹窗/Toast/加载） + 异常与边界（失败/超时/空/重复）**

每条功能点，按这 4 问写：
1. **触发**：用户在什么页面、什么状态下操作？（如：未登录用户在登录页点击「获取验证码」）
2. **动作**：做了什么？（输入手机号 + 点击按钮）
3. **反馈**：系统正常时怎样？（校验通过→60s 倒计时；成功→跳转首页）
4. **异常**：失败/边界怎样？（手机号非法→Toast「请输入正确的手机号码」；断网→「网络连接不稳定」；重复点→按钮 Disabled 防抖）

把你模板 6.1.2（校验）、6.1.3（边界）的内容，全部用这个 4 问重排一遍，就是标准交互说明。

### 可直接复用的交互说明小模板（粘到每个功能模块下）
```markdown
#### [功能名] 交互说明
- 触发：<页面 + 状态 + 操作>
- 输入/前置：<需要的字段、权限、数据>
- 正常流程：<步骤1 → 步骤2 → 结果>
- 校验规则：<格式、范围、频率限制>
- 异常/边界：<失败提示、超时、空数据、重复提交、极值>
- 埋点：<对应第七章事件名>
```
