> **一句话心智模型**：AI 眼镜不是"小一号的手机"，而是把意图入口从「屏幕上的点击序列」搬到「身体上的语音+视觉流」——一旦没有屏幕可读、没有控件可点，GUI Agent 那套范式整体失效，OS 必须重新回答"意图从哪来、算力在哪跑、责任谁来兜"。

## 学习定位

**这篇解决什么**
- 建立可穿戴形态的**地图感**：从无显示音频眼镜到双目 MR 头显，各档位分别是什么、差在哪。
- 建立 2025–2026 的**玩家坐标系**：谁已经发货、谁只有传闻、市调数字怎么读。
- 建立**技术约束的直觉**：为什么"什么智能能上眼镜"是被功耗/重量/散热按死的，而不是被算法水平决定的。
- 把可穿戴挂回 Ethon 的主线：[[跨端与多设备意图流转]]、[[端侧 AI 基建与算力预算]]、[[端侧意图框架 学习笔记]]。

**这篇不解决什么**
- 不做光学方案推导（波导/LCoS/MicroLED 的物理原理不展开）。
- 不做单品测评与购买建议。
- 不做供应链/BOM 成本拆解（本文引用的成本占比数字均为二手，已标待核实）。
- 不预测谁会赢。硬件热点领域传闻密度极高，本文的编辑原则是：**官方参数与传闻分列，查不到就写"待核实"**。

## 一、为什么 OS PM 必须看"手机之外的意图入口"

库里已有的 [[工业级 GUI Agent 架构（VLM+无障碍树）]] 那一套，前提是**存在一块可被读取、可被点击的屏幕**。可穿戴形态直接抽掉了这个前提：

| 手机上的假设 | 在无屏/小屏形态下的状况 | 后果 |
|---|---|---|
| 有无障碍树可读 | 无 App、无控件树，只有摄像头帧与麦克风流 | 感知层从"结构化 UI"退化为"原始多模态"，依赖 VLM/MLLM（见 [[大模型四类型：LLM VLM MLLM LMM]]） |
| 可以模拟点击执行 | 无点击目标；执行必须回落到手机或云 | 眼镜天然是**意图采集端**，不是执行端 |
| 用户可视觉确认结果 | 单目 HUD 只有极小画幅，音频眼镜完全无视觉 | 确认机制被迫改造（见 [[Confirmation UI 分级与产品责任边界]]） |
| 交互是"用户主动打开 App" | 相机/麦克风常开，AI 先于用户发起 | Always-on 感知带来隐私红线与功耗红线 |
| 算力预算 = 手机 SoC | 眼镜 SoC 只有手机的零头，且被热约束 | 大部分推理必须 offload，跨端调度成为刚需 |

**核心判断**：眼镜改变的不是"AI 有多聪明"，而是**意图的采集方式与执行位置分离**。这正是 [[跨端与多设备意图流转]] 的问题在新形态上的重演，只是耦合更紧、延迟预算更苛刻。

## 二、形态谱系表

从"最轻/最傻"到"最重/最强"的连续谱。注意：**重量与智能几乎线性正相关**，这是全篇最重要的约束。

| 档位 | 典型形态 | 重量量级 | 显示 | 主输入 | 算力位置 | 代表产品（已发售） |
|---|---|---|---|---|---|---|
| L0 音频眼镜 | 无摄像头，开放式扬声器 | 约 27–30 g | 无 | 语音、触控条 | 手机 | 米家智能音频眼镜 2（27.6 g）、华为音频智能眼镜 2 |
| L1 拍摄+AI 眼镜 | 摄像头+麦阵+扬声器，无显示 | 约 38–50 g | 无 | 语音、按键、手势 | 眼镜轻量 + 云/手机 | 小米 AI 眼镜（40 g）、Rokid AI Glasses Style（38.5 g）、夸克 G1（约 40 g） |
| L2 单目 HUD 眼镜 | 单眼小画幅 + 摄像头 | 约 69 g | 单目 600×600、20° FOV | 语音 + sEMG 腕带 | 眼镜 + 手机 | Meta Ray-Ban Display（69 g） |
| L3 双目全彩 AR 眼镜 | 双目波导/MicroLED | 约 76–136 g | 双目全彩，30°–51° FOV | 语音、触控、手势 | 独立 SoC | 雷鸟 RayNeo X3 Pro（76 g）、夸克 S1、Snap Specs（132/136 g） |
| L4 有线 puck 的 XR 眼镜 | 眼镜 + 手机大小计算终端 | 眼镜本体轻，puck 外挂 | 双目 OLED，70° FOV | 手势、语音 | 外挂 puck | XREAL Project Aura（2026 内上市，待发货） |
| L5 双目 MR 头显 | 全遮蔽 + 透视 | 545 g + 302 g 电池 | 双目 micro-OLED 27MP，109° FOV | 眼动+手势+语音 | 独立 XR SoC | Samsung Galaxy XR、Apple Vision Pro |
| P 挂坠/胸针类 | 无显示，录音为主 | 数十克 | 无 | 按键/常开拾音 | 云 | Plaud NotePin 系列 |
| R 手表/戒指类 | 腕上/指上 | 数十克 / 数克 | 微型屏或无屏 | 触控、抬腕、生理信号 | 手表 SoC / 手机 | Wear OS 手表、各类智能戒指 |

**读表要点**：L0→L2 之间存在一条明显的"重量墙"——加一块显示，重量从 40 g 直接跳到 69 g。L3→L5 之间存在"续航墙"——独立算力上来后，续航跌到 2–4 小时。

## 四、技术约束表：什么智能能上眼镜，是被物理决定的

| 约束 | 现实量级 | 对"智能"的直接后果 |
|---|---|---|
| 重量 | 普通眼镜约 30 g；L1 约 40 g；加显示到 69 g；双目 AR 76–136 g | 鼻梁压强决定佩戴时长；>70 g 基本告别"全天佩戴" |
| 续航 | L1 约 8–12 h；L2 混用约 6 h；L3 混用 4 h；L5 约 2–2.5 h | 连续 VLM 推理是续航杀手，只能做"事件驱动"而非"帧帧理解" |
| 电池体积 | L1 电池仅 200–290 mAh 量级 | 与手机差两个数量级，端侧大模型常驻不可能 |
| 散热 | 无风扇、贴着太阳穴，热是体感问题不只是降频问题 | 峰值算力受"能持续多久"而非"峰值多高"限制 |
| 算力 | 骁龙 AR1 Gen 1 为主流平台（NPU 约 4 TOPS 量级）；AR1+ Gen 1 厂商称可跑十亿参数级小模型 | 端侧只够跑唤醒词、VAD、轻量视觉；复杂推理必须外送 |
| 芯片架构 | 主流为 SoC + 低功耗协处理器双芯（如骁龙 AR1 + 恒玄 BES2800） | 协处理器常驻守夜、SoC 按需唤醒——这是"待机 vs 智能"的工程解 |
| 连接 | Wi-Fi 6 / BT 5.x 为主；雷鸟等尝试 eSIM 独立联网 | tethered 省电但强依赖手机；standalone 自由但吃续航 |
| 显示 | 单目 600×600、20° FOV（Ray-Ban Display）到 51°（Snap Specs）、70°（Aura） | 画幅决定信息密度；20° 只能放"一眼看完"的卡片，放不下列表和表单 |
| 亮度 | 户外需要 4000–6000 nits 级 | 亮度直接吃功耗，与续航互搏 |
| 隐私硬件 | 录制指示灯、防遮挡检测、硬件麦克风/相机开关 | 属于**合规必选项**，不是加分项 |

### tethered vs standalone

| 维度 | Tethered（手机为算力中枢） | Standalone（眼镜独立） |
|---|---|---|
| 代表 | Meta Ray-Ban Display、Android XR 音频眼镜、XREAL Project Aura（puck） | 雷鸟 X3 Pro（eSIM 方向）、Snap Specs |
| 重量/续航 | 更轻、更久 | 更重、更短 |
| 延迟 | 多一跳无线链路，抖动风险 | 本地闭环更稳 |
| 生态 | 天然继承手机账号/支付/通知 | 需自建生态，冷启动极难 |
| 对 OS 的含义 | 眼镜是手机 OS 的**外设与传感器阵列** | 眼镜是**独立终端**，要有自己的 OS/商店/开发者 |
| 商业含义 | 手机厂占优，眼镜厂沦为配件 | 眼镜厂有机会，但要独自承担分发成本（见 [[意图框架的商业与生态博弈]]） |

**判断**：2026 年绝大多数出货集中在 tethered。standalone 更像是为下一代 AR 占位。

## 五、交互范式表

| 范式 | 机制 | 优点 | 硬伤 |
|---|---|---|---|
| 语音优先 | "Hey Meta" / "小爱同学" / Gemini Live 唤醒 | 无屏也能用；最低学习成本 | 公共场合社交成本高；嘈杂环境拾音难；长指令口播疲劳 |
| 视觉共情境 | 摄像头把"我在看什么"喂给 VLM | 意图可以省略指代（"这个多少钱"） | 隐私成本最高；帧率与功耗强绑定 |
| 抬头看 / HUD 瞥读 | 20° 画幅上放导航、字幕、消息 | 不打断当下 | 信息密度极低，只能做卡片级 |
| 凝视/眼动 | 头显与部分高配眼镜的眼动追踪 | 精准选择、可做隐式意图信号 | 成本与功耗高；眼动数据本身是敏感生物特征 |
| 手势 | 摄像头识别捏合、拖拽 | 直觉、无声 | 需抬手，公共场合尴尬；识别受光照影响 |
| sEMG 腕带 | Meta Neural Band 读取肌电，捏合/拇指滑动/腕部旋转；官方预告手写输入 | 极隐蔽、可无声输入、不用抬手 | 需额外佩戴一件设备；官方明确提示对植入式医疗设备用户有电磁风险 |
| 触控条 | 镜腿滑动/点按 | 可靠、零学习 | 表达带宽极窄，只能做音量/切歌级操作 |
| Always-on 感知 | 协处理器常驻，事件触发主芯片 | 让 AI 有机会"先开口" | 功耗与隐私双重红线；主动打扰的容错率极低 |

对交互模式的系统性归纳可对照 [[Agentic UX 交互设计模式 学习笔记]]。眼镜的特殊性在于：**它没有"撤销键"**——语音下达的动作往往在用户看到确认前就已执行。

## 八、对 OS PM 的意义

1. **意图入口会长在身体上，执行仍留在手机里**。这意味着意图框架必须支持"跨设备的意图接力"：眼镜采集 → 手机决策与执行 → 眼镜/手表回执。这是 [[跨端与多设备意图流转]] 的直接延伸，也是 OS 厂最不该外包的一层。

2. **算力预算表要新增一行"可穿戴"**。眼镜的电池是手机的 1/10 量级、散热窗口更窄。[[端侧 AI 基建与算力预算]] 中那套"什么模型跑在哪一档设备上"的分层，需要为可穿戴单列一档：端侧只做唤醒、VAD、轻量视觉门控，其余全部 offload。

3. **协处理器守夜是范式而非技巧**。"低功耗芯常驻感知 + 主 SoC 按需唤醒"这套双芯架构，本质上是把 Always-on 的功耗成本压到最低。OS 层面需要提供对应的**分层唤醒 API 与功耗预算契约**，否则每家厂商各自造轮子。

4. **确认机制必须重做**。无屏形态下没有"点确认再执行"的空间，语音确认又极易误触发。[[Confirmation UI 分级与产品责任边界]] 里的分级模型需要新增"仅音频确认"档，并明确哪些动作（支付、发送、删除）在眼镜端必须回落到手机确认。

5. **隐私从功能变成了准入条件**。指示灯、防遮挡、本地优先处理、数据人工审阅链路披露——这些在 2026 年已经是欧盟监管的靶心。做全球化产品的 OS PM 需要把"旁观者隐私"列入设计评审的固定项。

6. **形态竞争的真实战场是分发权**。国内玩家的打法（夸克接支付宝/高德/淘宝、小米接米家与小米汽车）说明：眼镜争的不是 OS，是**服务入口的默认位**。这与 [[意图框架的商业与生态博弈]] 的结论同构——谁定义默认助手，谁定义意图去哪。

7. **不要被"眼镜替代手机"的叙事带跑**。当前所有已发货产品，支付、定位、分发、账号全部依赖手机。眼镜在 5 年内更可能是"第二块屏 + 第一只眼"，而不是主机。
