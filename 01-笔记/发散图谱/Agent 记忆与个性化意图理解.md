# Agent 记忆与个性化意图理解

> 发散方向：意图理解要做到「懂你」，靠的是 Agent 的长期记忆与个性化。这是端侧 Agent 体验差异化的隐性战场，也是安卓 PM 值得提前布局的。
> 关联：[[App Infra 应用基建]](Local RAG 段) · [[工业级 GUI Agent 架构（VLM+无障碍树）]] · [[Intent Schema Protocol 意图模式规范]]。

## 1. 为什么记忆决定意图理解的上限
- 同一句话不同用户意图不同：「帮我订那家」——「那家」靠的是**用户历史记忆**（常去餐厅 / 上次聊的店）。
- 没有记忆的 Agent 只能靠当轮上下文硬猜，复杂意图必错。
- 记忆让意图从「通用理解」走向「个性化执行」。

## 2. 记忆的三层（产品视角）
- **短期**：当前对话 / 任务上下文（会话内）。
- **长期**：用户偏好、习惯、常去地点、常用 App、历史订单——跨会话留存。
- **情境**：实时状态（位置、在做什么、屏幕上下文）——见 [[工业级 GUI Agent 架构（VLM+无障碍树）]] 的 On-Screen Context。

## 3. 端侧 RAG：把记忆变成可检索上下文
- App Infra 引入**端侧向量数据库**（见 [[App Infra 应用基建]] 的 Local RAG 段），给 Agent 提供低延迟的本地语义检索。
- 例：用户说「上次看的酒店」，Agent 在本地检索历史浏览/收藏，而非每次问云端。
- PM 价值：隐私好（数据不出端）、延迟低（免联网）、个性化强。

## 4. 个性化意图理解的落地形态
- 主动预推：「复制了快递单号」→ 键盘上方弹「一键转存」；「在看小红书酒店」→ 唤醒时已带上下文。
- 歧义消解靠记忆：默认槽位（如默认支付方式、常去城市）从用户记忆取，减少追问。
- 习惯学习：高频意图自动沉淀为快捷入口 / 自动化（类快捷指令）。

## 5. 挑战（点到为止）
- 存储与一致性：记忆跨设备/跨 App 如何同步。
- 遗忘与可控：用户要能查看/删除记忆（隐私，不展开机制）。
- 漂移：记忆过时导致意图理解跑偏。

## 6. 对安卓 PM 的机会
- 把「用户记忆」作为系统级能力开放给 Agent（类似系统级 Intent Registry 的思路），而非每个 App 各存各的。
- 端侧 RAG + 个性化，是和竞品拉开体验差的高潜方向。

## 深化补充

### 一句话心智模型

> **记忆的产品价值，说到底就是"槽位默认值的来源"。它不让 Agent 更聪明，它让 Agent 少问几句。**

这个定义听起来降格了，但我觉得它比"让 Agent 懂你"有用得多，因为它**可度量**：

> 记忆系统的 KPI = **平均追问轮次的下降幅度**

「订那家店」→ 没记忆要问"哪家店"；有记忆直接填 `restaurant_id`。省了一轮。
「打车回家」→ 没记忆要问"回哪"；有记忆填 `home_address`。省了一轮。

**把记忆从一个玄学话题（"个性化体验"）落成一个可量化指标（追问轮次），我才知道该怎么给它排优先级、怎么验收。** 而且这个视角自动告诉我该先记什么——**先记那些最常被追问的槽位**，而不是漫无目的地存用户画像。

### 一个原文完全没提、但我认为最重要的风险：记忆是攻击面

原文第 5 节的挑战列了"存储一致性 / 遗忘可控 / 漂移"，全是**功能性**问题。但把记忆和库里的安全笔记一联，我意识到少了一个量级更大的风险：

> **记忆是唯一一个"攻击者写入一次、长期生效"的组件。**

普通的 XPIA（见 [[XPIA 跨提示注入]]）是**一次性**的——恶意指令混进这一轮上下文，这轮结束就没了。但如果恶意内容被**写进长期记忆**：

1. 攻击者让 Agent 读了一篇带隐藏指令的网页/邮件
2. Agent 把"用户偏好使用 xxx 支付方式"错误地沉淀进长期记忆
3. **此后每一次**支付类意图，这个被污染的默认槽位都会被取出来用
4. 用户完全无感，因为它表现得就像"Agent 记住了我的偏好"

**从一次性注入升级为持久化后门。** 这跟 [[文档型 XPIA 自传播蠕虫]] 是同一类思路的不同载体。

对应的缓解，库里其实已经有现成答案了——[[数据溯源分级与单调棘轮]]：**给每条记忆打来源标签**（`user_input` / `tool_output` / `file` / `api_response`），并规定：

- 只有 `user_input` 来源的记忆能作为**高风险动作的默认值**；
- `tool_output` / `file` 来源的记忆只能用于**低风险场景或提示**，且不可升级（单调棘轮：只降不升）。

**这条我认为应该直接写进任何记忆系统的设计原则第一条。** 成本很低（就是加个字段），价值很高。

### 三层记忆再补一个维度：可信度

原文的三层（短期/长期/情境）是按**时间尺度**分的。我想再叠一个正交维度——**来源可信度**：

| | 用户明说的 | 系统观察到的 | 外部内容带进来的 |
|---|---|---|---|
| **短期** | "订那家川菜" | 当前在淘宝页面 | 网页里的一段文字 |
| **长期** | "我不吃辣" | 常在周五点外卖 | ⚠️ **这一格应该为空** |
| **情境** | — | GPS 在公司 | 通知栏里的第三方内容 |

**右下角那一格是关键：外部内容永远不应该沉淀为长期记忆。** 这是一条很干净的设计红线，画出来之后实现起来也简单。

而中间列（系统观察）也有个问题：**观察到的是行为，不是意愿。** "常在周五点外卖" ≠ "喜欢周五点外卖"，可能只是周五加班。**把相关性当因果，是个性化系统最常见的翻车方式**（推荐系统踩了十年的坑，Agent 不该再踩一遍）。

### 具体例子：记忆漂移是怎么伤人的

原文提了"漂移"两个字，我把它想具体：

用户三个月前搬了家。系统里 `home_address` 还是旧地址，因为：
- 用户没有主动说"我搬家了"（没人会对手机汇报这个）
- 系统观察到的打车终点变了，但**不敢自动改**（怕误判）

于是每次说"打车回家"，都填错地址。用户改了三次之后，**再也不用这个功能了**。

**这个例子让我看到记忆系统真正难的地方不是"记住"，是"知道什么时候该忘"。** 而且可以推出一条设计原则：

> **记忆的更新策略应该和它的风险等级挂钩：低风险槽位（音乐偏好）可以静默自动更新；高风险槽位（地址、支付方式）的变更必须走一次显式确认。**

这跟 [[Confirmation UI 安全机制]] 里的分层确认是同构的——**只不过确认的对象从"动作"变成了"记忆的写入"**。这个类比我觉得挺漂亮，值得单独展开。

### 待解问题

- [ ] 记忆的**来源分级**要不要做成系统级能力（像权限那样），还是让每个 Agent 自己管？如果自己管，那"系统级记忆开放给 Agent"（原文第 6 节的机会）就等于**把污染风险也一起开放了**。
- [ ] "记忆的 KPI = 追问轮次下降"——这个指标会不会被**过度优化**？为了少问一句而猜错，比多问一句更伤。是不是要配一个"错误默认值导致的撤销率"做反向约束？
- [ ] 用户要能"查看/删除记忆"，但**记忆是向量**，用户看不懂。怎么把向量记忆呈现成人类可读、可逐条删除的形态？这是个**产品难题不是技术难题**，而且我还没见过好的解法。
- [ ] 系统级记忆一旦成为差异化能力，**换手机时能不能迁移**？不能迁移 = 用户锁定（对厂商有利），能迁移 = 用户友好。这个取舍厂商会怎么选，我心里有数，但该不该这么选是另一回事。
