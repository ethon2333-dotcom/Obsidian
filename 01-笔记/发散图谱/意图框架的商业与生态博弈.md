# 意图框架的商业与生态博弈

> 发散方向：在国内安卓生态推「意图框架」，技术不是难点，**商业与生态博弈才是最大变量**。作为安卓 PM，这一层决定你的框架能不能真正落地。
> 技术底 / 阻力分析：[[国内安卓厂商做 App Intent 的阻力]] · [[安卓厂商意图识别破局策略]]。

## 1. 核心矛盾：厂商想收权 ↔ 超级 App 不给接口
- 微信/支付宝/美团/抖音/小红书 已是「操作系统之上的操作系统」，极度抗拒被「管道化、去界面化」。
- 开放深度 Intent = 让出流量入口、广告曝光、转化归因 → 大厂没有动力。

## 2. 流量入口重分配（厂商的杠杆）
- 系统级入口——负一屏、全局搜索、桌面卡片、锁屏——**优先倾斜给主动适配系统 Intent Schema 的 App**。
- 例：携程适配了意图，用户搜机票直接出极速卡片一键下单；未适配的只能以普通图标呈现。
- 用流量杠杆「逆向逼迫」竞品跟进适配。

## 3. 利益共享：只导流不闭环
- 在下单 / 付款 / 选座等核心转化节点，Agent **自动填参 + 跳 App 原生界面让用户最后点**。
- 保住 App 的 DAU、GMV、支付链、转化归因 → 消除大厂「流量被截胡」的戒心。
- 这是「破局」而非「对抗」：用商业留出空间换接口开放。

## 4. 联盟标准：把适配成本打下来
- 安卓群雄割据（小米/OPPO/vivo/荣耀各一套），开发者适配成本极高、收益不确定。
- 路径：信通院 / 行业协会牵头，重走「统一推送联盟 / 快应用」路线，定义**统一 Android Intent Schema**。
- 一套声明文件被所有主流厂商识别 → 开发者适配成本降 80%+，是生态爆发前提。
- 对 PM：推动联盟比单打独斗更划算，也是你能在厂商层面推动的杠杆。

## 5. 变现与服务分发机会
- 意图入口本身就是新的服务分发/广告位（主动预推卡片）。
- 但需平衡：过度商业化会伤体验、逼用户关权限 → 回归「体验破局」逻辑。

## 6. 安卓 PM 的可行动策略（五维）
- **技术**：L1 原生 / L2 深层协议 / L3 GUI Agent 渐进降级（见 [[GUI Agent vs 原生 API 产品决策树]]）。
- **体验**：把 GUI Agent 做成工业级（无障碍树 + 端侧 VLM）。
- **商业**：导流不闭环 + 流量倾斜。
- **生态**：推统一联盟标准。
- **感知**：系统级前置感知（剪贴板 / 屏幕 OCR / 通知）主动生成「下一步」。

## 深化补充

### 一句话心智模型

> **意图框架不是一次技术升级，是一次渠道革命。技术上它是"让 App 声明能力"，商业上它是"把货架从应用商店搬到系统层"——所以抵抗它的从来不是工程团队，是增长团队。**

想通这一层，很多现象就不需要额外解释了：
- 为什么技术方案都很成熟了，接入率还是上不去？—— 因为**决策权不在技术侧**。
- 为什么小 App 比大 App 积极？—— 因为小 App 本来就没有流量，白捡的入口；大 App 是拿存量流量去换不确定的增量。
- 为什么厂商要用"系统入口倾斜"当筹码？—— 因为这是**唯一能对等交易的货币**。

**推论：任何只谈技术接入成本的推进方案都会失败。** 我去和一个头部 App 谈接入，对方真正想听的是"我能多拿多少订单"，不是"你只要写 200 行 KDoc"。

### 一个实证：鸿蒙的接入率现状

竞品那边已经跑出了可观测的样本（见 [[HarmonyOS 意图框架竞品观察]]）：

- 银行、票务、O2O 这类**转化路径长、获客成本高**的类目 → 积极接（端/云 A2A 都上）
- **微信 → 「尚未接入」**

这个分布不是随机的。我总结出一条判断规则：

> **一个 App 接不接意图框架，取决于它把"用户注意力"当资产还是当成本。**
> - 把注意力当**成本**的（银行：用户不想打开我，能一句话办完最好）→ **积极接**
> - 把注意力当**资产**的（微信、抖音：用户停留时长就是我的收入）→ **坚决不接**

而且鸿蒙的处境比安卓好得多——它有单一厂商的统治力、有装机量做筹码，尚且拿微信没办法。**国内安卓群雄割据，单个厂商的筹码只有鸿蒙的几分之一。** 这个对照让我对"靠流量倾斜逼迫大厂"这条路的效力打了个折扣：它对中腰部有效，对头部大概率无效。

### 联盟标准这条路，其实已经有现成骨架了

原文第 4 节说"推动统一 Intent Schema 联盟"，我之前觉得这是个从零开始的事。但库里 [[智能体互联国家标准与 AIP]] 显示，**骨架已经有人搭了**：

《人工智能智能体互联》系列 7 项国家标准，五段式覆盖 **身份标识 → 能力描述 → 供需发现 → 协同交互 → 工具调用**。

这对我的直接价值是：**不用自己发明分层，直接借国标的坐标轴做自检和对外沟通。** 而且里面有一条洞察我认为特别关键——

> **五段里只有「能力描述」是必须跨厂商统一的，其余四段可以各家私有实现。**

这大幅降低了联盟的谈判难度。我不需要说服小米/OPPO/vivo/荣耀用同一套 Registry 和同一套调度引擎（那不可能，各家都想保住自己的差异化），我只需要说服他们**认同一份"能力声明格式"**。开发者写一次，四家都能读。**这才是能谈成的联盟版本。**

⚠️ 注意：国标的标准号、全文与实际采纳率在库里标注为**待补/未核验**，对外引用前必须查原文。

### 补一条原文没有的博弈：合规正在变成第三方筹码

原文的博弈是**双边**的（厂商 vs 超级 App）。但 2026 之后是**三边**——监管入场了：

- 国内：网信办/发改委/工信部《智能体规范应用与创新发展实施意见》要求"降低智能体研发、适配、应用门槛"；电子标准院下一步补**审计、交易**标准。
- 欧盟：EU AI Act Article 15 / Article 10 已于 2026-08-02 生效（见 [[Windows Copilot Actions 竞品观察]]）。

**对我的意义**：当"Agent 行为可审计"从产品特性变成合规要求，厂商就多了一个之前没有的说服角度——**"你不接系统的官方通道，那我只能走 GUI Agent 去操作你的界面，那部分行为的合规责任归谁？"** 这句话的分量，比"我给你流量"重得多。这条我觉得是当前最被低估的杠杆。

### 待解问题

- [ ] "导流不闭环"（最后一步跳回 App）能撑多久？一旦用户习惯了"一句话办完"，**中途跳 App 就是体验断点**。这个妥协方案有没有内在的保质期？到期后怎么办？
- [ ] 如果头部 App 永远不接，安卓靠 GUI Agent 兜底——**超级 App 会不会主动做反 GUI-Agent 对抗**（动态布局、行为检测、验证码）？如果会，那"技术兜底"这条退路根本不存在，博弈就变成纯商业问题了。**这是我判断整条路线成败的关键假设，得找证据。**
- [ ] 意图入口的**分成机制**该怎么设计？应用商店有 30% 的成熟模型，意图分发有没有对应物？没有钱路的生态推不动——**但如果收费，是不是又变成第二个应用商店，重蹈覆辙？**
