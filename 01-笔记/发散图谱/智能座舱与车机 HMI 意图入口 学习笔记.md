# 智能座舱与车机 HMI 意图入口 学习笔记

> **学习定位**：把「车机」补进意图入口形态谱系——它是继手机、[[AI 眼镜与可穿戴意图入口 学习笔记|AI 眼镜/可穿戴]]之后**第三个有独立 OS、独立算力、独立账号体系**的一等意图入口，且是唯一带「安全强约束 + 长时段封闭空间 + 高确定性场景」三重特征的入口。
>
> **心智模型**：**车机意图入口 = 「语音优先的单一主入口」× 「舱驾一体带来的富上下文」× 「端云分工被物理条件（隧道/弱网）强制切分」——手机上是「多入口竞争注意力」，车上是「单入口独占注意力但不能占用视线」。**

关联锚点：[[发散图谱 MOC]] · [[跨端与多设备意图流转]] · [[端侧意图框架 学习笔记]] · [[意图框架·跨体系索引 MOC]]

## 一、车机 HMI 意图入口形态谱系表

| 形态 | 交互通道 | 意图表达方式 | 端侧依赖 | 典型落地（2025–2026） | 成熟度 |
|---|---|---|---|---|---|
| **语音主交互（唤醒词）** | 麦克风阵列 + ASR + NLU | 显式指令 → 槽位填充 | 端侧 ASR 可离线 | 全行业标配 | 已普及 |
| **语音免唤醒 / 连续对话** | 常开拾音 + 端侧 VAD | 免前缀直说，多轮不重唤醒 | 端侧 ASR+NLU 上 NPU 推理 | 华为「小艺免唤醒」（端侧 ASR+端侧 NLU 方案，官方口径经媒体转述） | 量产中 |
| **多音区 / 声源定位** | 4–6 音区波束成形 | 「谁说的听谁的」 | 端侧信号处理 | 鸿蒙座舱四音区、多数新势力 | 已普及 |
| **可见即可说** | 语音 × 屏幕语义树 | 指令直达二级菜单 | 端侧 UI 语义索引 | 鸿蒙座舱、多数国产车机 | 已普及 |
| **多模态指代（视线/手势+语音）** | 摄像头 + 3D Gaze + 手势 | 「那家店」+ 指向 | 端侧视觉 | 商汤绝影 3D Gaze/手势方案；奔驰 CLA「语音+手势」试点（**待核实**） | 试点/早期量产 |
| **舱内感知主动触发** | RGB+红外摄像头、雷达、座椅传感 | 系统推测意图（无用户输入） | 端侧持续感知 | DMS 疲劳/情绪识别、鸿蒙座舱 AMS 多模态感知（**参数待核实**） | 量产中 |
| **屏幕触控 / 物理按键** | 中控屏、副驾屏、方向盘键 | 直接操作，非「意图」 | 无 | 全行业 | 成熟但正被语音替代 |
| **HUD / AR-HUD 输出侧** | 抬头显示 | 意图执行结果的低视线成本回显 | 端侧渲染 | HUD 盲区影像等（2025 多款新车） | 量产中 |
| **手机投屏（Projection）** | 手机算力 + 车屏 | 手机意图框架借用车屏 | 依赖手机端侧 | Android Auto（Google 称支持 2.5 亿辆车）、CarPlay、HiCar、ICCOA Carlink | 已普及 |
| **深度融合投屏** | 手机接管仪表盘 | 手机 OS 渗透进车辆域 | 依赖手机 | **CarPlay Ultra**（2025-05 阿斯顿·马丁首发，Apple 官方） | 早期 |
| **Agent 化任务执行** | 语音 → Agent → 跨 App/跨端 | 模糊意图 → 自主规划 → 调工具 | 端云协同 | 理想「生活助手 Agent」联动支付宝车载；斑马平台级 Agent 集群；阿里 Mobile-Agent 在比亚迪车机做视觉 GUI 操作 | 2025 起爆发 |

**关键判断**：车机的意图入口谱系正在从「通道叠加」（多加一块屏、多加一个麦）转向「**通道收敛到语音 + 上下文来源扩张到全车传感器**」。这与手机端的演进方向（[[端侧意图框架 学习笔记]] 中的「入口收敛、上下文扩张」）高度同构。

## 四、与手机端侧意图框架的同源技术对照表

> 这是本篇对 Ethon 最直接的价值：判断哪些手机侧能力可以平移、哪些必须重做。详见 [[跨端与多设备意图流转]]。

| 技术维度 | 手机端侧意图框架 | 车机意图框架 | 同源度 | 差异根因 |
|---|---|---|---|---|
| **意图识别（NLU）** | 端侧小模型 + 云端大模型分级 | 完全同构：端侧 1–7B 兜底，云端复杂推理 | ★★★★★ | 无本质差异，可直接复用模型与蒸馏管线 |
| **端侧 ASR / 唤醒** | 低功耗常听 + DSP/NPU | 同构，但需**多音区 + 声源定位 + 高噪声鲁棒**（胎噪/风噪/多乘客） | ★★★★☆ | 声学环境远劣于手机 |
| **意图 → 能力的注册与调度** | App Intents / 意图注册表 / 语义树 | 「可见即可说」= UI 语义树；Agent 平台接入第三方服务（如鸿蒙座舱 AI Agent 平台接 80+ 服务，⚠️） | ★★★★☆ | 车上 App 生态薄，需靠 GUI Agent 补（阿里 Mobile-Agent 路线） |
| **视觉 GUI Agent 兜底** | 手机上作为「无 Intent 时的降级方案」 | 车机上因生态更薄，反而**更早成为主路径** | ★★★★☆ | 车机 App 数量少、改造意愿低 |
| **上下文（Context）来源** | 屏幕内容、位置、日程、通知 | 上下文远更富：车速/电量/挡位/DMS 情绪/座舱温度/舱外摄像头/导航目的地 | ★★☆☆☆ | 车是「传感器最密集的个人终端」，意图先验强得多 |
| **主动服务 / 意图预测** | 通知/建议卡片，用户可忽略 | 主动性收益更高（长时段、目的明确的通勤），但打扰成本也更高（安全） | ★★★☆☆ | 场景确定性高 ⇒ 预测准确率天然更高 |
| **多用户身份** | 单用户设备 | **天然多用户**：面容/声纹切档案（理想）、多音区分权（后排不能关前排窗） | ★☆☆☆☆ | 车是共享设备，权限模型必须重做 |
| **端云分工的驱动力** | 隐私 + 成本 + 延迟 | 隐私 + 成本 + 延迟 + **物理断网（隧道/地库）+ 功能安全** | ★★★☆☆ | 车上「离线可用」是不可协商的底线 |
| **跨设备流转** | 手机 ↔ 平板/PC/穿戴 | 手机 ↔ 车 ↔ 家（华为、小米、Google 三家都在做同账号打通） | ★★★★★ | 完全同一个问题域 |
| **算力约束** | SoC NPU，功耗/热受限严苛 | 算力上限高得多（座舱芯片 30→320 TOPS 级），但**必须与智驾抢算力**（舱驾一体的 ACE 动态调度） | ★★☆☆☆ | 车上是「算力仲裁」问题，手机是「算力不足」问题 |
| **安全 / 合规** | 隐私合规为主 | 隐私 + **功能安全 ASIL-D + 驾驶分心法规**（NHTSA 分心致死数据被引为质疑 Gemini Live 的依据） | ★☆☆☆☆ | 车机独有的强约束，直接决定交互形态 |

## 五、对 OS PM 的启示

1. **「入口收敛」在车上先一步验证。** 手机上「多入口竞争」还在拉锯，车上因为不能占用视线，语音早已是事实上的单一主入口。车机是观察「当语音成为唯一入口时，意图框架会长成什么样」的**先行实验场**——包括可打断性、错误恢复、免唤醒的误触发权衡，这些手机端会晚 1–2 年遇到。

2. **端侧不是省钱，是「不可协商的可用性底线」。** 手机上端侧的理由主要是隐私和成本；车上多了一个「隧道里必须能用」。这给 [[端侧意图框架 学习笔记]] 里的端云路由策略提供了更强的论证素材：**端侧应按「断网可用性」而非「成本」来划定必须本地化的能力边界**。

3. **算力仲裁 > 算力堆料。** 舱驾一体的关键不是 TOPS 数字，而是地平线 ACE 这类「静止时算力给座舱、行驶时保智驾」的动态调度，以及「城堡」式物理隔离。手机 OS 上同理：意图框架与相机/游戏抢 NPU 时，**谁来仲裁、SLA 怎么定**，是比模型选型更早需要的架构决策。

4. **生态薄 ⇒ GUI Agent 提前上位。** 车机 App 生态远薄于手机，导致视觉 GUI Agent（阿里 Mobile-Agent 路线）在车上从「降级兜底」变成「主路径」。反推手机：**长尾 App 永远不会全部接 Intent，GUI Agent 必须是一等公民而非兜底。**

5. **多用户权限模型必须前置设计。** 车天然是共享设备（多音区 + 声纹切档案 + 后排不能操作前排）。手机正在往「家庭共享/多 Profile」演进，车机的权限模型是可直接借鉴的成熟样本。

6. **主权之争的形态值得警惕。** CarPlay Ultra 把手机 OS 推进到仪表盘、Gemini 取代车企自研语音——这是「通用 OS 厂商用意图入口反向收编垂直硬件」的标准剧本。作为 Android OS PM，需要判断：**车企愿意交出的是「显示面」还是「意图裁决权」**，两者的让渡边界完全不同。

7. **上下文富裕度是意图准确率的杠杆。** 车机能拿到车速/挡位/DMS 情绪/导航目的地，先验强到「我有点冷」可直接映射到空调+座椅加热。手机侧的启示是：**扩大可信上下文源的收益，可能大于换更大的模型。**
