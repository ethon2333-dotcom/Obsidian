> **心智模型一句话**：给 AI 生成内容打上「不可见指纹（水印）」+ 记录「出生证明（C2PA Content Credentials）」，让真假可溯源、可监管——区别于 [[端侧模型安全与越狱 学习笔记]]（模型被攻击）与 [[AI 监管与合规落地 学习笔记]]（监管框架），本文聚焦**生成内容"可溯源/可标识"技术侧**。

# 模型水印与内容溯源（学习笔记）

## 一、广度覆盖

### 1.1 三类概念对比（水印 vs 溯源 vs 检测）

| 维度 | 数字水印 Watermarking | 内容溯源 Provenance（C2PA） | 合成检测 Detection |
|---|---|---|---|
| 核心机制 | 把**不可见、可检测的信号嵌进内容本身**（像素/频谱/词元分布） | **内容之外的加密签名声明**（manifest + X.509 证书 + 哈希绑定） | 事后**分类器**推断内容是否 AI 生成 |
| 抗"剥离元数据" | 强（信号在内容里，截图/重压缩仍可留痕） | 弱（元数据易被平台重编码剥离，需 soft binding 补救） | 不参与生成，纯被动识别 |
| 抗"强力变形/对抗" | 弱（定向对抗噪声/改写可抹除） | 强（变形不破坏签名，但无签名=不可验证） | 弱（模型越新检测器越失效，如 Gemini 2.5 Pro 视频检测仅约 56-67%） |
| 谁控制 | 生成方（水印由生成器写入） | 生成/编辑方（签名由工具写入） | 任何第三方 |
| 典型代表 | SynthID、Stable Signature、AudioSeal | C2PA / Content Credentials | Reality Defender、Truepic、Azure Content Integrity |
| 一句话 | "这是不是我的模型造的" | "这份内容的出生与改历" | "这是不是真的" |

> 结论：三者**互补不替代**。可溯源故事要"水印 + 加密溯源"双层才站得住（见 [[AI 监管与合规落地 学习笔记]] 的监管合规诉求）。

### 1.2 主流水印技术方案横向表

| 方案 | 出品方 | 覆盖模态 | 技术要点 | 鲁棒性 / 局限 |
|---|---|---|---|---|
| **SynthID** | Google DeepMind | 文本 / 图像 / 视频（Veo）/ 音频（Lyria） | 图像在生成期改像素分布；文本改词元采样概率（已开源到 Hugging Face Transformers） | 抗裁剪/压缩/截图；对抗改写/定向攻击可削弱；**只能识别 Google 系内容** |
| **Stable Signature** | Meta（与 INRIA） | 图像（解码器微调）+ AudioSeal（音频） | 微调扩散解码器，每图固定比特串；已开源、发布解码权重 | 误报率号称极低（约 1/100 亿）；Stanford 2025 论文称定向攻击可移除 94% 测试图 |
| **C2PA 隐式标识** | Adobe / Microsoft / OpenAI / Google / Meta 等 | 图像 / 视频 / 音频 / 文档 | 加密签名 manifest 嵌元数据，含生成工具/模型/编辑链 | 元数据易被平台重编码剥离；soft binding（云端 manifest 库）补救 |
| **AudioSeal** | Meta | 音频 | 音频水印 | 模拟重录可破坏信号 |
| 中国隐式标识（数字水印） | — | 依《标识办法》鼓励 | 文件元数据 + 数字水印双重隐式标识 | 合规执行力度待核实 |

### 1.3 2025-2026 进展（点到为止，媒体口径，标待核实）

- **C2PA / Content Credentials**：规范版本号说法不一——有来源称已到 **2.0（2024）/ 2.1（2025）**，用户提到的「1.4」可能为某子规范，**待核实**。联盟成员规模有来源称 2026-01 超 6000、另有称 2025-12 超 200 家，**数字待核实**。ISO 推进为 ISO/CD 22144。
- **Adobe Content Authenticity Initiative**：Photoshop / Lightroom / Firefly 全系默认写 C2PA；2025 与 Digimarc 合作做"持久可互操作凭证"。
- **SynthID**：Google 称截至 2025-05 已水印超 100 亿、另有来源称 2025-11 超 200 亿条内容，**数字待核实**；2025-11 起 Gemini App 内置验证；**OpenAI 于 2026-05 起在 ChatGPT/DALL·E/Codex 输出加 SynthID**——此合作源自二手媒体，**待核实**。
- **EU AI Act**：第 50 条透明度义务（机器可读标识合成内容），有来源称 **2026-08-02 生效**，**具体日期待核实**；法案并不强制水印，C2PA/明文标签均可满足。
- **NIST**：AI 100-4 内容认证指南（有来源称 2025-01 落地），**待核实**；AIRMF 将水印列为溯源手段之一，但未强制。
- **端侧/on-device**：Qualcomm 2025-10 公布移动硅路线含硬件信任根做图像真实性；arxiv 2504.13205 论证"端侧水印是社会技术刚需"；DM-MARK（NWU，12nm）做扩散模型水印硬件加速，称 18× 延迟加速。

### 1.4 代表产品与组织

| 主体 | 角色 | 做什么 |
|---|---|---|
| **C2PA** | 开放标准联盟（Linux Foundation JDF，2021 由 Adobe CAI + MS/ BBC Project Origin 合并） | manifest + 签名 + provenance 链；创始 Adobe/Microsoft/Intel/ARM/Truepic，Google 2024 入指导委 |
| **SynthID** | Google DeepMind | 多模态不可见水印 + Detector 门户 |
| **Truepic** | 真实性平台 | C2PA Content Credentials + 防篡改核验（捕获即签名） |
| **Microsoft Azure Content Integrity / Video Authenticator** | 云/生产力套件 | Azure AI 合成媒体检测 + C2PA 签名，已扩展到 Teams/Copilot |
| **Reality Defender** | 纯检测厂商 | 多模态（图/视频/音频/文本）深度伪造检测，2025-12 获 Gartner 认可 |
| **Indelible** | 水印/溯源 | 内容标识（媒体口径较少，能力待核实） |
| **Adobe / OpenAI / Meta / Google / 索尼 / 莱卡 / 三星** | 采用方 | 生成侧默认写 C2PA / 水印 |

## 三、留给 Ethon 深补的待解问题

- [ ] **水印鲁棒性 vs 对抗抹除**：定向对抗噪声（如移除 Stable Signature 94% 图的攻击）如何遏制？是否只能靠"水印+C2PA"双层？
- [ ] **C2PA 链上隐私**：硬件签名密钥用"每设备唯一密钥"还是"共享密钥"？唯一密钥暴露 PII、共享密钥一旦泄漏连累海量内容，权衡如何落地？
- [ ] **端侧水印性能开销**：on-device 小模型实时水印的算力/延迟成本（如 DM-MARK 硬件加速思路）能否下沉到手机 NPU？
- [ ] **文本水印的"读而不能删"难题**：文本无物理传感器锚定，改写即破；能否靠 USENIX'25 的 20-bit 负载（userID/时间戳/模型ID）做真正 provenance 载荷？
- [ ] **监管生效与采用率**：EU AI Act 第 50 条确切生效日、中国《标识办法》各平台执行率、SynthID 跨厂商采用率——均待一手核实。
