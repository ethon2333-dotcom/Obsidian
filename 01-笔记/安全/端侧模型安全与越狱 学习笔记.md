端侧模型安全与越狱，本质是「把没有实时云端安全网关兜底的小模型直接放到用户设备上跑」后，模型本身（而非管道或数据）被提示注入、越狱、提取、投毒所攻破的风险面；它的特殊性在于：攻击者离模型更近，而防御者离补丁更远。

## 一、攻击面（BREADTH，点到为止）

| 攻击类型 | 一句话定义 | 端侧为何更危险 |
|---|---|---|
| Prompt Injection 提示注入 | 把恶意指令藏进模型读取的文档/网页/UI 文本，被动触发 | 端侧 Agent 常读本地文件/屏幕，注入面大且难统一过滤 |
| Jailbreak 越狱 | 绕过安全对齐，让模型输出本应拒绝的内容 | 小模型对齐弱、无云端二次拦截，越狱成功率普遍更高 |
| 训练数据投毒 | 在训练/微调语料中埋入后门或偏见 | 端侧常跑厂商/第三方微调小模型，供应链难审计 |
| Model Extraction 模型提取 | 通过大量查询反推模型权重或能力边界 | 本地模型文件可被逆向提取，IP 与能力直接泄露 |
| 对抗样本 | 对输入做微小扰动使模型误判 | 端侧多模态（视觉/语音）输入通道多，扰动更易落地 |

## 二、端侧 vs 云端的特殊性

| 维度 | 云端模型 | 端侧模型 |
|---|---|---|
| 安全网关 | 实时云端护栏/过滤，可热更新 | 无实时云端兜底，离线运行 |
| 补丁速度 | 服务端秒级热更新 | 设备端无法快速热更新，依赖系统 OTA |
| 数据隐私 | 数据上传，集中管控 | 本地推理，但模型文件可被本地提取 |
| 攻击距离 | 攻击者远，有 API 限流/审计 | 攻击者近（本机/本地应用），可直接调模型 |
| 模型规模 | 大模型对齐强 | 小模型（如 ~3B）对齐薄，越狱基线高 |

## 三、防御手段

| 手段 | 做法 | 局限 |
|---|---|---|
| 输入/输出过滤 | 扫描 prompt 与 response 的有害内容 | 可被 Unicode/编码混淆绕过（见下方待核实） |
| 对齐 fine-tuning | 在微调阶段注入安全样本 | 小模型容量有限，易被 jailbreak 覆盖 |
| 系统提示加固 | "safety sandwich"：系统策略 + 用户消息标记不可信文本 | 对强对齐模型有效，对小模型有限 |
| 沙箱化工具调用 | 把危险操作隔离在受控环境 | 见 [[工具调用安全 学习笔记]] |
| On-device Guardrail | 本地轻量护栏模型（如 Llama Guard 类）实时判别 | 增加延迟与算力开销 |
| 与意图框架配合 | 高风险动作走 Confirmation UI 二次确认 | 见 [[端侧意图框架 学习笔记]]、[[Confirmation UI 分级与产品责任边界]] |

## 对 OS PM 的意义

Ethon 做 Android OS，端侧 Agent/意图框架上线后，模型不再只是「功能」，而是「可被攻击的本地实体」：

- 端侧小模型对齐弱于云端，**默认不能假设它安全**；上线前需本地红队扫描（见 [[端侧大模型推理 学习笔记]] 的部署上下文）。
- 离线 + 无热更新 = **补丁窗口长**，安全设计要前置到模型选型与系统提示，而非靠服务端兜底。
- 与 [[Agent 执行安全（PM视角）]] 和 [[工具调用安全 学习笔记]] 联动：模型被越狱后，真正的危害在「它能调用的工具」，护栏要和 Confirmation UI 分级绑定。
- 监管口径（EU AI Act）影响**责任边界**——作为系统整合方可能成为 GPAI 下游 provider，需保留训练数据摘要与透明度义务。
