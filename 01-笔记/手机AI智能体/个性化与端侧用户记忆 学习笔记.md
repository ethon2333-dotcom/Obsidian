> 心智模型一句话：**端侧个性化 = 把"用户模型"装进手机本地，越用越懂你，且数据不出设备。** 它解决的是"手机如何在本地把用户建出来、用起来，而不把原始数据传云"。

---

## 1. 定义与分类

| 维度 | 说明 |
| --- | --- |
| **On-device personalization（端侧个性化）** | 在设备本地学习并维护用户模型（画像/偏好/习惯），推理与更新均在端侧完成。原始数据不离机。 |
| **Cloud personalization（云端个性化）** | 用户数据上传云端，由服务器统一训练/推理后下发结果。能力更强但涉及数据出境与隐私。 |
| **个性化 vs 记忆系统（关键区分）** | **个性化**建模"用户是谁"（偏好、习惯、画像），使模型/系统对该用户更准；**记忆系统**存储"用户经历过什么"（对话、事实、事件），供检索与上下文拼接。二者互补：记忆是原料，个性化是加工成品。详见 [[Agent 记忆与个性化意图理解]] 对记忆系统+意图理解的"基础设施"定位。 |
| **个性化 vs 推荐系统** | 推荐系统多为云端聚合统计；端侧个性化强调单设备、单用户的本地化建模与隐私闭环。 |

## 2. 技术方法（点到为止）

| 方法 | 一句话 | 备注 |
| --- | --- | --- |
| **端侧微调 / On-device fine-tuning** | 在手机上用用户数据直接调整模型权重。 | 算力与内存受限，通常需配合压缩。 |
| **LoRA / 适配器（Adapter）** | 冻结主干，只训练低秩增量矩阵（如 r=8, alpha=16）。 | 可训练参数量可减少 90%+（参考 Open-AutoGLM 实践与 LoRA-Edge 研究），适合端侧。 |
| **私有 LoRA（Private LoRA）** | 每用户一个 LoRA 适配器，**永不离开设备**，仅本地生效。 | 与联邦 LoRA 的关键区别见下。 |
| **联邦学习个性化（Federated Personalization）** | 各设备本地训练，仅上传（差分隐私保护后的）梯度/适配器权重，云端聚合全局模型再下发。 | FedAvg/FedLoRA 系；可在保护原始数据前提下集体进化。 |
| **联邦 LoRA（Federated LoRA）** | 联邦框架下只共享 LoRA 适配器权重、不共享训练数据。 | 结合差分隐私+安全飞地可形成隐私保护微调管道。 |
| **迁移学习 / 上下文-行为序列建模** | 用预训练通用模型作底，结合本地行为序列（App 使用、时空、交互）做轻量适配。 | 行为序列是端侧画像的核心信号源。 |
| **设备端特征提取（向量化/embedding）** | 把本地内容（照片、联系人、日程）压缩为数学"指纹"向量，供本地检索与关联。 | 如本地语义索引，不复制原文即可"找图"。 |
| **端云协同个性化** | 端侧做轻量个性化+隐私过滤，复杂任务上云（私有云/机密计算）扩展智能。 | 代表：Apple Private Cloud Compute、Google Private AI Compute。 |

**代表框架/工作（公开资料）**：Apple 端侧 30 亿参数基础模型 + LoRA 适配器；Google Gemini Nano / AICore / Private Compute Core；Meta 在联邦学习与个性化适配器方向的系列研究；学术前沿 FedGen-Edge（arXiv 2511.11585, 2025）、DP-FedLoRA（arXiv 2509.09097, 2025-09）、LoRA-Edge（2025）。

## 3. 隐私—个性化权衡

| 机制 | 如何兼顾"懂你"与"护你" |
| --- | --- |
| **差分隐私（DP）** | 在上传的梯度/适配器上加校准噪声（如 (ε,δ)-DP），防止从更新反推个人数据；代价是一定精度损失。 |
| **联邦学习** | 原始数据不出设备，只传聚合信号（"匿名的经验课"，非你的文本）。 |
| **设备内推理** | 大多数任务在端侧完成，响应更快、弱网可用、数据不触网。 |
| **隔离执行环境** | Android Private Compute Core、Apple 安全飞地等沙箱，敏感数据（语音/屏内容/生理）以原始形态不越界，仅最终结果出沙箱。 |
| **私有云扩展** | 需更强模型时上"私有云"，数据不被存储/不被厂商读取（Apple PCC 由独立专家可核查代码）。 |

## 4. 2025–2026 进展（联网核实）

| 方向 | 进展（点到为止） |
| --- | --- |
| **端侧小模型个性化** | Apple Intelligence 端侧 30 亿参数模型（官方称达 70 亿+模型相当表现）；开发者可通过 Foundation Models 框架直接调用端侧基础模型（WWDC25，2025-06）。 |
| **私有 LoRA / 联邦 LoRA** | DP-FedLoRA（2025-09）将 LoRA 适配与差分隐私结合；FedGen-Edge（2025-12）把"冻结全局主干 + 本地轻量适配器 + 仅聚合适配器"作为边缘生成式 AI 的实用路径，宣称上行流量较全模型 FedAvg 减少 99%+。 |
| **端云协同个性化** | Apple Private Cloud Compute、Google Private AI Compute（2025 末，Titanium Intelligence Enclaves）把"云端级"能力接上"端侧级"隐私承诺。 |
| **OS 级个性化入口** | Android 将 Gemini Nano 深度嵌入系统（AICore/系统智能），学习使用习惯做通知摘要、智能回复、自适应 UI；Apple 把端侧模型开放给第三方 App 做个性化体验。 |
| **多模态端侧个性化** | Gemini Nano 在端侧支持图文音同时理解（本地 NPU），用于实时翻译、场景识别、AR 叠加。 |

## 与《Agent 记忆与个性化意图理解》的分工

本库已有 [[Agent 记忆与个性化意图理解]]（位于「发散图谱/」），重在 **agent 记忆系统 + 个性化意图理解作为"基础设施"**——即"系统如何存、取、理解用户的意图上下文"。

**本篇的独特定位**：站在**个性化建模的技术侧**，回答"手机如何在端侧把用户模型建出来、用起来，而不把数据传云"——即 on-device learning / 端侧微调 / 联邦个性化 / 私有 LoRA / 隐私保护个性化这一层的方法与权衡。

> 一句话分工：**那篇 = 记忆与意图理解的"地基/管道"；本篇 = 在地基之上，端侧如何"长出懂你的用户模型"。** 二者可衔接：记忆系统提供原料与上下文，端侧个性化方法把原料加工成画像与偏好，再回灌给意图框架做预判。

## 对 OS PM 的意义

作为安卓系统 PM，端侧个性化是支撑以下产品目标的底层能力：

- **主动服务 / 意图预判**：本地行为序列建模让用户画像持续更新，使系统能在"用户开口前"预判需求（如按习惯推荐、按场景简化 UI），与 [[端侧意图框架 学习笔记]] 的意图识别/路由能力形成闭环。
- **隐私合规卖点**："数据不出设备"是差异化叙事（对标 GDPR、《个人信息保护法》），可作为系统级信任卖点，而非单纯功能堆砌。
- **与端侧意图框架的衔接**：意图框架负责"识别意图→路由到能力"，端侧个性化负责"用用户模型让识别更准、路由更贴心"；二者共用同一份本地画像/记忆，避免重复采集。
- **资源与体验权衡**：端侧个性化受 NPU/内存/功耗硬约束，PM 需平衡"适配器数量/存储预算"与"个性化收益"，并定义冷启动与遗忘机制的产品策略。
- **生态杠杆**：开放端侧个性化能力（类似 Apple Foundation Models 框架）可撬动开发者在自有 App 内做隐私优先的个性体验，反哺系统黏性。

## 待解问题

- [ ] **冷启动**：新用户/新设备无历史数据时，个性化如何 bootstrap（默认值/群体先验？）
- [ ] **遗忘与漂移**：用户改变习惯或偏好时，端侧模型如何"忘掉旧我"、避免概念漂移？
- [ ] **存储预算**：多场景/多用户适配器共存时，端侧 LoRA 适配器的内存上限与淘汰策略如何定？
- [ ] **私有 vs 联邦取舍**：何时该上传适配器做联邦聚合、何时必须留在本地不共享？
- [ ] **合规边界**：本地建模是否仍属"处理个人信息"？端侧个性化在 GDPR /《个人信息保护法》下的义务如何界定？
- [ ] **评测缺位**：如何量化"更懂用户"？业界缺乏统一的端侧个性化效果基准。
