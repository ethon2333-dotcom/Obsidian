# 国内安卓厂商做 App Intent 的阻力

> 国内安卓厂商（及鸿蒙）推行类似 App Intent 的「意图框架」，最大阻力**从来不是技术水平不够，而是手机厂商与互联网超级 App 之间关于生态掌控权、流量入口和商业利益的博弈**。

把 App Intent 比作系统给软件颁发的「标准 API 接口」：在 iOS，苹果有绝对话语权；在国内安卓，情况复杂得多。

## 4 个核心阻力

### 1. 超级 App 不愿沦为「无头 API」与后台管道
微信、支付宝、美团、抖音、小红书等超级 App 本质是「操作系统之上的操作系统」。
- **流量与广告流失**：用户对着手机 AI 说话，系统经 App Intent 后台完成「订外卖、买机票、发定位」，用户不再打开 App 界面。
- **失去掌控权**：App 失去用户停留时长、信息流广告曝光、首页弹窗、交叉推销（点外卖顺便借贷 / 买电影票）机会。互联网巨头极度抗拒被「管道化」和「去界面化」，对开放深度 Intent API 持谨慎甚至排斥态度。

### 2. 手机厂商阵营割据，接口标准严重碎片化
- **苹果**：全球 iOS 一个平台，开发者只适配一套 `AppIntents.framework` 即可覆盖全量用户。
- **国内安卓**：华为（鸿蒙意图框架）、小米（超级小爱）、荣耀（Magic Live / YOYO）、vivo（蓝心 Agent）、OPPO 等各自建 AI 意图标准。开发者要为 5~6 家单独适配 Intent 协议和 Schema 格式，工程成本高、收益不确定。

### 3. 数据主权与用户资产的「高墙防御」
App Intent 精准自动化不仅开放「动作（Action）」，更需暴露 App 内部**数据实体（App Entity）**——历史订单、聊天上下文、收藏夹、出行行程等。大厂视这些数据为核心商业护城河，极度担心：
- 经 Intent 暴露给手机厂商端侧 AI，造成用户数据资产泄露；
- 被手机厂商用于训练自己的竞争模型或推荐竞争对手（如手机 AI 据美团数据推荐饿了么优惠）。

### 4. 迫不得已的折中：GUI Agent 带来的「恶性循环」
正因无法推动大厂开放原生 API，国内厂商转向 **GUI Agent**（视觉识别 + 无障碍权限的屏幕模拟点击）：
- **优点**：绕过 App 许可直接「硬干」。
- **代价**：速度慢、耗算力、易因 App 小版本更新（改按钮位置 / 样式）而中断崩溃，且隐私安全风险大。
- **恶性循环**：厂商用 GUI Agent 强行点按 → 大厂更没动力开发维护原生 Intent → 甚至用技术手段（反爬虫、屏蔽无障碍服务）对抗自动点击。

## 核心困局
- 苹果：用强大生态统治力强行推行标准。
- 国内安卓：陷入「**厂商想收权 → 大厂不给接口 → 厂商用视觉点击（GUI Agent）破局 → 大厂防范对抗**」的拉锯战。

## 深化补充（2026-08）

### 一句话心智模型
阻力的本质不是「要不要开放一个接口」，而是「**谁来当用户的默认入口**」。App Intent 表面是技术协议，实际是**入口权的再分配协议**——所以它注定谈不拢，因为这是零和的。

### 2026 的关键变化：瓶颈换位了
上面第 4 点把 GUI Agent 写成「速度慢、易失效」的技术妥协。这个判断在 2026 需要修正——**GUI 的主要矛盾已经从「点不点得对」变成「被不被允许点」**：

- **能力侧在收敛**：OSWorld 榜单从 2024 年设立时的 ~12% 一路到 2026-07-31 的 **90.2%**（⚠️ 媒体报道口径，官方榜单页与提交记录**待核实**，见 [[OSWorld 计算机操作基准]]）。
- **准入侧在恶化**：豆包手机二代 NaviX Ultra **放弃一代的 GUI 视觉模拟路线，改用 MCP 协议与 App 官方接口直连**，公开动机就是**规避风控封禁**——这是国内第一个公开的路线切换实证。
- **准入边界被公开可视化**：华为小艺「帮帮忙」实测已可 GUI 跨应用操作支付宝、淘宝、拼多多，而**微信提示「尚未接入」**。这张图很说明问题：不是技术做不到，是有些门就是不给进。

→ **对本笔记原结论的修正**：「厂商用 GUI 破局」这条路的天花板不是技术精度，是**风控与追责**。规模化之后一定被反噬。GUI 的正确定位只能是**过渡 + 长尾只读**，绝不能拿来做写操作和支付。

### 一个此前没写进来的第三方力量：国标
碎片化（第 2 点）一直被当成无解，2026 出现了国家级路径：

- 《人工智能智能体互联》系列 **7 项国家标准**，覆盖「身份标识 — 能力描述 — 供需发现 — 协同交互 — 工具调用」五段式；北京在此之上提出 **AIP（智能体互联协议）**。
- 意义：四大 OS 各自封闭 Registry，**跨厂商互认此前没有公共层**，国标提供了第一份骨架。其中「**能力描述**」是唯一必须机器可读且跨厂商可迁移的一段——统一它，其余四段各家私有实现也行。
- ⚠️ **待核实**：标准号、全文、实际采纳率均未核验；产业落地深度未验证。

### 还有一股新的碎片化力量（第 2 点的加剧项）
「第五类玩家」——不是四大 OS，而是在 Android 之上做意图调度内核的：荣耀 AgenticOS、阶跃 Step AOS、卓易 DroiClaw（给中小品牌做 AI OS 中间层，累计装机超 2 亿，厂商口径）。它们把「意图驱动」打到千元档，**既加速长尾终端意图化，也让意图框架碎片化更严重**。原来是 5~6 家要适配，现在可能更多。详见 [[Agentic OS 意图调度内核]]。

### 推论：国内厂商联盟只能选「自由声明派」
Apple 和鸿蒙都走「平台预定义 Schema」（鸿蒙官方文档明示仅支持预置垂域意图、不允许自定义）。这条路要求平台有**压倒性生态号召力**——国内任一安卓厂商都不具备。所以联盟标准现实上只能仿 Android AppFunctions 的「开发者自由声明 + 描述文本驱动路由」，代价是**语义一致性差、路由准确率吃开发者文档质量**。这是选路时绕不开的取舍。

### 待解问题
- [ ] 如果 GUI 通道注定被风控封杀、原生通道注定谈不拢，**厂商的第三选择是什么**？（系统级前置感知？只做导流不做闭环？还是等国标强制？）
- [ ] 超级 App 抗拒的是「被管道化」。那有没有一种设计能让 App **在 Intent 调用中仍然获得曝光与归因**（比如系统强制回显 App 品牌卡片、把转化归因回传）？这是不是比谈判更有效的解法？
- [ ] 国标五段式里「身份标识」和「审计」一旦落地为强制要求，**受影响更大的是厂商还是超级 App**？谁更怕留痕？
