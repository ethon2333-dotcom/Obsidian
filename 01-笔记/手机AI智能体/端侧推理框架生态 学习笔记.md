# 端侧推理框架生态 学习笔记

> 学习定位：本篇是**广度种子笔记（BREADTH > DEPTH）**。从锚点「端侧大模型推理」向外辐射，落到**具体跨平台推理框架/运行时层**——它们是把训练好的模型真正"搬上手机跑起来"的部署工具。重点是「框架能力对比 + 部署形态 + 2025-2026 进展」，**不深挖每个框架源码**，也不重复「NPU 芯片厂编译栈（QAIRT/NeuroPilot）」与「端侧量化算法」两篇的内容。深度留白给 Ethon 后续补充。

---

## 一、一句话心智模型

**端侧推理框架 = 一个"跨平台运行时/部署容器"，把你训练好的模型（不论 PyTorch/TF/ONNX）编译成能在手机 CPU/GPU/NPU 上高效前向推理的可执行体，是技术栈里"模型 → 设备硬件"之间的那层胶水。**

补一句防混淆：

> **框架 ≠ 编译器 ≠ 量化算法。** 框架是"运行时壳"，它通过调用芯片厂的编译栈（delegate/EP）把算子落到 NPU，又通常在内部集成量化工具——但它本身不发明 NPU 指令集、也不发明量化算法。

## 二、广度覆盖：主流跨平台推理框架对比

| 框架 / 运行时 | 出品方 | 主打能力 / 硬件后端 | 量化 / 算子支持 | 部署形态 | 典型使用场景 |
|---|---|---|---|---|---|
| **LiteRT**（TFLite 接班人） | Google | 跨平台 ML/GenAI 运行时；CPU(XNNPACK) / GPU(ML Drift：OpenCL·OpenGL·Metal·WebGPU) / **NPU(Google Tensor·Qualcomm·MediaTek)** | 训练后量化工具链；**LiteRT-LM** 专跑 LLM（`.litertlm`，原生 KV-cache） | `.tflite` / `.litertlm`；Android/iOS/桌面/Web/LiteRT.js | Gemma 系端侧聊天与图像理解；Pixel AI Edge Gallery；Chrome/Chromebook 端侧 GenAI |
| **ExecuTorch** | Meta（PyTorch） | PyTorch **原生**端侧运行时；后端 XNNPACK / Core ML / **Qualcomm Hexagon** / Arm Ethos-U / Vulkan / MediaTek / Samsung Exynos / OpenVINO / NXP | 导出期量化（int8/int4 LLM）；`.pte` 紧凑格式；~50KB 最小运行时 | `.pte`；iOS/Android/嵌入式/AI PC/MCU | Meta 系 App（IG/WhatsApp/Messenger）端侧特性；多模态 LLM/VLM 落地 |
| **MNN** | 阿里巴巴 | 轻量**混合调度**引擎；CPU / GPU(OpenCL·Vulkan·Metal) / NPU(CoreML·NNAPI·HIAI) | INT4/INT8/FP16；**MNN-LLM** 跑 Qwen/Llama/Baichuan | 自研 `.mnn`；Android/iOS/PC/嵌入式/鸿蒙 | 淘宝等 30+ App；MNN-LLM、MNN-Diffusion、TaoAvatar 离线多模态 |
| **NCNN** | 腾讯 | 纯 C++ **无第三方依赖**、ARM CPU 极致优化；Vulkan GPU | INT8；动态 shape；PNNX 模型转换 | `param/bin`；Android/iOS/鸿蒙/嵌入式/WebAssembly | 微信/QQ 端侧视觉；移动端检测/分割/人脸识别 |
| **ONNX Runtime Mobile** | Microsoft | 通用 ONNX 运行时；**EP**：NNAPI(Android) / CoreML(iOS) / XNNPACK / DirectML / **Qualcomm QNN** | INT8 量化；minimal build 可压到 4–5MB | `.onnx`；Android(`.aar`) / iOS | 跨框架模型落地 Windows/Android/iOS 企业应用 |
| **TFLM**（TFLite for Microcontrollers） | Google | KB 级 MCU 专用 TinyML 运行时 | 定点/int8，固定内存 arena | `.tflite` 固定 arena | 超低资源 microcontroller（非手机主战场，作对照） |

## 三、主流方案分类（别混成一锅）

### 3.1 通用跨平台推理引擎 vs 厂商专用编译栈（关键区分）

| 类别 | 是什么 | 代表 | 与框架的关系 |
|---|---|---|---|
| **通用推理引擎 / 运行时**（本篇主角） | 跨厂商、跨 OS 地把模型跑起来 | LiteRT / ExecuTorch / MNN / NCNN / ONNX Runtime | 上层"壳"，通过 delegate/EP 调用下面那层 |
| **厂商专用编译栈**（本篇**不展开**） | 芯片厂把计算图编译成 NPU 专用指令 | 高通 **QAIRT/QNN**、联发科 **NeuroPilot**、Apple **Core ML/ANE**、华为 **CANN** | 框架的"后端"，被框架调用，不是框架本身 |

> PM 视角：**选框架决定"开发一次能部署到哪些设备"，选编译栈决定"在那颗 NPU 上跑多快"**。二者是上下层，别把"用了 LiteRT"和"用了 QNN"当成二选一——实际是 LiteRT 通过 QNN delegate 调高通 NPU。

### 3.2 按"是否 LLM 优先"再切一刀

- **LLM 优先**：LiteRT-LM、ExecuTorch（`.pte` 多模态）、MNN-LLM、llama.cpp/MLC-LLM。
- **经典 CV/CNN 优先、后补 LLM**：NCNN（原生偏 CNN）、ONNX Runtime Mobile、MNN（混合）。

## 四、2025—2026 进展（一手源优先）

- **LiteRT 全面取代 TFLite**：2024 发布、Google I/O 2025 预览 v2 **CompiledModel API**，2025 年把 NPU/GPU 加速"毕业"进生产栈。官方口径：GPU 较 TFLite 平均 **1.4×**；统一 NPU 接入 Google Tensor / 高通 / 联发科；LiteRT.js 走 WebGPU+WASM 在浏览器内跑。⚠️ "1.4×" 来自 Google 官方博客，未列具体模型/设备，待一手基准。
- **ExecuTorch 1.0 GA**：Beta 于 2024-10，1.0 正式版由 Meta+Arm 在 **2025 下半年**（Arm 新闻 2025-11）联合发布；~50KB 最小运行时、12+ 后端（新增 Arm VGF、NXP eIQ Neutron、Samsung Exynos NPU/GPU、Intel OpenVINO）。已在 Meta 系数十亿用户 App 生产使用。⚠️ 确切 GA 月份待 Meta 官方发布页对齐。
- **MNN 2026 社区动态**：GitHub News 显示 2026/03 支持 **Qwen3.5** 系列、2025/10 支持 **Qwen3-VL**、MNN-LLM Android App、MNN TaoAvatar（LLM+ASR+TTS 全本地离线 3D 数字人）；持续强化 INT2/3/4-bit 权重量化。
- **NCNN 持续发版**：2025/05（20250503）、2025/09（20250916）等滚动版本；新增**鸿蒙（HarmonyOS）**交叉编译构建，适配国内多端。
- **ONNX Runtime Mobile**：移动端 EP 成熟（NNAPI / CoreML / XNNPACK），新增 **Qualcomm QNN EP** 直连骁龙 NPU；minimal build 支持按需裁剪算子到 4–5MB。

## 五、与相邻概念的关系（防信息孤岛）

1. **vs NPU 编译栈（QAIRT/NeuroPilot/ANE）**：框架是"上层运行时"，编译栈是"芯片厂把图落到 NPU 指令的工具"。框架通常经 delegate/EP 调编译栈——本篇只讲框架层，编译栈细节留给「移动端 NPU 与推理编译栈」专题（库内暂无，待建）。
2. **vs 端侧模型量化（算法侧）**：量化是"模型压缩步骤"（算法/数值），框架是"执行容器"。多数框架自带量化工具链（LiteRT Optimizer、MNN-Compress、ORT Quantization），但量化算法本身不是框架发明的——算法细节留给「端侧模型量化」专题（库内暂无，待建）。
3. **vs 锚点「端侧大模型推理」**：那篇讲"在手机跑 LLM 的范式、为什么重要、四层技术栈（硬件/压缩/系统/框架）"，本篇只取其中**「推理框架层」**向外铺开做横向对比——是锚点的"框架子树"深耕版，不重复其硬件/量化/系统优化章节。
