> **一句话心智模型**：端侧不是「一个模型跑到底」——根据任务难度、实时性、功耗预算、网络状态，在端侧小模型、端侧大模型、云模型之间**动态路由**，是端侧 AI 体验与成本平衡的核心调度问题。

> **差异化定位**：本篇聚焦「**运行时**的动态路由与模型选择**决策**」；区别于《端云协同推理与混合部署》那篇的端云「架构分流/混合部署」视角，也区别于 `[[端侧大模型推理 学习笔记]]`（推理本身）、`[[端侧 AI 功耗与散热约束 学习笔记]]`（功耗约束）、`[[端侧多模态 VLM 学习笔记]]`（模型供给）。本篇是「**在哪一档模型上跑、何时切换**」的调度层。

## 一、为什么需要动态路由

端侧算力/功耗/延迟约束与任务难度**异质**之间存在根本张力：简单任务（意图分类、抽取、改写）用大模型是浪费，复杂任务（长链推理、跨模态生成）用小模型是能力不足。动态路由的价值在于**用最小代价满足质量门槛**。

| 约束维度 | 端侧小模型（SLM） | 端侧大模型 | 云模型 |
|---|---|---|---|
| 首字延迟 | 极低（本地） | 低-中 | 高（网络往返） |
| 功耗/发热 | 低 | 中-高 | 无（端侧） |
| 离线可用 | ✅ | ✅（若装得下） | ❌ |
| 能力天花板 | 低 | 中 | 高 |
| 单请求成本 | 近 0（用户电费） | 近 0 | 按 token 计费 |

> 行业口径（待核实）：有分析称生产 Agent 系统 70-80% 的 LLM 查询「从未需要 frontier 模型」（GraphWiz, 2026）。该数字为媒体估算，未独立验证。

## 二、路由维度与策略（核心）

路由可以由**单维度启发式**或**多维度 router** 驱动。下表为广度覆盖：

| 路由策略 | 触发信号 | 典型场景 | 代表实现 / 出处 |
|---|---|---|---|
| **按任务类型路由** | 任务标签（分类/抽取/生成/推理） | 意图分类→小模型；创作→大模型 | 端侧模型路由表（CSDN 选型指南, 2026，待核实具体数字） |
| **按置信度 fallback** | 小模型输出 confidence / 自评估 < 阈值 | 简单问答本地答，答不准转云 | FrugalSOT（arXiv 2608.21621, 2026）：按 prompt 复杂度分级 + 相关性阈值后台自适应 |
| **按功耗/热预算路由** | 电池%、NPU 温度、散热余量 | 高温时降级到更小模型保流畅 | 高通/联发科异构调度（厂商宣传口径） |
| **端云混合路由** | 网络状态、数据敏感度、延迟 SLA | 隐私数据留端、复杂任务上云 | Apple PCC、GraphWiz 三层级架构（2026） |
| **多模型 ensemble 路由** | 任务需多专长 | 多专家投票/级联 | Mixtral 类 MoE 稀疏激活（见第五节） |
| **按内存/OOM 降级** | 可用内存 < 模型需求 | 低端机回退到 230M/1B 模型或云 | 端侧部署最常见失败模式=OOM 崩溃（行业经验，待核实系统性数据） |

## 三、实现机制

- **Router / 分类器**：一个轻量 SLM 或规则分类器在请求入口做「先判难度再派发」。FrugalSOT 用 prompt 长度、命名实体密度、句法复杂度作为复杂度特征，先发给「最可能过阈值的最小模型」，不过再升级。
- **LLM 自评估 confidence**：让小模型输出自身置信度；低于阈值则 fallback 到更大模型或云。需配套校准，否则「过度自信」会破坏路由正确性（深度盲区）。
- **Prompt 复杂度预估**：基于长度/结构/实体密度的启发式，或学习到的复杂度打分（FrugalSOT 思路）。
- **硬件状态感知**：读取 NPU 负载、SoC 温度、剩余电量、可用内存，动态调整档位。高通 QNN / 骁龙 AI Engine 据称按「负载类型 + 延迟预算 + 功耗包络」跨 CPU/GPU/NPU 调度（厂商宣传口径）。
- **ASR / VLM 分级**：语音与视觉链路本身也是分级路由——ASR 用 Tiny 模型实时出字、复杂口音/噪声升级；VLM 用端侧小 VLM 做 grounding，复杂视觉理解上云（串接 `[[端侧多模态 VLM 学习笔记]]`、语音交互链路）。

## 四、代表系统与框架

| 系统 / 框架 | 路由/调度做法 | 备注 |
|---|---|---|
| **Apple Adaptive（端侧 + PCC）** | 约 3B 端侧基础模型处理日常（改写/摘要/优先级），重任务 offload 到 Private Cloud Compute；决策由 OS 实时做 | 端侧模型常驻、PCC 端到端加密、可关 PCC 仍用端侧（Apple 官方/媒体综述, 2025） |
| **高通 Hexagon NPU + QNN** | Snapdragon AI Engine 跨 CPU(矩阵加速器)/Adreno GPU/ Hexagon NPU 异构调度，按负载类型与功耗包络分配 | 2025 骁龙 8 至尊版 NPU 性能 +37%、每瓦 +16%（厂商发布口径，待核实独立基准） |
| **联发科 APU** | Dimensity APU 在 NPU 内做任务调度；与 Google LiteRT 生产级 NPU 集成（MediaTek + LiteRT, 2025/2026） | 中端机 democratize 端侧 AI |
| **LiteRT / ExecuTorch delegate** | 运行时自动选择 GPU/NPU delegate，条件不足**自动回退 GPU/CPU**；AOT + JIT 两种编译策略 | LiteRT 称 NPU 比 CPU 快 100×、比 GPU 快 10×（Google 官方博客，待核实跨 SoC 一致性） |
| **端云混合 serving 路由** | 三层级：端侧 1-14B / 私有云 14-70B / frontier 云；router 按复杂度+敏感度+延迟+成本派发 | GraphWiz 2026 生产模式总结 |
| **Speculative 端侧小模型 draft** | 端侧小 draft 模型快速出 token，大 target 模型并行验证（加速而非选模型，但本质是「小模型打头阵」的协同路由） | EdgeLLM（IEEE TMC 2025，最高 9.3× 加速）、SLED（SEC 2025）、边缘-云投机解码（arXiv 2505.21594） |

## 五、2025-2026 进展

| 进展方向 | 是什么 | 代表 |
|---|---|---|
| **SLM 充当 router** | 用极小的 SLM 做「路由决策」本身，比规则更泛化 | FrugalSOT（2026）、各类 router-LLM 方案 |
| **MoE 端侧稀疏激活** | 总参数大但每 token 仅激活 top-k 专家，端侧承受「大容量 + 小算力」 | EdgeMoE（IEEE TMC 2025，专家权重按激活外存换入）；Liquid AI **LFM2-8B-A1B**（2025-10，8.3B 总参/1.5B 激活，官方宣称质量≈3-4B dense、速度>Qwen3-1.7B） |
| **硬件感知调度** | 运行时据温度/电量/NPU 负载自动切档与 delegate 回退 | LiteRT 统一 NPU 委托+回退、QNN 异构调度 |
| **端侧 Agent 的模型动态选型** | Agent loop 中按子任务类型选端/云/大小模型（如规划用云、执行用端） | 高通 2025 骁龙峰会展示「端侧 AgentCPM」「超级小爱×马蜂窝」等端侧多模态 Agent（厂商展示） |
| **动态精度切换** | 按复杂度自动切运算精度（int4/int8/fp），降本 30-40%（调研口径，待核实） | 行业趋势文（2025-2026） |

> ⚠️ 多处厂商数字（TOPS、加速倍数、降本比例）来自厂商发布或行业博客，**未独立验证**，详见文末待核实清单。

## 六、产品体验含义

| 体验指标 | 路由策略如何影响 | PM 关注点 |
|---|---|---|
| **首字延迟 (TTFT)** | 简单任务走端侧 SLM → 近乎零延迟；复杂任务上云 → 受网络影响 | 低端机/弱网下路由降级的可感知卡顿 |
| **功耗/发热** | 高温或低电量时降档可避免降频掉帧 | 长会话发热导致的体验拐点 |
| **离线可用** | 关键意图/离线指令走端侧 → 断网仍可交互 | 离线能力边界需对用户透明 |
| **成本** | DAU>1 万后端侧成本优势显著（行业估算，待核实） | 端侧集成成本 vs 云端 token 账单权衡 |

## 待解问题（BREADTH 留白，点到为止）

- [ ] **置信度校准**：小模型自评估 confidence 的校准误差会直接破坏 fallback 正确性，实际生产中如何低成本校准？
- [ ] **路由器的自身开销**：router 本身（SLM/分类器）的延迟与功耗是否抵消了路由收益？阈值如何动态设定？
- [ ] **MoE 在手机端的专家换入抖动**：外存↔内存专家换入带来的 I/O 延迟，在低端机是否反而劣于 dense 小模型？
- [ ] **端侧 Agent 的多步路由一致性**：Agent loop 中每步重选模型，如何避免「前半步端侧、后半步云端」导致的上下文/隐私割裂？
- [ ] **厂商 NPU 调度黑盒**：高通/联发科/苹果各自调度策略不透明，第三方 App 能否真正拿到「温度/负载」做二次路由，还是只能被动接受？
