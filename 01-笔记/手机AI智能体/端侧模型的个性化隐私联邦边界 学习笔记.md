# 端侧模型的个性化隐私联邦边界

> **一句话心智模型**：端侧个性化与隐私联邦的边界，是一条「数据物理位置 × 隐私保护强度」的连续谱——左端数据永不出端（本地 LoRA/ICL/RAG 适配个人），右端仅出模型更新并加噪声（联邦聚合），中间由 PCC/TEE 等可信边界撑起「该出时才出」的端云协同。

---

## 一、广度覆盖（点到为止）

### 1. 定义

| 概念 | 核心含义 | 边界要点 |
|---|---|---|
| 端侧个性化（on-device personalization） | 在设备本地让模型适配个人，**原始数据不出端** | 手段含 LoRA/adapter 微调、prompt 缓存用户画像、RAG 个人知识、上下文学习（ICL） |
| 隐私联邦（privacy-preserving federation） | 多设备协同训练共享模型，**仅上传模型更新（梯度 / LoRA delta）而非原始数据** | 靠差分隐私、安全聚合、同态加密、TEE 保护「更新」中的隐私 |

### 2. 分类

| 类别 | 典型成员 | 一句话区分 |
|---|---|---|
| 个性化方式（出端 vs 不出端） | LoRA/adapter 微调、prompt 缓存用户画像、RAG 个人知识、上下文学习（ICL） | 决定「适配发生在哪」：本地权重 / 本地缓存 / 本地检索 / 上下文 |
| 联邦学习（FL） | FL / Federated Averaging（FedAvg）、联邦微调（federated fine-tuning）、个性化联邦学习（PFL，如 Ditto） | 决定「共享如何发生」：全局聚合 + 可选个性化头 |
| 隐私技术 | 差分隐私（DP / DP-SGD）、安全聚合（SecAgg）、同态加密（HE）、可信执行环境（TEE） | 决定「出端的东西有多安全」：噪声 / 掩码 / 密态计算 / 硬件隔离 |

### 3. 主流方案（2025–2026 核实）

| 方案 | 主体 | 关键点（公开口径） |
|---|---|---|
| Gboard + FL/DP | Google | Gboard 自 2024 起全部神经语言模型以「联邦学习 + 差分隐私」训练，仅聚合学习、不上传按键（媒体口径，待核实具体版本边界） |
| Private AI Compute | Google | 对标 Apple PCC：超端侧算力的请求在加密安全区处理，Google 自称看不到敏感数据（媒体口径） |
| Apple Intelligence + PCC | Apple | 端上优先；超量走 Private Cloud Compute（无状态、可验证、差分隐私、Enhanced Visual Search 用同态加密） |
| 端侧 LoRA/PEFT | 学界/产业 | EdgeTune（SenSys'26, 2026.05）主打端侧持续个性化，摊销成本最高降 **79%**（论文口径，绝对值待核实）；Google 2026.09 提出 hypernetwork 生成 LoRA，**仅前向传播、无需端上梯度下降**（arXiv:2609.24979） |
| 联邦微调框架 | FedML / OpenFL / TensorFlow Federated / Flower | 开源生态：FedML（生产级 MLOps）、OpenFL（Intel→Linux Foundation，含 SGX 安全区）、TFF、Flower（PyTorch/TF/JAX 通用） |
| 差分隐私训练 | DP-SGD / Opacus / TensorFlow Privacy | 提供 `(ε,δ)`-DP 隐私预算记账，噪声越大隐私越强但效用下降 |

### 4. 2025–2026 进展

| 进展方向 | 代表信号 | 说明 |
|---|---|---|
| 端侧 PEFT/LoRA 个性化普及 | EdgeTune（2026.05）、hypernetwork-LoRA（2026.09） | 把「端上微调不可行」逐步推向「前向传播即可个性化」，降低存储/算力门槛 |
| 联邦学习与端云协同 | Apple PCC、Google Private AI Compute | 把隐私边界从「纯端」延伸到「可信云」，端云分工成为主流形态 |
| 隐私预算 ↔ 个性化强度权衡 | DP-Ditto（IEEE TMLCN 2025） | 量化「收敛–隐私–公平性」三角权衡；隐私预算 ε 越小噪声越大，个性化公平性随之下降 |
| 法规影响数据治理 | EU AI Act 2025 落地、《个人信息保护合规审计管理办法》2025.05.01 施行 | GDPR 将 LLM 训练视为个人数据处理，强化同意/退出；个保法以「告知同意、最小必要」约束行为数据 |

### 5. 代表产品 / 平台横向对比

| 方案 | 个性化是否出端 | 聚合/协同方式 | 主要隐私技术 | 代表场景 |
|---|---|---|---|---|
| Google Gboard | 否（仅出模型更新） | FL + FedAvg | 差分隐私 | 输入法预测 |
| Apple Intelligence / PCC | 尽量不出端，超量走 PCC | 端上 + 可信云 | DP + HE + TEE | Siri、Genmoji、邮件摘要 |
| EdgeTune / hypernetwork-LoRA | 完全不出端 | 无需聚合（本地生成 LoRA） | 本地隔离 | 端侧 LLM 个性化 |
| FedML / OpenFL / TFF / Flower | 取决于部署 | FedAvg / SecAgg | DP + SecAgg | 研究与企业级联邦 |

## 二、深度盲区（待解问题）

- [ ] 待解问题：个性化「遗忘 / 注销」如何彻底擦除端上 LoRA 与用户画像（被遗忘权 vs 端侧残留，PCC 的「可验证擦除」能否覆盖本地）？
- [ ] 待解问题：联邦参与的激励与公平性——低资源设备 / 少数群体是否被「平均」掉？DP-Ditto 论文显示 DP 噪声下公平性差异可达 32.71%（论文口径），泛化到真实异构设备待核实。
- [ ] 待解问题：端侧微调的存储与算力上限——1B 级模型 LoRA 在手机 RAM / 功耗下的可行性边界（EdgeTune 称摊销成本降 79%，但绝对上限与热节流影响待核实）。
- [ ] 待解问题：差分隐私对效果的损耗量化——DP 噪声带来约 5–10% 准确率下降为媒体/论文口径，不同任务、不同 ε 下的真实损耗边界待核实。
- [ ] 待解问题：联邦聚合中的「边界穿越」——hypernetwork 训练（Phase 1）虽在端外，但需用户上下文样本，如何在不集中原始数据下完成（论文称可用 TEE-based FL，但落地形态待核实）。

## ⚠️ 待核实清单

- Gboard「全部神经语言模型以 FL+DP 训练」为媒体综述口径，具体版本与模型范围待向 Google AI Blog / 原始论文核实。
- Google「Private AI Compute」命名与能力边界为媒体口径，官方技术白皮书待核实。
- EdgeTune「摊销成本最高降 79%」「GradCut 降约 20%」为论文在 Jetson Orin Nano + Pixel 6a 上的实测，迁移到 2026 主流手机 SoC 的绝对值待核实。
- DP-Ditto 的「公平性 +32.71% / 准确率 +9.66%」基于 MNIST / FMNIST / CIFAR-10 等图像分类，端侧 LLM 个性化场景的对应数字**待核实（未定）**。
- 差分隐私「约 5–10% 效用损失」为多篇资料共识性口径，具体取决于 ε、任务与聚合轮数，**未定数字需按部署实测**。
- EU《数位综合法案（Digital Omnibus）》草案（2025.11 提出）对 GDPR 的修订仍处立法进程，最终文本与生效时间**待核实**。
