**端侧小模型不是"原创"的：它几乎都由一个更大的教师模型蒸馏而来，但用户和 PM 既看不到教师是谁、也看不到它转移了什么能力——这条"师生血缘"是当前端侧透明度最大的盲区。**

> 面向 PM / OS 产品视角，点到为止的广度覆盖，不深挖蒸馏算法本身。

## 广度覆盖

| 维度 | 内容要点 | PM / OS 产品视角盲区 |
| --- | --- | --- |
| **定义** | **影子模型（shadow model）** 有两层含义：① 作为"蒸馏教师"的大模型，其输出/logits 是端侧学生模型的训练数据与能力来源；② 用于监测已部署模型偏差/漂移的代理模型。**蒸馏教师透明度** = 披露"端侧学生由谁蒸馏、从教师处转移了哪些能力、训练数据来源为何"。 | 端侧团队通常只拿到学生权重，对上游教师的身份、训练数据、能力边界没有能见度。 |
| **分类** | 1. **蒸馏教师 vs 端侧学生**：大模型→小模型的知识迁移（soft-label / logit 蒸馏）。2. **影子模型用于偏差监测**：用同分布代理模型监控端侧模型偏差与概念漂移。3. **训练数据来源透明度**：含教师生成的合成数据（synthetic data）血缘、版权与许可链。 | 三类透明度常常被混为一谈；合规与产品文档往往只覆盖第 2 类（偏差），第 1、3 类几乎空白。 |
| **主流方案与代表** | - **知识蒸馏 pipeline**：学生模仿教师的软化输出分布（KL 散度损失）。- **教师模型托管**：教师留在云端 / TEE 内，学生端侧训练（Google AICore 托管 Gemini Nano 教师；DistilLock 用 TEE 防教师 IP 泄露，待核实）。- **EU AI Act Art.50 透明度义务**：交互告知"你在和 AI 互动"、合成内容机器可读标记；Art.53 / Annex XI 对 GPAI 另有文档义务。- **模型卡披露教师来源**：Model Card / Datasheet 标注师生血缘（Meta 在模型卡中界定学生相对教师的能力位阶，待核实）。- **第三方审计**：独立验证模型 lineage 与训练数据来源（目前端侧场景近乎缺位）。 | 端侧 SLM 的"能力来源"通常不在 model card 中；第三方审计缺乏可验证证据链。 |
| **2025-2026 进展** | - 端侧小模型（SLM）普遍由前沿大模型蒸馏而来（Gemini Nano、Llama 系列蒸馏版、DeepSeek R1 蒸馏版等），带来**透明度 / 知识产权 / 能力溯源**三重问题。- **DistilLock**（TEE 辅助安全边缘蒸馏，2025-10，待核实）尝试在保护教师 IP 下完成端侧蒸馏。- **EU GPAI 实践准则**（2025-07-10 发布）与 Art.50 指南构成"模型层→输出层"全链条透明度监管。- 蒸馏合法性边界成为焦点：2025 多起版权诉讼与威胁报告指向"未授权蒸馏他人专有输出" vs "合法内部蒸馏"（待核实项见文末）。 | "教师更新、学生不自动同步"的版本治理缺口；端侧团队难追溯上游教师的合规状态变化。 |
| **代表产品 / 实践** | - **Google Gemini Nano**：蒸馏自更大 Gemini 兄弟模型，经 AICore / ML Kit GenAI API 在 Android 16 端侧运行。- **NVIDIA Llama-3.1-Minitron**：剪枝+蒸馏版 Llama 3.1 8B，称用至多 40× 更少训练 token 匹配教师。- **DeepSeek R1 蒸馏版**（2025-01，基于 Qwen / Llama，1.5B–70B，MIT 许可）。- **Meta Llama 蒸馏生态 / Muse Glimmer**（待核实具体命名与发布细节）。- **Apple Foundation Models**：端侧自研，教师关系未公开（待核实）。 | 厂商口径普遍只讲"端侧能跑、隐私更好"，极少披露教师血缘、合成数据占比与能力溯源。 |

## 深度盲区（待 Ethon 补充）

- [ ] 当前主流端侧 SLM（Gemini Nano / Apple FM / 各安卓厂端侧模型）的**模型卡是否披露教师来源与蒸馏范围**？是否有公开事实可查？
- [ ] EU AI Act Art.50 的"交互告知 + 合成内容机器可读标记"义务，**在端侧离线推理场景下如何落地**（无云端水印服务时）？各厂商 2026 合规时间表为何？
- [ ] 端侧学生模型的**能力溯源与责任归属**：当输出侵权 / 出错，责任在教师方、蒸馏方还是部署方？现有合同（ToS 禁止蒸馏条款）如何界定？
- [ ] **第三方审计**端侧模型 lineage 的可行机制：是否可借助模型卡 + 水印 + TEE  attestation 构成可验证证据链？
- [ ] 教师模型**更新后学生不自动同步**的版本治理：端侧 OTA 是否应携带"教师版本 / 蒸馏日期"元数据供追溯？
