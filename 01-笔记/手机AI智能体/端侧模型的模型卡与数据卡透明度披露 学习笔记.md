**心智模型：模型卡 / 数据卡是把"这是什么模型、训练了什么、能做什么、不能做什么"结构化的"AI 营养标签"，随模型一起分发；端侧 AI 跑在用户设备上，用户更应有可读的透明度面板来信任它。**

> 与库内笔记的区分：本篇聚焦**"模型卡/数据卡这类结构化披露物本身 + 其合规义务"**（披露什么、谁要求、怎么成证据）；不重复 [[端侧模型推理的可解释性 UX 落地 学习笔记]]（那是算出来的归因/置信度"怎么给用户看"的呈现层）、也不展开 [[负责任 AI 与 AI 产品伦理落地 学习笔记]] 的泛 RAI 产品化框架。合规义务侧串接 [[AI 监管与合规落地 学习笔记]]，端侧保护侧可参考 [[端侧大模型安全芯片级防护 学习笔记]]、软硬协同侧见 [[端侧模型与 SoC 协同设计 学习笔记]]。

## 一、定义：三种"卡"的对象不同

| 名称 | 提出/来源 | 描述对象 | 核心类比 |
| --- | --- | --- | --- |
| **Model Card（模型卡）** | Mitchell, Gebru 等（Google），FAT\* 2019《Model Cards for Model Reporting》 | 训练好的**模型权重**：怎么训、在哪评、在哪失败 | "AI 的营养标签" |
| **Datasheet / Data Card（数据卡）** | Gebru 等 2018《Datasheets for Datasets》（CACM 2021）；Pushkarna 等（Google）2022《Data Cards》 | **训练数据集**：动机/构成/采集/标注/分发/维护 | 电子元件数据手册 |
| **System Card（系统卡）** | OpenAI GPT-4 System Card 2023；arXiv:2509.20394《Blueprints of Trust》(2025) | **端到端部署系统**：模型+安全栈+护栏+工具调用 | 产品级安全论证 |

- 规则：**一个对象一份卡**。模型卡依赖数据卡准确（上游文档）；生产级安全论证还需要系统卡（CVE 常出现在系统层 RAG+工具，而非模型层）。
- Model Card 标准九节：模型细节 / 预期用途 / 因子（评估相关人群或环境）/ 指标 / 评估数据 / 训练数据 / 定量分析（按因子拆分）/ 伦理考量 / 注意事项与建议。

## 二、披露维度分类（端侧模型应覆盖的字段）

| 维度 | 端侧场景下的关键字段 |
| --- | --- |
| **模型身份与来源** | 名称/版本/开发者/基础模型/参数量/语言/蒸馏或量化来源 |
| **训练数据概要** | 数据集来源·规模·构成·标注方式·已知偏见；是否附 Data Card 链接 |
| **能力边界** | 预期用途、适用任务、`端侧能跑`的上下文长度/吞吐、按人群拆分的量化评测 |
| **已知限制与失败模式** | out-of-scope 用法、典型幻觉/拒答、对抗脆弱点、长上下文衰减 |
| **能耗 / 隐私属性** | CO₂/水耗（云端训练）、端侧 vs 云侧、数据是否出端、NPU 量化格式（INT2/INT4） |
| **许可证** | 权重许可、商用限制、red-team / 衍生披露要求 |

## 三、主流框架

| 框架 | 性质 | 与端侧模型卡的关系 |
| --- | --- | --- |
| **Google Model Cards**（Mitchell 2019） | 学术/自愿格式，9 节 | 端侧小模型卡字段蓝本 |
| **Datasheets for Datasets**（Gebru 2018） | 学术/自愿格式 | 端侧模型"训练了什么"的上游凭证 |
| **Hugging Face Model Cards** | **事实标准**：模型仓库的 README.md + YAML 元信息块（license/languages/training datasets/base model/task） | 端侧开源模型（Gemma/Qwen/MiniCPM）的默认分发载体；Model Card Guidebook 要求 3 个角色共同填写（开发/社会技术/项目负责人） |
| **EU AI Act 透明度义务** | **法律强制** | 见下节 |
| **Apple / Qualcomm / Snapdragon 端侧披露实践** | 厂商技术报告 / AI Hub 元数据 | 见第五节 |

## 四、合规透明度义务（EU AI Act，重点区分两条线）

> ⚠️ 注意：常被混为一谈的两条透明度线要分开——
> - **Article 50**：面向"用户交互"的透明度——AI 系统需告知用户"你在和 AI 交互"、合成内容需机器可读标记、情感识别/生物识别/深伪需披露。官方口径**自 2026-08-02 起适用**（注：本库部分中文二手源写 2025，以官方 artificialintelligenceact.eu / EC 事实页为准）。这与"模型卡"是**用户体验层**义务，对应 [[端侧模型推理的可解释性 UX 落地 学习笔记]] 的标识层。
> - **Chapter V / Article 53（GPAI 模型）**：面向"模型本身"的文档义务——提供者须编制并持续更新技术文档（**Annex XI**）、向下游提供者共享（Annex XII）、按模板公开**训练内容摘要**；自 **2025-08-02** 起适用。这套文档**长得像模型卡，但更长、可依法索要**——把模型卡变成合规证据的关键落点。

- 模型卡成为"合规证据"的 4 个条件（aisigil 整理）：版本化、三角色签署、用监管字段名书写、关联到 AI 系统记录。
- 透明度正在退步：Foundation Model Transparency Index（2025-12）平均 **41/100**，较 2024 跌 17 分；HF 上**最少填写**的字段是环境影响、限制、评估。
- 采用痛点：Oreamuno 等 2023 审计 HF 模型卡，仅 **0.3%** 记录伦理考量。

## 五、2025–2026 进展

| 趋势 | 要点 |
| --- | --- |
| **端侧小模型卡** | 端侧 SLM（3B 级）开始配模型卡/技术报告，字段比云侧大模型更强调端侧约束（上下文长度、NPU 量化、能耗） |
| **合规驱动透明度** | EU GPAI 文档（Annex XI）+ 加州 AI Transparency Act 等把"写卡"从自愿变强制证据 |
| **用户可读面板** | 从开发者 README 走向"用户可读信息面板"；Data Card 的望远镜/潜望镜/显微镜三层（Pushkarna 2022）适配不同读者 |
| **自动化与可验证** | CardGen（Liu 2024）用 LLM 自动生成模型卡；Blueprints of Trust（arXiv:2509.20394）推机器可读 JSON Schema、随构建流水线自动生成 |
| **可验证证明** | Laminator（Duddu 2024）等"可验证证明"工作，解决"卡写了但不可信"——⚠️ 端侧落地的成熟度**待核实** |

## 六、代表产品与厂商实践

| 厂商 / 产品 | 透明度披露实践 |
| --- | --- |
| **Apple Foundation Models** | 发布技术报告描述模型族（2025 端侧约 **3B** 参数、量化感知训练压到 ~2-bit 主权重、4-bit embedding、8-bit KV cache）；OpenELM 开源小模型。**但**未公开统一生产表（各模型上下文窗/RAM/token 速率/路由策略未全披露）——透明度"半开" |
| **Qualcomm / Snapdragon** | Qualcomm AI Hub 托管端侧优化模型并附模型元信息/性能指标；Hexagon NPU 强调能效比而非裸 TOPS（⚠️ 具体模型卡字段覆盖度**待核实**） |
| **面壁 MiniCPM / UltraData** | 开源 1B 级端侧模型 + **公开训练数据治理全流程**（query 筛选→答案校验→去重），把"数据卡"做进开源生态，对抗评测刷榜 |
| **Hugging Face 生态** | Gemma / Qwen / Phi 等端侧友好模型默认带 README 模型卡，是端侧开源模型分发主渠道 |
| **Google Model Cards / Data Cards** | 提供模板（Data Card 覆盖 15 个常查主题），是端侧模型卡字段的事实起点 |
