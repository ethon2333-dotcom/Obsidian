# 手机端 AI 智能体·意图框架横切全景

> 衍生深耕笔记（Round 1）。把 `手机AI智能体/` 簇里分散在多篇 own-words 笔记里的核心判断，横切串成一张**安卓 PM 视角的全景心智图**。
> 本文是「线」，不是「点」：每个节点都可点回源笔记深读。自己的原始笔记一字未改。

## 0. 一句话收口

意图框架这件事，技术只是外壳。**真正被争夺的是「入口所有权」**——当系统能按语义直接调 App 能力，App 图标就从唯一入口退化成能力的展示外壳。看懂这一层，四平台所有动作都讲得通。

---

## 1. 五段心智链（从上往下读）

```
① 语义寻址        ② Schema 定义权      ③ 四平台分层       ④ 上行通道        ⑤ 入口所有权
(寻址单位变了)    (词汇表谁写)        (风险分级链路)     (服务找人燃料)    (真正的战场)
```

### ① 语义寻址：改变的是「寻址方式」

过去系统按**包名**寻址（我要 `com.xxx.yyy`），现在按**语义**寻址（我要「给张三发条消息」这个能力）。[[App Intent 的核心作用]] 里点明的「以用户任务为中心」是现象，**寻址单位从 App 降到能力**才是机制。

> 推论：一旦按能力寻址，App 的内部功能结构就暴露给系统了——这是后面所有「入口所有权」博弈的起点。

### ② Schema 定义权：四平台分成两派

| 派系 | 平台 | 含义 | 代价 |
|---|---|---|---|
| **预定义派** | Apple、HarmonyOS | 平台写好能力目录，开发者对齐 | 平台没定义的垂域进不来 |
| **自由声明派** | Android | 开发者 KDoc 即工具描述，KSP 构建期生成 XML | 路由质量取决于开发者文档；Google 用 KDoc Refinement 打补丁 |
| **混合受控** | Windows | MCP 连接器自述 + ODR 受控发现 | 平台保留准入裁决 |

**产品含义**：预定义派要求平台有压倒性生态号召力。国内任一安卓厂商都不具备 → 联盟标准现实上只能走自由声明路线（见 [[安卓厂商意图识别破局策略]] 第四节）。

### ③ 四平台分层：风险准入递减的分级链

官方架构（Google built-in intents / AppFunctions / UI Automation；鸿蒙 Want；Apple App Intents 2.0；Windows Copilot Actions）本质都是**按任务风险分级的链路**，不是「能力递减的兜底链」：

- L1 原生 API（高稳定/低延迟）→ L2 深层协议（免打开）→ L3 GUI Agent（兜底，但**只做低风险只读与可重试动作**）
- 三分边界已成型：**系统理解意图 / App 保留履约与支付 / 用户保留最终决定权**

### ④ 上行通道：被忽略的「主动推荐」燃料

下行（意图调用）只是「一句话直达」；**上行（意图共享/捐赠）才是「服务找人」（负一屏、小艺建议、Siri 建议）的全部燃料**。鸿蒙官方把智慧分发拆成 5 类特性，只有 1 类是调用，其余 4 类全是上行喂出来的（[[端侧意图框架 学习笔记]] 6.2）。

> 对 PM 的用处：评估一个 App 的意图适配完成度，不能只看它注册了几个 Intent，还要看它有没有在共享/捐赠。

### ⑤ 入口所有权：真正的战场

一旦工具目录由 OS 托管，入口价值从 App 图标转移到系统 Agent（[[MCP 与设备侧 MCP]] 4.4）。国内厂商与超级 App 真正在争的不是技术接口，是入口所有权。

## 2. 三件必须分开算账的事（防过度承诺）

来自 [[MCP 与设备侧 MCP]] 4.3，但同样适用于整个意图框架叙事：

| 好处 | 成立条件 | 常见误区 |
|---|---|---|
| 隐私 | **仅执行段**留在端；理解段可能上云 | 「执行在端侧」≠「全链路在端侧」 |
| 延迟 | 省掉下半程；但 Planner 在云上仍被云支配 | 真正低延迟要端侧 Planner + 端侧工具两头齐 |
| 离线 | 端侧模型 + 端侧工具 + 本地数据，缺一不可 | AppFunctions 只解决第二项 |

> **铁律**：设备侧能力是「执行侧本地化」，不是「全栈本地化」。对外讲隐私必须限定到执行段。

## 3. 安卓 PM 的待解问题（收口到决策）

1. **工具排序权**：端侧工具与云侧工具同处一份清单时，谁定择优规则？若 Agent 偏向云侧同名工具，App 的端侧适配是否形同虚设？
2. **上行数据博弈**：超级 App 连下行调用都不给，凭什么给上行数据？没有上行，「服务找人」在国内安卓是否根本做不起来？
3. **形式适配治理**：Registry 动态可见性普及后，App 把能力注册进去却常年 `isEnabled=false` 应付合规，系统如何识别？
4. **入口回报**：厂商永远拿不到交易闭环，这套投入的商业回报在哪（预装位？会员？广告？纯防守）？
