**当知识库里混着图片、音频、视频、PDF 时，AI 必须把非文本模态自动归类并建立跨模态统一索引，才能让你用「一句话 / 一张图」搜回任意模态的内容——否则它们只是各自孤立、永远搜不到的「数字垃圾」。**

> 本文是「广度种子」笔记，刻意区别于 [[AI 辅助信息架构与知识组织结构 学习笔记]]（那篇聚焦**文本**结构的自动组织：自动 MOC / 打标 / 双链建议）。本文聚焦**图像 / 音频 / 视频**在知识库中的自动归类与跨模态检索引擎结构，点到为止。

## 一、广度覆盖

### 定义

多模态知识库（Multimodal PKM）指把文本、图片、音频、视频、PDF 等非结构化多源异构数据映射到**统一语义向量空间**，并自动完成归类、索引与跨模态检索（Cross-Modal Retrieval）的系统。核心能力是「用任意模态搜任意模态」（如拍图搜文档、说一句定位视频片段）。

### 分类（自动组织 + 跨模态检索的主要技术环节）

| 环节 | 做法 | 代表技术 |
|---|---|---|
| 图像自动打标 / 聚类 | 视觉编码器抽取特征，自动生成 caption 标签并聚类 | CLIP / SigLIP / Nomic Vision 双编码器 |
| 音频转写入库 | 语音转文本 + 时间戳元数据，或音频直接嵌入 | Whisper / Wav2Vec2 / VGGish |
| 视频关键帧抽取 | 按场景变化或固定间隔抽帧 → 帧向量 + 时序池化 | FFmpeg + PySceneDetect + 帧嵌入 |
| 跨模态 embedding 统一向量空间 | 不同模态映射到同一空间，余弦相似度跨模态比对 | CLIP / ImageBind / Cohere Embed v4 / Google Multimodal / Qwen3-VL-Embedding |
| 多模态 RAG 索引结构 | 检索（多路召回）→ 融合（fusion）→ 生成（VLM 引用溯源） | ColPali / MuRAG / MRK（向量索引 + 模态感知知识图谱）/ MISS 树索引 |

### 主流方案与代表产品

| 流派 | 代表产品 / 方案 | 多模态能力 |
|---|---|---|
| 笔记 / PKM 插件生态 | Obsidian（Smart Connections 语义检索支持图像、Copilot、Bases）、Logseq、Mem AI | 以文本为主，图像/音频索引能力**有限且多为社区插件** 待核实 |
| 云端多模态个人知识库 | **NotebookLM**（支持 PDF / Google Docs / YouTube / 网页 / 音频；2026-03 上线 Cinematic Video Overviews，2025 加 Deep Research 与 Gemini 集成） | 多模态摄取 + 生成式概览，开箱即用 |
| 向量库统一图文音视频索引 | Milvus / Weaviate / Pinecone / Chroma / Qdrant / FAISS | 统一存多模态 embedding，支持 metadata 过滤与多向量召回 |
| CLIP 类跨模态检索 | OpenCLIP / SigLIP / Chinese-CLIP / Jina CLIP v2 / BGE-VL | 零样本图文互搜，可扩展至音频/视频 |
| 多模态 RAG 框架 / 论文 | MuRAG（2022 奠基）、ColPali（late interaction 视觉）、MRK、M-Retriever（Google 2025-12，跨模态对齐损失）、VisRAG / M3DocRAG | 检索-融合-生成三阶段，VLM 引用溯源 |

### 2025-2026 进展（已核实的主线）

- **多模态 RAG 综述三连（2025 春）**：Abootorabi et al.（arXiv:2502.08826「Ask in Any Modality」）、Mei et al.（arXiv:2504.08748「A Survey of Multimodal RAG」）、Zhao et al.（arXiv:2503.18016 视觉向）——系统化「检索 / 融合 / 生成」 taxonomy；多数子问题仍开放。
- **统一多模态 embedding 爆发（2025-2026）**：Cohere Embed v4（文本+图+表）、Voyage Multimodal-3（文本+图，原生 PDF 截图）、Google Multimodal Embeddings（文本+图+音频+视频，4 模态）、ImageBind（Meta，6 模态）、Qwen3-VL-Embedding、ColPali late-interaction 视觉化。
- **多模态索引结构新范式**：MISS（Guo et al., 2025-08）用递归 k-means 树做层次化多模态索引；MRK（2025-10）提出「向量索引 + 模态感知知识图谱（MAKG）」双工件混合检索。
- **NotebookLM 多模态化**：2025 加 Deep Research / Gemini 集成，2026-03 推出 Cinematic Video Overviews（Gemini 3 + Nano Banana Pro + Veo 3 三模型协作）。
- **融合策略（production default）**：score fusion（各模态归一化后求和，略偏向查询主模态）→ attention-based fusion → MoE fusion（按路由加权）。
- **跨模态评测仍不成熟**：无统一跨模态 benchmark，常用 Recall@k（分模态）、融合 top-k 准确率、人工端到端满意度作代理——来自综述，待标准。

> ⚠️ 下列「性能数字」来自单一博客 / 厂商口径，未跨源交叉验证，一律标「待核实」：**CLIP 在 MS-COCO 上 recall@1 >75%**、**2026 多模态 embedding 相对纯文本 +40% 跨模态 recall**、**M-Retriever 电商图文匹配 +34%**、**ColPali 类模型 MTEB 检索 62-63 分**——详见文末待核实清单。

### 关键玩家

- **模型层**：OpenAI（CLIP）、Google（SigLIP / Gemini / NotebookLM / M-Retriever / Vertex AI 多模态 embedding）、Meta（ImageBind）、Cohere（Embed v4）、Voyage（Multimodal）、Jina（CLIP v2）、BAAI（BGE / BGE-VL）、阿里（Qwen-VL-Embedding）。
- **向量库层**：Zilliz/Milvus、Weaviate、Pinecone、Chroma、Qdrant（均支持多模态统一索引与 metadata 过滤）。
- **应用层**：Google NotebookLM、Obsidian 插件生态（Smart Connections / Copilot）、Mem AI、AnythingLLM / PrivateGPT（本地优先）。
