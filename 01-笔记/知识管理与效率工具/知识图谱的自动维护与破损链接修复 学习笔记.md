# 一句话心智模型
知识图谱建成后会腐化——自动检测破损链接、重复节点与过时事实并修复，是图谱长期可用的关键运维层（区别于 [[知识管理的个人知识图谱自动化构建 学习笔记]] 的"构建"，本文是"构建后"的维护与修复）。

## 广度覆盖（点到为止）

- **定义**：KG maintenance = 图谱在持续摄入/演化中保持质量（正确、完整、一致、最新）的运维过程；broken-link repair 是其子集（修复指向失效/缺失节点的边）。
- **分类**：schema 漂移 / 破损链接 / 重复节点 / 过时事实 / 矛盾检测（见下表）。
- **主流方案**：LLM 校验修复、图嵌入异常检测、链接解析器/实体解析、规则/约束引擎（SHACL）。
- **2025-2026 进展**：从"检测到即过滤"转向"检测 + 保守修复"；连续/动态 schema 验证；GNN 从人类编辑历史学修复；GraphRAG 管道中实体解析成为必需；双时态 + invalidate-not-delete 成工程范式。
- **代表工具/产品**：Obsidian 维护插件、Neo4j AuraDB + APOC、开源 KGGen/LINK-KG/FastER/LLM_sim/ADKGD、企业 Zingg/Wikidata 协作修复。

### 维护任务分类
| 任务 | 说明 | 代表方案 |
|---|---|---|
| Schema 漂移 | 实体/属性定义随数据演进而偏离初始 schema | SHACL 约束 + COSE 连续形状抽取 (BIGDATA 2025)、QSE/Shactor 动态形状提取 |
| 破损/死链 | 实体/关系指向不存在或已删除的节点，链接断裂 | Obsidian「Find orphaned files / broken links」、Link Maintainer 插件、link resolver / 实体解析 |
| 重复节点 | 同一实体因别名/大小写/缩写被拆成多个节点 | 实体解析 (FastER 2025)、KGGen/LINK-KG 合并、去重可降约 40% 图体量 (NTU 2025) |
| 过时事实 (stale facts) | 事实被后续信号推翻但未被作废 | 双时态 valid_at/recorded_at + invalidate-not-delete（self-healing KG 2026） |
| 矛盾检测 | 两条 plausible 边互相冲突 | 前置环/矛盾检测 + 隔离待人工复核（SHARP 2026，quarantine） |

### 主流方案对比
| 方案类别 | 机制 | 代表 |
|---|---|---|
| LLM 校验/修复 | 用 LLM 世界知识检测并修正噪声三元组或校验失败的三元组 | LLM_sim (COLING 2025, WN18RR F1 0.951)、CTI 三元组修复 (ICAIC 2026)、Wikidata GNN 修复 (ESWC 2026「Structure is the Signal」) |
| 图嵌入异常检测 | KGE/GNN 重建误差或双通道打分发现异常节点/边 | ADKGD (arXiv 2025.01)、GCN/GAT/GAE 混合架构 |
| 链接解析器 / 实体解析 | 多源/多别名记录解析到同一真实实体（link resolver） | FastER、KGGen (embedding 聚类 + LLM 去重)、Zingg |
| 规则 / 约束引擎 | SHACL 形状约束做验证，闭环修复 | PRISM 闭环治理、COSE 连续形状抽取、Neo4j APOC 图重构 |
