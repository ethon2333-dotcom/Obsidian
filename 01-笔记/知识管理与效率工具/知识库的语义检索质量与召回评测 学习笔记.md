# 知识库的语义检索质量与召回评测

> [!abstract] 一句话心智模型
> **检索质量评测的本质，是把「这个 RAG 答得好不好」拆成两道独立考卷——检索层「抓住了多少关键信息、又塞进了多少噪声」，生成层「有没有把检索到的东西用好」；任何单一总分都会掩盖真正坏掉的那一层。**

---

## 一、广度覆盖

### 表 1 · 核心指标速查（检索层 / 上下文层 / 生成层）

| 层级 | 指标 | 含义（点到为止） |
|---|---|---|
| 检索层（传统 IR） | Recall@k | 全部相关文档中，前 k 个检索结果覆盖了多少 |
| 检索层 | Precision@k / Hit@k | 前 k 个结果里相关项占比 / 至少命中 1 个相关项的比例 |
| 检索层 | MRR | 每个查询「第一个相关文档排位」的倒数平均，重排位轻 |
| 检索层 | NDCG@k | 考虑「相关性分级 + 位置折扣」的排序质量，[0,1] |
| 上下文层（RAGAS 系） | Context Recall | 标准答案所需信息，有多大比例能在检索到的上下文里找到 |
| 上下文层 | Context Precision | 检索到的上下文里，真正相关的内容排在前面的程度（信噪比） |
| 上下文层 | Context Relevancy | 检索上下文整体「为当前问题服务」的句子占比 |
| 生成层 | Faithfulness | 回答能否从检索到的上下文推断出来（防幻觉） |
| 生成层 | Answer Relevancy / Correctness | 回答是否切题 / 与标准答案的事实吻合度 |
| 细粒度诊断（RAGChecker） | Claim Recall / Noise Sensitivity / Hallucination | 把回答拆成「原子 claim」逐条比对，定位检索 vs 生成的失败点 |

> ⚠️ 关键区分：`Recall@k`（文档级、需标注 qrels）≠ `Context Recall`（答案信息覆盖度、RAGAS 常用 LLM-as-judge）。两者同名易混，评测前先定清楚口径。

### 表 2 · 评测分类维度

| 切分维度 | 一端 | 另一端 | 备注 |
|---|---|---|---|
| 评测时机 | **离线评测** | **在线评测** | 离线=固定测试集打分；在线=埋点/AB/用户反馈/查询日志回流 |
| 打分来源 | **自动指标**（LLM-as-judge、IR 指标） | **人工标注** | 人工金标准（qrels）是基准根基，自动指标省成本但有方差 |
| 评测对象 | **检索评测** | **生成评测** | 本报告聚焦前者；生成评测见 [[RAG 详细学习笔记]] |
| 数据归属 | 公开基准（BEIR/MTEB） | 自有语料评测 | 公开基准用于「选模型」；自有查询+语料才「说了算」 |

### 表 3 · 主流方案与评测工具

| 工具 / 基准 | 定位 | 侧重 |
|---|---|---|
| **Ragas** | RAG 专项评测事实标准 | Context Recall/Precision、Faithfulness 等；LLM-as-judge、支持合成数据集 |
| **RAGChecker**（NeurIPS 2024, arXiv 2408.08067） | 细粒度诊断框架 | claim 级拆解，分检索/生成错误，与人类判断相关性优于旧指标 |
| **DeepEval** | 工程化全家桶 | pytest 风格、CI/CD 友好、60+ 指标、Confident AI 面板 |
| **TruLens** | 可观测性驱动 | 反馈函数逐段打分（groundedness），生产监控/调试侵入性强 |
| **ARES** | 自动评测框架（Snowflake） | LLM-judge + 预测驱动推断；⚠️ 细节待核实 |
| **BEIR** | 零样本 IR 基准 | 18+ 异构数据集，测跨域泛化；nDCG@k / Recall@k |
| **TREC**（含 TREC-DL、TREC-COVID） | 深度人工标注集合 | 池化+人工判相关性，标签远比 MS MARCO 稠密 |
| **MTEB / MMTEB** | 聚合排行榜 | 含检索+分类+聚类等 56+ 任务；多语言版 MMTEB |
| **BRIGHT**（ICLR 2025） | 推理密集型压力测试 | 1385 条需推理的查询，暴露「表面相似≠真相关」短板 |
| **ViDoRe V1/V2/V3** | 多模态文档检索基准 | 视觉富文档（图表/表格/版式）检索，ColPali 等 |
| **RTEB**（2025-10 beta） | 抗过拟合基准 | 开放+私有双集合，私有半防训练泄题 |

### 表 4 · 2025–2026 进展（点到为止）

| 方向 | 进展 |
|---|---|
| 基准饱和与迁移 | BEIR 被认为「被刷穿」，新基准转向多语言/代码/视觉/企业真实场景（MMTEB、CoIR、RTEB、ViDoRe v2/v3、AIR-Bench） |
| 多模态检索评测兴起 | ViDoRe 系列把「图文混排 PDF 检索」独立成评测赛道，nDCG@5 成主指标 |
| 诊断范式升级 | 从单一总分 → claim 级、layer 级诊断（RAGChecker 带动「检索错还是生成错」分离） |
| 评测进生产 | Eval-as-Code / RAG 评测进 CI（与 [[开发者态 Agent 评测与 CI 集成 学习笔记]] 同脉） |
| 失败模式分析 | 噪声 chunk、长尾召回、stale/conflicting 文档、权限边界、缩写/内部术语成为高频评测用例 |
| 小模型反扑 | 300M–600M 嵌入模型（Nomic、ModernBERT、jina-emb-v3、BGE-M3）性能逼近大模型，影响评测基线选择 |

- **学术基准**：BEIR、TREC-DL、MTEB、BRIGHT、LoTTE（长尾）、MIRACL（多语言）、ViDoRe（多模态文档）

## 二、几个值得记住的失败模式（点到为止）

- **噪声 chunk 陷阱**：RAGChecker 实验显示，检索 chunk 从 5→20 时 Claim Recall 上升、Faithfulness 上升，但 Noise Sensitivity 同步上升——「多检索」不是银弹。
- **长尾召回塌陷**：多数基准偏头部查询，LoTTE 等证明头/尾查询表现严重分化；个人知识库里冷门笔记正是长尾。
- **多模态检索评测缺口**：纯文本基准（BEIR）无法反映「图表/表格/版式」检索质量，需 ViDoRe 类专门基准；ColPali 在 ViDoRe 上约 81.3 nDCG@5，显著优于 OCR+文本基线（⚠️ 具体数字见待核实清单）。
- **没有自己语料的评测都是「抽象好」**：公开基准定短名单，自有查询+语料定生死（awesome-search 观点）。
