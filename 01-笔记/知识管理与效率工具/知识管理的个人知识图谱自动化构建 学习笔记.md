# 知识管理的"个人知识图谱"自动化构建 学习笔记

> 心智模型一句话：个人知识图谱（PKG）是把你 vault 里的笔记/文档用 AI 抽成「实体（节点）+ 关系（边）」的图，让"我其实记过、但没显式连起来"的知识被自动浮现——它和双链笔记是"AI 推断"与"人手工策展"的互补，而不是替代。

## 一、定义：什么是个人知识图谱（PKG）

个人知识图谱是把**个人笔记、文档、对话、高亮**等私有语料，组织成「实体—关系」图结构（节点=概念/人/项目/工具，边=它们之间的有标签关联，常见三元组 `(subject, relation, object)`）。它服务于三类动作：**回顾/重访**（找到忘了记过的内容）、**发现连接**（跨领域节点的隐性桥接）、**图谱感知问答**（"我和 Ali 讨论过哪些项目？"这类多跳问题）。区别于企业知识图谱，PKG 强调本地、隐私、个人语料所有权。

## 二、分类：按"抽取方式"与"存储形态"两条轴

### 2.1 抽取方式（怎么长出这张图）

| 抽取方式 | 做法 | 典型代表 / 说明 |
|---|---|---|
| LLM 实体/关系抽取 | 用 LLM 从文本/对话流抽取三元组 `(主体, 谓词, 客体)`，可带 schema 或动态生成 | 占构建质量问题的大头：抽取错误会**累积成噪声图**；需同义词检测 + 共指消解（如 "S Shankaran" 与 "Sagar Shankaran" 同一人）|
| Embedding 语义聚类 | 把笔记/段落向量化，按语义相似度聚类、补语义边 | 与双链互补：捕获"没写链接但意思相近"的关联 |
| 社区检测 + LLM 摘要 | 用 Leiden 等算法把实体聚成社区，LLM 为每个社区写摘要（Microsoft GraphRAG 的 global search 范式）| LightRAG 提供轻量、可增量更新的变体（双级检索：具体实体 + 宽泛主题）|
| 时序/双时态图 | 给边加"有效时间 + 记录时间"窗口，事实变更时**失效旧边而非删边** | Zep/Graphiti 是领先实现；区分"活的记忆"与"静态批量索引"的关键 |

### 2.2 存储形态（图存在哪）

| 存储形态 | 形态 | 代表 |
|---|---|---|
| 图数据库 | 通用图引擎，Cypher 查询 | Neo4j（市占领导者）、Memgraph（内存实时）、ArangoDB（多模型）、Amazon Neptune（托管云）、Kuzu（轻量，部分方案已弃用）|
| 本地 SQLite / 文件 | 单文件、端侧、零云依赖 | `obra/knowledge-graph`（SQLite + FTS5 + sqlite-vec + Claude Code MCP 插件）、mnemo（Rust 二进制 + SQLite + petgraph，<50ms）|
| 笔记内 YAML frontmatter | 关系直接写回 Markdown 元数据 | Obsidian 插件 Knowledge Brain 等（写回会改变 vault，需谨慎）|
| 向量 + 图混合 | 向量库管语义召回，图库管关系遍历 | GraphRAG 系（向量检索结果 + 图检索结果合并喂 LLM）|

## 三、与双链笔记（Obsidian）的互补关系

| 维度 | Obsidian 原生双链/图谱 | AI 个人知识图谱 |
|---|---|---|
| 连接来源 | 人手工写 `[[wikilink]]`，显式、可控 | AI 推断，自动、可能含噪 |
| 图谱含义 | 节点=笔记，边=你写下的链接；**不推断缺失关系、不验证 claim 真伪** | 节点=实体/概念，边=抽取出的语义/事实关联 |
| 盲区 | 孤岛笔记（无链接）、隐性主题关联看不见 | 抽取错误累积、可能"假连接" |
| 结论 | 双链是**策展层**，PKG 是**发现层**——先写好笔记与链接，图谱才自然好看；**图谱是结果不是目标** | 两者并存：用双链定骨架，用 PKG 挖遗漏；Obsidian 原生图谱 >5000 笔记可能卡顿，AI 图更适合大库的结构化探索 |

## 四、主流方案与工具（广度一览）

| 类别 | 代表 | 定位 |
|---|---|---|
| 图构建框架 | Microsoft GraphRAG、LightRAG、Graphiti/Zep、HippoRAG、LazyGraphRAG | 把"索引→社区摘要→检索"工程化的底层框架，多非开箱产品 |
| Obsidian 图谱插件 | Simple Graph Builder、Knowledge Graph（obra）、Knowledge Brain、Graph Mind、Karpathy LLM Wiki、Knowledge Graph Analysis | 在 vault 内做实体抽取 / 语义检索 / 图谱问答；有的写回 vault，需先备份 |
| AI 原生 PKM | Mem（自动图谱、云优先）、Logseq（大纲+图谱、本地优先开源）| 一个"AI 替你连"，一个"你连、AI 辅助" |
| 图数据库个人库 | Neo4j（LLM Knowledge Graph Builder 2025 发布；neo4j-labs/agent-memory）| 把个人语料抽进标准图库做多跳查询 |
| 本地优先管线 | mnemo、Chaos Cypher、Ollama+FAISS+Neo4j 自建 | 完全离线、数据不出本机 |

## 五、2025-2026 进展（点到为止）

- **GraphRAG 走向成熟与廉价化**：Microsoft GraphRAG（截至 2026-05 约 34k+ stars，v3.1.0）仍是思想锚点；LazyGraphRAG（2025 年中）把索引成本压到原管线的约 0.1%；LightRAG（EMNLP 2025 Findings，截至 2026-06 约 37k stars）主打轻量可增量；Graphiti/Zep 攻"活更新/双时态"，HippoRAG 2（ICML 2025）把 KG-RAG 框定为"非参数持续学习=记忆"。
- **个人规模的关键校准**：媒体口径称 GraphRAG 在复杂多跳问题上比向量 RAG 全面性高 50–70%「**待核实**」；但 2025–2026 证据一致显示——主流个人查询（"找我存过的那篇/那条"）纯向量/混合 RAG 胜出，图谱只在**多跳 / 全局意义建构**这类少数查询上赢。**GraphRAG global search 有常驻成本（如 Neptune Analytics 约 $0.48/小时 ≈ $350+/月地板价）**，个人小规模多数不划算，轻量图谱风味（如 LightRAG）才是务实选择。
- **Obsidian 插件生态活跃**：Simple Graph Builder 0.9.0（2026-10）支持"让你的 agent（Claude Code/Desktop/Codex）用 MCP 建图、只写图不写笔记正文"，内置 10 个固定实体类型 + 自由关系动词；`obra/knowledge-graph` 走本地 SQLite + 本地 embedding + Claude Code MCP；**Simple Graph Builder 作者自报数据文件体积在 5177 节点 vault 上从 6.8MB 降至 3.8MB（降 44%）「待核实，仅为插件特定存储结果，非通用速度/质量基准」**。
- **AI 原生 PKM 两极**：Mem 走"完全自动图谱、capture-first、AI 替你连"（评测口径称约 70% 连接有用「**待核实**」，且云依赖/商业模式存疑）；Logseq 仍是大纲+图谱、本地优先开源，AI 以社区插件为主、DB 版过渡慢于预期。
- **NotebookLM 图谱化**：新增 Mind Maps 交互可视化；有资料称其可把实体/关系导出为 RDF 或 Neo4j CSV「**待核实，来自二手资料，官方能力以当前产品为准**」。
- **本地优先爆发**：mnemo（Rust 单二进制、零云依赖、Ollama 可全本地）、Chaos Cypher（Ollama 全本地管线）、Ollama+FAISS+Neo4j 自建教程，呼应"数据不出设备"的隐私诉求。

## 六、代表产品 / 工具速写

- **Obsidian 图谱插件**：Simple Graph Builder（LLM 实体抽取 + 轻量图 + RAG 检索 + MCP agent 建图）、Knowledge Graph（obra，本地 SQLite + 语义搜索 + 社区检测 + Claude Code MCP）、Knowledge Brain（frontmatter 关系 + AI 建议）、Graph Mind（本地 Ollama 语义检索 + 引用问答）、Karpathy LLM Wiki（本地优先、实体/概念页 + 图谱问答）、Knowledge Graph Analysis（图指标 + Gemini 分析）。
- **Mem**：AI-first、云优先，"你写、AI 连"的自组织工作区；自动知识图谱 + 概念搜索 + 跨笔记问答；隐私/云依赖是主要顾虑。
- **Logseq**：开源、本地优先、大纲块 + 双向链接 + 图谱视图；AI 集成社区驱动、仍在成熟中。
- **GraphRAG 个人化**：Microsoft GraphRAG（研究项目而非 SDK，批量索引贵、无原生增量）、LightRAG（轻量可增量、最活跃 OSS）、Graphiti/Zep（双时态活记忆）、HippoRAG 2（学术基线）、LazyGraphRAG（索引成本极低，但未开源）。
- **Neo4j 个人库**：LLM Knowledge Graph Builder（2025 发布，把文档抽进 Neo4j）；neo4j-labs/agent-memory（POLE+O 本体、3 记忆层、MCP server，可做个人 agent 记忆）。
