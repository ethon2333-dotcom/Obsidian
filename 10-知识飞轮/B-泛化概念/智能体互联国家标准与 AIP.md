# 智能体互联国家标准与 AIP

> 全新概念（2026-07-31 新增）。四大 OS 各自建私有 Registry（见 [[Intent Schema Protocol 意图模式规范]]），本节点记录**国家级、跨厂商**的互联规范这条独立路径，与 [[A2A 端侧智能体协议]]（厂商/技术协议）互补不重复。

## 一句话定义

**《人工智能智能体互联》系列 7 项国家标准** 是中国为智能体互操作制定的国家级规范，覆盖 **「身份标识 — 能力描述 — 供需发现 — 协同交互 — 工具调用」** 全链路；北京在此之上首次提出 **智能体互联协议（AIP）** 作为地方产业抓手。

## 为什么重要

- **补上四大 OS 的空白**：Apple App Toolbox、Android Registry、Windows ODR、鸿蒙意图框架各自封闭，**跨厂商互认没有公共层**；国标提供了这一层的第一份骨架。
- **五段式与 OS Registry 高度同构**：可直接当作四平台横向对比的坐标轴（谁做了身份标识？谁做了能力描述？谁做了供需发现？）。
- **治理先行**：下一步补齐 **智能体审计、交易** 标准，意味着「Agent 行为可审计」将从产品特性变为合规要求（对照 [[Agent 身份与硬件级审批]]）。

## 适用边界

- **中国境内**的标准与政策路径；不直接约束 Apple/Google/Microsoft 的全球产品设计。
- 目前为标准发布阶段，**标准号、全文与实际采纳率待补**；产业落地深度尚未验证。
- 与 MCP / A2A 是「规范层 vs 技术协议」关系，不是替代关系。

## 证据与例子

**五段式规范骨架**

| 环节 | 作用 | 四大 OS 对应物 |
|---|---|---|
| 身份标识 | Agent 是谁、可否被追溯 | Windows Agent 账户 + 签名；[[Agent 身份与硬件级审批]] |
| 能力描述 | 我能干什么（机器可读） | Apple `@AppIntent(schema:)`、Android `@AppFunction` KDoc、鸿蒙 SKILL.md |
| 供需发现 | 谁能干这件事 | Android Registry、Windows ODR、Apple Spotlight 语义索引 |
| 协同交互 | 多 Agent 如何对话 | [[A2A 端侧智能体协议]]、鸿蒙端/云 A2A |
| 工具调用 | 实际执行 | MCP / AppFunctions / Intents Kit |

**政策与标准时间线（2026）**

- 1 月：工信部、发改委等联合发布《"人工智能制造"专项行动实施意见》，明确打造智能体新业态。
- 5 月：网信办、发改委、工信部联合印发《智能体规范应用与创新发展实施意见》，要求「夯实技术底座，健全标准体系，降低智能体研发、适配、应用门槛」。
- 随后：**《人工智能智能体互联》系列 7 项国家标准正式发布**（标准号待补）。
- 7-23：北京《关于加快智能体引领发展的若干措施》——技术/应用/产业/生态四方面十条，单项目最高 **1 亿元** 支持；**首次提出智能体互联协议（AIP）、Token 经济、OPC（一人公司）**；实施「一区一品」策略。
- 7-31：中国网络空间安全协会副秘书长梁博撰文，提出对手机助手、终端智能管家、云端智能体建立 **终端分级标识、可信开源代码安全** 体系。
- 下一步（电子标准院）：补齐 **智能体审计、交易** 等关键基础标准。

**市场口径**：2024 年中国 AI 智能体市场约 28.73 亿元，预计 2030 年接近 300 亿元（中商产业研究院）。

⚠️ 数据与表述来源为《中国商报》综合报道（证券日报/21世纪经济报道/北京日报/人民网），**标准原文未核验**。

## 可复用启发

- 做 OS Agent 的能力开放设计时，可直接用**五段式**自检：身份标识→能力描述→供需发现→协同交互→工具调用，缺哪段就是生态短板。
- **「能力描述」是唯一必须机器可读且跨厂商可迁移的一段**——统一它，其他四段可以各家私有实现。这与 [[Agent Skills 技能范式 2026]] 的 SKILL.md 之争是同一个问题的两个战场。
- 审计与交易标准一旦落地，**Agent 行为日志将成为强制产物**，产品设计要提前预留可审计的执行轨迹（呼应 [[Agent Workspace 隔离执行]] 的审计能力）。
