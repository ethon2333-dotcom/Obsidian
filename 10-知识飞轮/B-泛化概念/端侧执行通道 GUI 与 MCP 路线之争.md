# 端侧执行通道：GUI 与 MCP 路线之争

> 全新概念（2026-07-31 新增）。技术实现见 [[工业级 GUI Agent 架构（VLM+无障碍树）]]（GUI 侧）与 [[Function Calling 端侧工具调用]]（结构化侧）；生态博弈见 [[国内安卓厂商做 App Intent 的阻力]]。本节点只聚焦**「同一能力该走哪条通道」的路线判断**，不重复上述内容。

## 一句话定义

系统 Agent 执行一个跨应用任务，有三条通道：**① 官方 Intent/Function 直连**（App 主动声明）、**② MCP 连接器**（跨生态标准协议）、**③ GUI 模拟兜底**（视觉/无障碍树点击）。2026 年的关键转折是：**GUI 路线的能力天花板被抬高，但厂商反而在主动撤离 GUI 路线**。

## 为什么重要

- **瓶颈换位**：GUI Agent 的主要矛盾已从「点不点得对」变成「**被不被允许点**」。能力问题正在被解决，准入问题正在恶化。
- **决定商业模式**：走结构化通道要和 App 谈判（签约/授权），走 GUI 不用谈但会被风控封。这不是技术选型，是生态位选型。
- **决定可靠性 SLA**：结构化通道不受 UI 改版影响、可返回结构化结果；GUI 通道每次 App 改版都可能失效。

## 适用边界

- 三通道**不是互斥的**，成熟系统是「结构化优先 + GUI 兜底长尾」双轨（华为小艺即如此）。
- 支付、社交、交易类任务**几乎必须**走被应用认可、可审计追责的通道；低风险只读任务可 GUI 兜底。

## 证据与例子

**1）能力天花板已被抬高（GUI 侧利好）**
- OSWorld 2026-07-31 首破 **90.2%**，跨应用协同与系统底层操作表现突出（见 [[OSWorld 计算机操作基准]]）。
- 华为小艺「帮帮忙」实测（南都，2026-07-31）已可 GUI 跨应用操作 **支付宝、淘宝、拼多多**（「去淘宝领金币」「支付宝查公积金」）。
- HarmonyOS 7 的 **HMAF 2.0 首次开放 GUI 操控能力**——官方把 GUI 当作正式一等通道纳入框架。

**2）厂商却在撤离 GUI（结构化侧胜出）**
- **豆包手机二代 NaviX Ultra（钛媒体，2026-07-31）**：**放弃一代 GUI 视觉模拟路线，改用 MCP 协议与 App 官方接口直连**，公开动机是**规避风控封禁**；备货 3 万→20 万台。这是国内首个公开的路线切换实证。
- Google 明确分工：`actions.xml` 已弃用；**built-in intents** 用于「拉起并履约」，**AppFunctions** 用于「带类型参数调用 + 返回结构化结果」，**零代码 UI Automation** 只作为未适配应用的覆盖手段（S26/Pixel 10，限美韩，外卖/生鲜/打车）——「你不接入也有覆盖，但**失去对执行方式的控制权**」。
- Apple 立场：App 须经 App Intents **主动声明**可被调用的动作与数据，**界面私有内容不自动向系统开放**。

**3）准入才是真瓶颈**
- 小艺 GUI 已覆盖三大电商/支付 App，但 **微信提示「尚未接入」** ——超级 App 的准入边界被公开可视化。
- WAIC 演示（Amoo × 美团跑腿）：系统 Agent 完成地址推断与订单填写，**付款环节任务停在美团页面等待用户确认**。三分边界成型：**系统理解意图 / App 保留履约与支付 / 用户保留最终决定权**。
- 支付宝 **AHA** 跨端协同接口：7-15 与 OPPO 小布连接，小布理解需求、阿宝调用支付宝**近 200 项生活服务**，关键授权与支付仍由用户确认。
- 判断：MCP / App Intents / AHA 协议不同，但解决同一问题——**让应用主动决定哪些能力可被 Agent 调用**，而不是系统 Agent 自行进入应用读页面。

**三通道对照**

| 维度 | ① 官方 Intent/Function | ② MCP 连接器 | ③ GUI 模拟 |
|---|---|---|---|
| 可靠性 | 最高（结构化返回） | 高 | 受 UI 改版影响 |
| 覆盖面 | 仅已适配 App | 已接协议方 | 理论全覆盖 |
| 准入成本 | 需 App 适配/授权 | 需协议对接 | 无需对方同意 |
| 风控风险 | 无 | 低 | **高（可被封禁）** |
| 可审计 | 强 | 强 | 弱 |
| 适用任务 | 支付/交易/写操作 | 跨生态服务编排 | 长尾只读/低风险 |

## 可复用启发

- **决策顺序**：官方 Intent → MCP → GUI。只有当「无官方通道 + 任务低风险 + 可容忍失效」三条同时成立时才用 GUI。
- **不要用 GUI 做写操作和支付**：即便技术上能点，风控与追责会在规模化时反噬（豆包一代的教训）。
- **GUI 的正确定位是过渡与长尾**：用它换取上线速度与覆盖面，同时用真实调用数据反推「该优先游说哪些 App 开放官方通道」。
