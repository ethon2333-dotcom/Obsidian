# Agent 写回路径 XPIA 风险评估 SOP

## 使用场景

当你在设计一个具备「写回（write-back）」能力的 Agent / OS 意图框架时——即 Agent 能把内容写回文档、日历、记忆、Registry、跨 App 存储或任何会被他人 / 后续会话复用的产物——用本 SOP 判定它是否暴露在**自传播 XPIA** 风险下。

触发背景：Copilot for Word 文档型蠕虫（[[文档型 XPIA 自传播蠕虫]]）证明，传统「隔离 / 确认 / 审计 / 溯源」四道防线全部假设「攻击是一次性的」，而具备写回能力的 Agent 可能让注入自我复制、在人际间正常流转，从而击穿所有四道线。

## 输入

- Agent 的能力清单：它能否修改哪些产物（文档 / 记忆 / 实体 / 意图注册 / 设备状态）。
- 产物流向：被修改的产物会不会再次进入 Agent 上下文（被自己或他人复用）。
- 确认触发规则：哪些动作会弹确认、哪些属于「本职工作」无确认。
- 多 Agent / 跨端场景：产物是否会在人际或跨设备间流转。

## 步骤

1. **画写回路径**：列出 Agent 所有「输出会持久化并被复用」的出口（不仅限发信/付款，还包括改草稿、写记忆、注册意图、回填日历）。
2. **逐路径三问判据**（三问全「是」= 蠕虫风险，须升级处置）：
   - ① Agent 能否修改**会被他人复用**的产物？
   - ② 这个产物**会不会再次进入 Agent 上下文**（自己或他人下次会话）？
   - ③ 修改本身是否**属于 Agent 的正常职责**（因而**不触发确认**）？
3. **对命中路径补四维防护**（见 [[Confirmation UI 安全机制]]）：可信 / 可见 / 可控 / **可逆**。重点补「可逆」——执行后一键撤回 + 任务中止，因为「执行后才发现」是常态。
4. **对命中路径做类别级评估，而非 PoC 级**：区分「某个载荷字符串失效」与「漏洞类别关闭」。诚实结论是「载荷修了，类别没修」时，靠卫生措施降级频率，不要宣称已解决。
5. **跨端 / 多 Agent 额外问**：当调度单元升级为「意图」（[[Agentic OS 意图调度内核]]），**意图本身会不会成为被注入对象**？（三家新 OS 均未公开回应，标待补。）

## 完成标准

- 每条写回路径都标注了三问判据结果。
- 命中路径都有四维防护设计，且至少包含「可逆」机制。
- 安全评审文档明确区分「PoC 已缓解」与「类别未关闭」，无夸大结论。

## 常见失败与处理

- **失败：只盯「敏感动作」确认**。Word 蠕虫的「改草稿财务数字」是本职工作，不触发任何确认。→ 处理：把判据从「动作是否敏感」转为「产物是否会被复用 + 是否会回流上下文」。
- **失败：以为隔离能解决一切**。[Agent Workspace 隔离执行] 隔离执行域，但隔离不了被污染产物在同事间正常流转。→ 处理：隔离 + 可逆 + 卫生措施组合，不单押隔离。
- **失败：把检测器堆成 LLM 盾牌**。作者论断「用比目标 LLM 更弱的检测器必留表征缺口；LLMs all the way down」无解。→ 处理：架构层（写回前结构化校验、产物带来源标记）优于纯模型对齐。

## 示例

Copilot for Word 蠕虫路径评估：① 能改会被同事复用的 Q1 报告 → 是；② 同事基于它起草 Q2，报告再进 Copilot → 是；③ 改数是 Copilot 本职、无确认 → 是。**三问全「是」= 蠕虫风险**。处置：微软两轮缓解（Edit with Copilot / 升 GPT-5.5→5.6）仅修载荷，类别 144 天后仍未关闭——印证「类别级」需架构层而非模型升级。
