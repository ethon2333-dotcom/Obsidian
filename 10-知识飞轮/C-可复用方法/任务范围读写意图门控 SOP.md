# 任务范围读写意图门控 SOP

## 使用场景

为会读取网页、文件、跨 App 上下文或 Tool Output，并会调用 Intent / Tool 写入外部状态的 Agent 设计执行边界。适用于浏览器或应用层 Agent；截至 2026-08-09，四大 OS 的 Intent Registry 均未确认内建此能力。

## 输入

- 用户目标、任务生命周期和允许的完成条件。
- 当前会话可访问的来源、Intent 和 Tool 清单。
- 每个调用的 `read` / `write` 属性、目标资源和可逆性。
- 高风险资源清单：支付、凭证、医疗、消息发送、删除、外部发布。

## 步骤

1. **建立任务作用域**：在 Planner 读取外部内容前创建任务 ID，并生成两个不可由页面内容修改的集合：`readOnly` 与 `readWriteable`。
2. **为调用标注读写语义**：查询、预览、下载写入 `read`；创建、修改、发送、删除、支付和授权写入 `write`。复合 Intent 拆成最小读写步骤。
3. **确定性门控**：所有新增资源、跳转、Tool 调用和 Intent 执行先由系统规则检查其目标是否已在对应集合中。未命中即阻断，不允许 Planner 自行扩大集合。
4. **隔离相关性判断**：若必须请求扩容，隔离的 Critic 只能读取动作元数据（目标、调用类型、任务 ID、风险级别），不得读取网页正文、Tool Output 或不可信提示；其结论只可建议，不能直接放行。
5. **执行写操作前升级**：`write` 调用若不可逆、涉及隐私或资金，交由带外授权组件确认；普通可逆写操作至少记录可撤销操作日志。
6. **回收与审计**：任务结束立即废弃两个集合，持久化调用日志、拦截原因和授权证据。不得将某任务的白名单直接继承给下一任务。

## 完成标准

- 每次 Intent / Tool 调用都有 `read` 或 `write` 标注和任务作用域。
- 作用域扩大、导航和调用均经过不读取不可信正文的确定性检查。
- 高风险写操作具有带外授权和可审计证据。
- 会话结束后不存在可被后续任务复用的隐式白名单。

## 常见失败与处理

- **失败：把来源可信度当作读写权限。** 来源密级和读写作用域是正交控制；两者必须同时检查。
- **失败：让 Planner 自报调用是只读。** 由 Registry / Framework 的语义声明决定调用类型，不能信任模型描述或页面字段。
- **失败：让 Critic 直接读取页面正文。** Critic 会被同一提示注入面污染；只提供动作元数据。
- **失败：任务跨会话继承白名单。** 默认回收；确需持久化时转化为用户可见的显式授权规则。
