> [!abstract] 30 秒速览
> **核心突破**：24 小时内出现三个方向性信号——① **OSWorld 首破 90.2%**，GUI 执行路线的能力天花板被抬高；② **豆包手机二代放弃 GUI 视觉模拟、改走 MCP 官方接口直连**，厂商主动撤离 GUI；③ **中国《人工智能智能体互联》7 项国家标准发布**，给出四大 OS 私有 Registry 之外第一个跨厂商互联骨架。

面向 OS / 系统级 Agent 方向的产品与技术决策者。目标：在**能力已够用**的前提下，把注意力从「模型能不能做到」转向「**通道能不能被允许、确认权该落在谁的界面**」。

## 正文

### 一、今天最该记住的一句话

**GUI Agent 的瓶颈已经不是能力，是准入。**

同一天里，OSWorld 被推到 90.2%（跨应用协同与系统底层操作表现突出），而豆包手机二代却公开放弃 GUI 视觉模拟、改用 MCP 与 App 官方接口直连，理由是**规避风控封禁**。华为小艺的 GUI 能力已经能操作支付宝、淘宝、拼多多，但微信一句「尚未接入」就划出了边界。

能力曲线在涨，可用边界却由生态方而非模型能力决定。这决定了 OS Agent 的竞争重心正在从算法转向**协议、商务与合规**。

### 三、三个可直接用的判断

1. **通道优先级是硬规则**：官方 Intent/Function → MCP 连接器 → GUI 兜底。**资金与不可逆写操作绝不能落在 GUI**，否则规模化必被风控反噬（豆包一代教训）。落地流程见 [[端侧执行通道选型 SOP]]。
2. **确认权的关键不是「弹不弹窗」，而是「在谁的界面上弹」**。支付停在美团/支付宝原生页面，责任链才清晰可审计。同时，Android 17 的系统选择器示范了正确的授权形态：**系统代持 + 单次 + 字段级**，而不是把长期权限交给 Agent。
3. **端侧路由的一等指标是「云端逃逸率」而非准确率**。prism-coder 级联实测显示 14b 承接 99% 流量、0% 打到云端——本地承接比例才决定成本与延迟优势是否成立。另注意 <1B 模型只有在「窄域 + 微调 + 严格 JSON」三条件齐备时可上主路由。
